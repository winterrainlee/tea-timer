## 1. 제품 정의

### 1.1 한 줄 정의
끓는 물을 부은 뒤 **수십 초의 짧은 시간** 동안, 화면을 보든 안 보든 "지금 따라낼 때"임을 자연스럽게 깨닫게 해 주는 모바일 차 우림 타이머. 차를 처음 마시는 친구에게도 가볍게 권할 수 있을 만큼 부담이 적고, 차에 재미를 붙이는 입구가 되는 것을 지향한다.

### 1.2 핵심 사용자 흐름
1. 앱을 연다. 홈 화면 아이콘 또는 브라우저에서 세로 화면으로 실행한다.
2. 차를 고른다. 차 캐러셀의 좌우 버튼으로 넘기면 다하 위의 마른 찻잎 미리보기, 권장 시간, 권장 온도가 반영된다.
3. 우림 도구를 고른다. 히어로 양쪽 화살표 또는 스와이프로 전환한다.
4. 큰 시간 조정 영역에서 슬라이더와 `-`/`+` 버튼으로 시간을 조정한다.
5. `우리기 시작`을 누르면 물 붓는 연출 후 우림이 시작된다.
6. 우림 중 찻물 색, 찻잎, 김, 글로우, 링, 숫자, 예고음이 진행감을 만든다.
7. 완료 시 종소리, 플래시, 도구별 완료 메시지가 나온다.
8. 일반 다구는 `차 따라내기`, 표일배는 `버튼 눌러 내리기`로 출탕을 마친 뒤 `다음 泡 우리기`를 누른다.

### 1.3 설계 원칙
- **도구 앱처럼 정돈되되, 차 도구처럼 따뜻해야 한다.** UI는 절제하고, 감각적 분위기는 중앙 도구·탕색·김·소리에서 만든다.
- **선(Line)을 지우고 면(Fill)과 여백으로 표현한다.** 테두리 선을 억제하고 은은한 미세 불투명도 면과 고운바탕체 타이포그래피로 동양적 젠(Zen) 미학을 살린다.
- **숫자는 보조, 감각 신호가 주역이다.** 탕색·링·글로우·증기·예고음·플래시를 겹쳐 어느 하나를 놓쳐도 전달되게 한다.
- **차 우리기의 종료는 0초가 아니라 분리/따르기다.** 모든 도구에는 실제 완료 행동이 있다.
- **고정 도구는 이미지 자산, 변하는 현상은 코드다.** 기물 형태를 코드 path로 억지로 그리지 않고, PNG 자산 위에 액체·잎·김·링만 SVG로 합성한다.
- **수십 초 스케일에 맞춘 긴장 곡선**을 쓴다. 마지막 3-5초에 임박 신호를 집중시킨다.
- **엄지 영역 우선**이다. 주요 조작은 하단에 두고 모든 터치 타깃은 44px 이상이어야 한다.
- **차를 마시는 경험이 기록보다 먼저다.** 기록하지 않고 타이머만 써도 완전한 사용이다. 열 잔은 목표나 저장 한도가 아니라, 쌓인 기록을 조용히 돌아볼 수 있는 발견의 시점이다. 진행률·연속 기록·레벨·AI 취향 판정으로 기록을 독려하지 않는다.
- **이미 아는 것을 다시 묻지 않는다.** 앱의 차·다구 선택과 실행 시간은 재사용하되, 권장값을 실제 측정값처럼 저장하지 않는다. 찻잎 양·물 양·실제 수온은 필요한 사람만 입력하는 확장 정보로 둔다.
- **데이터 락인(Data Lock-in)을 배제한다.** 현재는 일반 텍스트 복사와 PNG 공유·다운로드를 제공한다. 앞으로 재생성할 수 없는 사용자 기록·단어·레시피·커스텀 태그는 JSON 백업·복원과 개별 JSON/Markdown 이동을 지원한다. 회원가입·중앙 사용자 DB·클라우드 동기화를 필수로 두지 않는다.
- **오프라인·즉시 실행**을 목표로 한다. 현재 PWA 앱 셸은 캐시되지만 폰트는 아직 CDN 의존이다.
- **정지한 화면은 계산도 정지한다.** 대기·배수 완료 상태는 이벤트가 있을 때만 다시 그리고, 진행 중 시각 효과도 화면 주사율보다 낮은 제한 프레임으로 충분히 부드럽게 표현한다. 타이머 정확도와 소리 신호는 렌더 프레임 수에 의존하지 않는다.
- **가장 작은 모바일 화면(iPhone Mini 등 375x660 뷰포트) 검증을 의무화한다.** 데스크톱이나 대형 화면 검증에 안주하지 않고, 가장 작은 모바일 디바이스 화면에서 레이아웃 붕괴, 여백 팽창, flex 줄바꿈 미세 오류가 없는지 반드시 검증한다.

### 2.2 주의할 불일치
- 통합 전 `CLAUDE.md`에는 개완 뚜껑 열림이 적용된 것으로 적혀 있었으나, 현재 `index.html` 기준으로는 미작동이라 정정했다.
- 이전 체크리스트에는 아이콘 PNG가 없다고 되어 있었으나, 현재 `icons/`에는 필요한 PNG가 있다. 로드맵에서 제거한다.
- 통합 전 README의 "가로 스와이프로 차 전환" 표현은 현재 구현과 달랐다. 스와이프는 도구 히어로에만 적용되어 있어 README를 정정했다.
- `차 느낌` 버튼은 현재 모든 상태에서 보이며 첫 우림 전에도 시트를 열 수 있다. 상시 노출을 유지하기로 결정했으며, [초안 보호 정책](design-tea-feeling.md#draft-policy)은 TW-03 구현 대기다. 시트를 자동으로 열지는 않는다.
- 차 느낌 시트와 카드 미리보기는 현재 `dialog` 의미, 포커스 이동·복귀, Escape 닫기, 닫힌 레이어의 `inert` 처리가 없고 태그 칩의 높이도 30px라 44px 터치 기준을 충족하지 않는다. 구현 안정화 항목으로 `ROADMAP.md`에서 관리한다.
- TW-01에서 메인·설정의 저장 경계를 공통화했다. 커스텀 태그·빈 목록을 보존하고 농향 우롱·생보이·숙보이는 기존 메인 ID와 과거 설정 별칭을 호환한다. [저장 계약](data-portability.md#preferences-contract)을 따른다.

## 3. UI/UX 설계

### 3.1 모바일 세로 레이아웃

```text
safe-area top
┌─────────────────────────────┐
│ 우림 끝                사용법  │
│ 차 한 잔의 시간 / Time for Tea │
│ ‹ 백차    청향 우롱    농향 우롱 › │
│       길쭉한 다하 + 마른 찻잎       │
│        ● ● ● ● ● ● ●           │
│ ‹       도구 히어로        ›     │
│          0:18                  │
│     권장 우림 95°C / 20초         │
│  우림 기록 1포 20초 / 2포 25초     │
│       2포 25초 우리기            │
│ [−]   ━━━━┃━━━━●━━━━      [+]   │
│ ┌───────────────────────────┐  │
│ │        우리기 시작          │  │
│ └───────────────────────────┘  │
│ 🔊                         ✎ │
└─────────────────────────────┘
safe-area bottom
```

- 시각적으로는 상단 메뉴·차 선택·히어로·우림 조작·푸터의 다섯 구역이다. 실제 `.app`은 `auto / minmax(0, 1fr) / auto` Grid이고 중간 `.session-content`는 스크롤 가능한 Flex Column이다.
- 기존 `7:18:40:29:6` 비율은 레이아웃을 검토하던 시각적 목표였으며 현재 CSS의 고정 비율 규칙이 아니다. 콘텐츠 높이와 작은 화면 제약을 우선한다.
- 다하와 dots는 `.tea-picker` 내부에 포함해 히어로를 침범하지 않게 한다. 기본 차 선택부 위 간격은 `1.05rem`, 높이 720px 이하에서는 `.45rem`이다.
- 다구별 readout 위치는 현재 `18%`다. 푸터는 별도 Grid 행에 두고 하단 padding을 safe-area와 결합한다. `margin-top: 1.05rem`을 고정한다는 이전 명세는 폐기한다.

### 3.2 컴포넌트 기준

| 컴포넌트 | 현재 기준 |
|---|---|
| 상단 액션 | 좌상단 `우림 끝`, 우상단 `사용법` 링크. 별도 테두리 없이 기존 텍스트 버튼 톤을 따른다 |
| 헤더 | 앱 이름, 영문 부제만 표시. 선택 차와 회차 정보는 중복 노출하지 않음 |
| 차 선택 | 히어로보다 먼저 배치. 현재 차는 화면 중앙에 고정하고 테두리 없이 색 점, 글자 크기, 굵기로 강조 + 이웃 차 이름 + 길쭉한 다하 위 마른 찻잎 + 하단 dots. 차 이름만으로 고르게 하지 않고 잎의 모양과 색을 같이 보여 주어, 차 종류를 정확히 모르는 사용자도 "내가 가진 잎과 비슷한 것"을 눈으로 고를 수 있게 한다. 좌우 셰브런 버튼은 차 이름·다하·dots를 통합한 선택 영역의 세로 중앙에 배치. 우림 중에는 선택 조작·이웃 이름·dots를 숨기되 다하 미리보기는 흐리게 유지 |
| 히어로 | 도구 이미지, 액체·잎·김·링·pour 효과, 큰 카운트다운 |
| 도구 선택 | 히어로 좌우 화살표 + 히어로 스와이프. 도구 이름 텍스트는 숨김 |
| 시간 조정 | 히어로 아래의 큰 조작 영역. 별도 `우림 시간` 제목 없이 세 줄로 구성 — ① `권장 우림 95°C / 20초`(현재 포 기준, 포·차·다구 변경 시 갱신), ② `우림 기록 1포 20초 / 2포 25초`(완료 포만, 없으면 빈 줄 유지), ③ Gowun Batang 큰 `n포 n초` + 작은 `우리기` 접미. 아래 slider(권장 지점 눈금) + `-`/`+` |
| 주 액션 | 상태에 따라 `우리기 시작`, `물 붓는 중…`, `우리는 중…`, `차 따라내기` 또는 `버튼 눌러 내리기`, 출탕 뒤 `다음 泡 우리기` |
| 보조 액션 | 상단 `우림 끝`, 하단 좌측 음소거 토글(소리 켜기/소리 끄기), 하단 우측 `차 느낌` 노트 버튼. 노트 버튼은 항상 표시되고 사용자가 누르면 현재 세션 요약·태그·자유 문장·export 액션이 있는 바텀시트를 연다 |
| 도움말·설정 | `help.html`은 사용법·자유 사용 안내·제작자 연락처와 응원 박수, `settings.html`은 차별 시간 보정·커스텀 태그·기억한 설정 삭제를 담당한다. 박수/괜찮습니다 선택은 개인 식별자 없이 제작자 반응 집계 API로 전송한다 |

### 3.4 앱 아이콘·파비콘 방향

#### 현재 소스 해석
- 현재 앱 아이콘의 원본은 `icons/icon-source.jpeg`이다. 검은 바탕 위에 크림색 개완, 주황빛 찻물, 금빛 원형 링, S자 증기가 배치된 정사각 이미지다.
- 개완과 열린 뚜껑은 "차를 우리는 순간"을 직접 보여 준다. 일반 티머그보다 동양 차 도구의 인상이 강해 앱의 정체성과 맞다.
- 열린 뚜껑과 증기는 완료 후 마시는 컵이 아니라, 짧은 우림 중의 뜨거운 상태를 암시한다.
- 금빛 원형 링은 앱 안의 진행 링과 완전히 같은 색·두께일 필요는 없다. 홈 화면과 브라우저 탭에서는 "시간이 돈다"는 상징을 우선한다.
- 어두운 배경은 실제 앱의 `#120d09` 계열과 맞물려 PWA 스플래시·홈 화면에서 이질감이 적다.
- 크림색 기물과 금빛 링은 작은 크기에서도 대비가 높아 16px/32px 파비콘으로 축소되어도 형태가 남는다.

#### 기준 컬러 팔레트

| 역할 | 색상 | 사용 기준 |
|---|---|---|
| 배경 | `#120D09` | 앱 배경과 이어지는 매우 어두운 차색 바탕. 투명 배경보다 홈 화면에서 안정적이다 |
| 다구·김 | `#EFE6D6` | 개완, 뚜껑, 증기의 주 색. 작은 크기에서 형태를 가장 먼저 읽히게 한다 |
| 타이머 고리 | `#E4D691` 또는 `#CDBF63` | 진행 링의 상징색. `#E4D691`은 밝고 부드러운 금빛, `#CDBF63`은 더 muted한 보조안 |
| 찻물 | `#C98F43` | 수면과 차의 따뜻함을 드러내는 주황빛 탕색 |
| 진한 찻물 보조색 | `#9E6526` | 수면 깊이, 그림자, 농향 계열 보조색 |

이 팔레트는 앱 내부의 모든 UI 색을 강제하는 전역 팔레트가 아니라, 앱 아이콘과 파비콘을 다시 만들 때 우선 참조할 기준값이다. 내부 UI의 말차색 차 선택, 회색에 가까운 진행 링, 도구별 탕색은 기능적 신호로 별도 유지할 수 있다.

#### Gemma E4B 이미지 관찰 기록
- 관찰 도구: `gemma-e4b-image-review`, 모델 `gemma-4-e4b-it-qat-ud-q4-k-xl`, 단일 패스, 2026-06-24.
- E4B는 이미지를 "원형 테두리 안의 김 나는 차/따뜻한 음료 아이콘"으로 해석했다. 프로젝트 의도상 중앙 기물은 개완이지만, 작은 크기나 일반 관찰자에게는 넓은 찻잔/컵으로 읽힐 수 있다.
- E4B는 팔레트를 따뜻한 베이지·연갈색 다구와 muted gold/ochre 링으로 보았다. 핵심 인상은 "warm, muted, minimalist"에 가깝다.
- E4B는 컵/증기/원형 프레임이라는 세 요소가 단순해서 작은 크기에서도 알아보기 쉽다고 보았다.
- E4B의 비발견 사항으로 전체 구도는 균형 있고, 단일 주제가 명확해 아이콘 컨셉이 강하다는 평가가 있었다.
- E4B가 남긴 주의점은 두 가지다. 첫째, 금빛 링은 어두운 배경 위에서 축소 시 대비가 약해질 수 있으므로 16px/32px에서 확인해야 한다. 둘째, 증기 선은 단순하지만 아주 작은 크기에서는 뭉칠 수 있으므로 최소 크기 렌더를 확인해야 한다.

#### 제작 원칙
- 아이콘은 앱 화면의 축소판이 아니라 브랜드 표식이다. 내부 UI의 말차색·회색 링 팔레트를 그대로 복제하려고 하지 않는다.
- 작은 크기에서 먼저 읽혀야 하므로 요소 수를 늘리지 않는다. 현재처럼 `원형 링 + 개완 + 찻물 + 증기`까지만 유지한다.
- 파비콘에서는 잎, 글자, 회차, 세밀한 다구 장식처럼 축소 시 뭉개지는 요소를 넣지 않는다.
- 앱 내부 진행 링은 기능 신호이고, 아이콘의 금빛 링은 상징 신호다. 둘이 완전히 같아 보이지 않아도 괜찮다.
- 링 색은 배경 위 대비가 부족하면 `#CDBF63`보다 `#E4D691`을 우선한다.
- 소스는 래스터 이미지로 관리한다. `scripts/generate_icons.py`는 `icons/icon-source.jpeg`를 기준으로 필요한 PNG 세트를 재생성한다.
- `index.html`에는 PNG 파비콘만 연결한다. 같은 의미의 SVG 파비콘을 별도로 유지하지 않아 브라우저별 우선순위 차이를 줄인다.

#### 교체 기준
- 16px 파비콘에서 금빛 링의 열린 원, 개완 덩어리, 증기 방향이 구분되어야 한다.
- 180px/192px 홈 화면 아이콘에서 뚜껑이 열린 차 도구로 보여야 한다.
- 배경은 투명보다 어두운 고정 배경을 우선한다. 다양한 홈 화면 배경 위에서 안정적으로 보이기 때문이다.
- 아이콘을 바꿀 때는 `icons/icon-source.jpeg`를 먼저 교체하고 `python3 scripts/generate_icons.py`로 PNG를 재생성한다.
- 아이콘 파일을 바꾼 뒤에는 `sw.js` 캐시 버전을 올려 설치된 PWA가 새 아이콘을 받게 한다.

### 3.5 기능 확장 시 배치·메뉴 표현 — 결정·미구현

상세 기준과 대안 검토는 [화면 배치와 메뉴 표현](design-navigation.md)에 둔다. 위 §3.1–3.3은 현재 화면이며 아래는 후속 적용할 설계다.

- 우상단은 직접 언어 선택과 `메뉴`로 구성하고 기존 사용법은 메뉴 안으로 옮긴다. 좌상단 `우림 끝`, 중앙 타이머, 푸터 소리·차 느낌은 유지한다.
- 기록함·단어장·레시피는 구현된 시점부터 메뉴에 노출한다. 첫 저장으로 메뉴를 해금하거나 홈에 개수 배지·하단 탭을 추가하지 않는다. 느낌 시트에는 단어장 맥락 진입, 기록함에는 선택적 회고, 설정에는 전체 백업·복원을 둔다.
- 목적지·언어·소리는 아이콘+이름, 우림·임시저장·삭제는 문구, 이전·다음·시간 ±·닫기는 아이콘만 쓴다. 브라우저 기록 저장은 사용자 선택에 따라 모바일 기기 아이콘+문구를 쓴다. 아이콘만 있는 버튼에도 구체적 접근성 이름과 44px 조작 영역을 제공한다.
- TW-05는 언어 popover·기본 메뉴·공지사항 읽기와 기존 문서 연결을 구현한다. 메뉴의 사용법 위에 스피커 아이콘+공지사항을 두고, 배포된 변경과 예정된 업데이트를 구분한다. 정적 공지를 같은 문서에서 읽으며 상세는 [공지 정책](design-navigation.md#announcements)을 따른다. 장기 기록·단어장·회고·레시피를 앞당기지 않는다.

### 4.5 다구와 우림·분리 방식 확장 — 미구현

향후 기록 모델에서는 기물의 종류와 우림 방식·분리 방식을 구분한다. 같은 머그도 거름망을 들어 올리는 방식과 찻잎을 그대로 두는 방식이 다를 수 있다. `pour / drain / lift / none`은 이 구분을 위한 후보이며 아직 확정된 런타임 상태나 데이터 필드가 아니다.

현재는 5종 모두 `done → draining → 다음 포` 흐름을 사용한다. 표일배의 버튼식 배수 외에 `lift`·`none`에 맞춘 별도 완료 동작은 구현되지 않았다. 확장 시에는 타이머 준비 흐름과 완료 행동부터 검증하고, 기물 이미지 추가와 데이터 모델 변경을 함께 다룬다.

## 5. 우림 연출

### 5.1 긴장 곡선

| 구간 | t 범위 | 표현 | 소리 |
|---|---|---|---|
| A. 우러나기 | 0-0.5 | 색이 초반 빠르게 오르고 잎이 펴지기 시작 | 무음 |
| B. 무르익음 | 0.5-0.85 | 색은 완만히 포화, 김과 글로우 안정 | 무음 |
| C. 임박 | 마지막 3-5초 | 숫자·메시지·링·글로우가 강조 | 예고음 + 매초 tick |
| 완료 | t >= 1 | 완료 메시지, 플래시, 완료 상태 고정 | 종소리 |

### 5.2 구현된 연출
- 색 곡선은 `easeInOut` 대신 추출 포화형 `sat(t)`를 쓴다.
- 개완 액체는 path 기반 형태, 세로 그라데이션, meniscus, 벽면 wash를 쓴다.
- 표일배 아래 잔은 `rect + clip`에서 파라메트릭 `path`로 바뀌었다.
- 찻잎은 차종별 프로필(`leafProfile`), 잎별 delay, sway, flutter, pour 난류를 가진다. 7종 차마다 고유한 잎 형태(`kind`)를 사용한다: 녹차 needle(가는 바늘), 백차 bud-leaf(싹+넓은 어린잎), 청향 우롱 ball-broad(넓은 타원), 농향 우롱 ball-crinkle(주름진 넓은 잎), 홍차 mid-strip(중폭 긴 잎), 보이 생차 serrated(톱니 가장자리), 보이 숙차 broken(작은 잎+파편 혼합).
- 수면은 `shimmerSurf()`로 미세하게 일렁이며 임박 구간에서 진폭이 커진다.
- 불투명 도구는 `ambientGlow`와 `steamPorts()`로 진행감을 만든다. 김은 실제 다구의 증기 배출 경로에 맞춰 배치한다: 개완과 표일배는 뚜껑 중앙이 아닌 뚜껑-사발 림 틈새 양쪽에서, 머그는 수면 중앙 양측에서, 티팟은 주둥이와 뚜껑 꼭지에서, 다호는 뚜껑 위에서 나온다.
- 유리 도구(개완·표일배)의 찻잎은 우림 전 idle 상태에서도 보인다. 마른 잎이 다구 안에 이미 들어 있는 물리적 상태를 반영한다.
- pour 구간은 0.9초이며 물줄기와 착지 잔물결이 표시된다.

### 5.3 아직 구현되지 않은 연출
- 개완 완료 시 뚜껑 림라이트 이동과 틈 하이라이트. 현재 `lidTarget`과 `lidLift`는 계산되지만 `#g-lid`에 쓰이지 않는다.
- 회차별 탕색 점감. 현재 5泡도 1泡와 같은 `peak` 농도를 사용한다.
- 도구 전환 전이. 현재는 `display:none`과 표시 전환만 사용한다.

### 6.2 반복 사용 상태 영속 스펙

구현됨. 앱을 다시 열었을 때 직전에 쓰던 차·다구·시간·음소거 상태에서 바로 시작한다. 우림 진행 상태와 기록은 복원하지 않는다.

아래는 TW-01까지 반영한 구현 스펙이다. 저장 병합·빈 태그 목록·ID 호환 계약은 [데이터 보존 §4.1.1](data-portability.md#preferences-contract), TW-05의 언어·태그 확장은 [다국어 설계](design-localization.md)를 따른다. TW-05의 언어·태그 표현 확장은 구현 대기다.

핵심 원칙: **권장 시간은 권장일 뿐이고, 사용자가 직접 조정한 시간이 그 차의 기준이다.** 조정은 절대 초가 아니라 권장 대비 보정값(델타)으로 차별로 저장한다. 이렇게 하면 어느 포에서 조정하든 같은 보정으로 환산되어 이후 포와 다음 세션 1포에 일관되게 적용된다.

#### 저장 범위

단일 키 `teaTimer.preferences.v1`에 아래 형태로 저장한다.

```js
{
  version: 1,
  lastVesselId: "gaiwan",
  lastTeaId: "oolong",
  secDeltaByTea: { "oolong": 25 },
  muted: false,
  customTags: ["단맛", "꽃향", "과일"]
}
```

- `lastVesselId`: 마지막으로 고른 다구 ID.
- `lastTeaId`: 마지막으로 고른 차 ID.
- `secDeltaByTea`: 차별 보정 초. 사용자가 시간을 직접 조정한 순간의 `조정값 − 권장(현재 포)`이며 음수도 가능하다. ±115초를 넘는 값은 손상 데이터로 본다.
- `muted`: 마지막 음소거 상태.
- `customTags`: 차 느낌 시트와 설정 페이지가 공유하는 감각 태그 목록. 기본 14종에서 추가·삭제할 수 있다.
- 회차, 진행 중 타이머, `infusionHistory`, 완료 상태는 세션 한정이며 저장하지 않는다.
- 아직 UI가 없는 `ticks`, `flash`, `wakeLock` 설정은 이번 범위에 넣지 않는다.

#### 시간 계산 규칙

- 권장 시간은 기존 그대로 `권장(n) = base + add×(n−1) + 다구 보정(steepOffset)`이다.
- 표시 시간은 항상 `clamp(권장(n) + 보정, 5, 120)`이다. 보정이 없으면 권장 시간 그대로다.
- 보정은 차 단위로 하나만 두고, 비율이 아니라 덧셈 델타를 쓴다. 포별 증가 리듬(`add`)은 차 지식으로 유지하고, 사용자 취향(전체적으로 길게/짧게)은 전체 이동으로 반영한다.
- 예: 청향 우롱(1포 권장 20초, +5초/포)을 1포에서 45초로 조정하면 보정은 +25초. 2포는 50초, 3포는 55초, 다음 세션 1포는 다시 45초가 된다.

#### 저장 시점

- 차 또는 다구 선택이 바뀌면 즉시 저장한다.
- 슬라이더나 `−`/`+`로 시간이 바뀌면 현재 차의 보정을 `조정값 − 권장(현재 포)`로 즉시 재기준화해 저장한다.
- 음소거 버튼을 누르면 즉시 저장한다.
- 타이머 프레임마다 저장하거나 우림 시작·완료를 저장 조건으로 삼지 않는다.

#### 시작과 선택 변경 규칙

1. 앱 시작 시 저장값을 읽고 유효한 차·다구·음소거 값을 먼저 복원한다.
2. 시작 시간은 `권장(1포) + 복원된 차의 보정`이다.
3. 차를 바꾸면 그 차의 보정을 적용한 1포 시간을 보여준다. 보정이 없으면 현재 다구 기준 1포 권장 시간을 쓴다.
4. 다구를 바꾸면 새 다구의 권장 시간에 같은 차 보정을 그대로 더한다. 다구 보정(`steepOffset`)과 사용자 보정은 서로 독립이며 합산된다.
5. 다음 포로 넘어가면 `권장(다음 포) + 보정`으로 계산한다. 자동 계산은 보정을 바꾸지 않으며, 사용자가 다시 직접 조정할 때만 보정이 재기준화된다.
6. 저장값을 복원해도 항상 `idle`, 1포, 빈 우림 기록으로 시작한다. 실행 중이던 타이머가 재개된 것처럼 보이면 안 된다.
7. 차·다구 전환은 기존 구현처럼 현재 세션을 1포·idle로 초기화한다. 저장된 보정과 선호값은 이 초기화의 영향을 받지 않는다.

#### `우림 끝`과 초기화

- 상단 `우림 끝`은 현재 우림 세션과 차 느낌 초안을 비우고 1포·idle 상태로 되돌린다. 되돌린 뒤 표시 시간은 `권장(1포) + 보정`이므로 사용자가 맞춘 시간으로 돌아온다.
- 이 동작은 저장된 차·다구·차별 보정·음소거를 삭제하지 않는다.
- 전체 저장값 삭제는 설정 페이지의 `기억한 설정 지우기` 같은 명시적 보조 동작으로만 제공한다. 보정과 커스텀 태그가 삭제되므로 순수 권장 시간과 기본 태그로 복귀한다.
- 삭제 성공 시 설정 화면에서 순수 권장 시간·기본 태그를 표시한다. 메인에 다시 진입하면 청향 우롱·개완·권장 20초·소리 켜짐으로 시작한다. 이미 열린 다른 탭의 진행 중 타이머는 초기화하지 않는다.

#### 권장 지점 표시

- 슬라이더 트랙 위에 현재 차·다구·포 기준 권장 시간 위치를 작은 눈금으로 표시한다.
- 사용자가 자기 조정이 권장 대비 어느 쪽인지 한눈에 보고, 원하면 권장으로 쉽게 되돌릴 수 있게 한다.
- 눈금은 저대비 장식 수준으로 유지해 시간 숫자와 슬라이더 손잡이보다 시선을 끌지 않아야 한다. 다만 사용자가 시간을 늘려 눈금이 금색 채움 구간 안에 들어가도 식별되도록, 밝은 몸통에 어두운 테두리를 두른다.
- 눈금 위치는 트랙 전체 폭의 선형 비율이 아니라 손잡이 중심 좌표계(양끝에서 손잡이 반지름만큼 보정)로 계산한다. 손잡이를 권장값에 두면 눈금이 손잡이 한가운데에 온다.
- 차·다구·포가 바뀌면 눈금 위치도 즉시 갱신한다.

#### 오류와 호환성

- `localStorage` 접근 실패, JSON 파싱 실패, 알 수 없는 ID, 범위를 벗어난 보정값은 조용히 무시하고 기본값으로 시작한다.
- 일부 필드만 유효하면 유효한 필드만 복원한다.
- 저장 실패가 타이머 사용을 막아서는 안 된다. 명시적 설정 편집이 저장되지 않았을 때는 비차단 상태 안내를 제공하고 성공으로 표시하지 않는다.
- 공통 loader는 payload 버전이 다르면 기본값으로 시작하며 기존 raw에 쓰지 않는다. TW-01·05에서는 키와 `version: 1`을 유지하고 새 필드는 호환 확장한다. 향후 버전 변경은 별도 이관 설계를 요구하며, 단순 폴백으로 사용자 자산을 덮어써도 된다는 의미가 아니다. 읽기·쓰기 보호 규칙은 [저장 계약](data-portability.md#preferences-contract)을 따른다.

#### 완료 기준

- 새로고침과 PWA 재실행 후 마지막 차·다구·보정이 적용된 시간·음소거 상태가 복원된다.
- 권장 20초인 차를 1포에서 45초로 조정하면 2포는 50초로 계산되고, 재실행 후 1포는 45초로 복원된다.
- 차 A와 차 B에 서로 다른 보정을 만든 뒤 오가면 각각의 시간이 복원된다.
- `우림 끝`을 눌러도 보정과 선호값은 유지되고 회차·포 기록·차 느낌 초안만 초기화된다.
- 설정 페이지의 `기억한 설정 지우기` 후에는 순수 권장 시간과 기본 태그로 돌아온다.
- 손상된 저장 데이터나 사용할 수 없는 저장소 환경에서도 기본 타이머가 정상 동작한다.
- 복원 직후 소리가 자동 재생되지 않으며, 소리 켜짐 상태여도 WebAudio는 첫 사용자 동작에서만 활성화한다.
- 권장 지점 눈금이 차·다구·포 변경에 따라 올바른 위치로 이동한다.

### 6.3 `[이번 차의 느낌]` 기록·export 스펙

상세 UI와 확장안은 [design-tea-feeling.md](design-tea-feeling.md)에서 관리한다. 현재 구현의 기준은 다음과 같다.

- 푸터의 `차 느낌` 버튼은 항상 보이지만 시트는 자동으로 열리지 않는다. 사용자가 직접 눌러야 타이머 위 바텀시트가 열린다.
- 시트는 현재 선택한 차·다구·날짜와 완료된 포의 타이머 실행 시간을 요약한다. 사용자는 표시 제목, 감각 태그, 자유 문장을 선택적으로 입력할 수 있다.
- `customTitle`, `sessionDraftTags`, `sessionDraftNote`는 실행 중인 세션 메모리에만 둔다. 시트를 닫거나 `임시 저장`을 눌러도 같은 세션에서는 유지되지만 새로고침·앱 재실행·`우림 끝` 뒤에는 복원하지 않는다.
- 텍스트 복사는 차·다구·날짜·포별 시간·태그·문장을 일반 텍스트로 내보낸다. 카드 이미지는 680×900 Canvas PNG로 만들고 파일 공유가 가능하면 Web Share API를, 아니면 다운로드를 사용한다.
- 사용자 입력이 없어도 자동 세션 정보만으로 텍스트와 카드를 내보낼 수 있다.
- IndexedDB 기반 영구 기록 저장소와 `[차 열 잔의 기록]` 화면은 구현하지 않았다. 영구 보관은 현재 export가 담당한다.
- 닫힌 시트의 포커스 차단, `dialog` 의미, Escape 닫기, 포커스 복귀, 태그 44px 유효 터치 영역은 아직 완료 기준을 충족하지 않는다.

### 6.4 장기 기록·사용자 자산 확장 원칙 — 미구현

세부 저장·이동성 기준은 [data-portability.md](data-portability.md), 표현을 돕는 기능은 [sensory-vocabulary.md](sensory-vocabulary.md)에서 관리한다. 아래는 현 구현과 구분한 제품 방향이다.

- **초안 보호와 기록 확정을 분리한다.** 입력을 시작한 내용은 로컬 초안으로 보호하고, `브라우저 기록으로 남기기` 같은 명시적 행동으로 장기 기록을 확정하는 방향이다. 현재 초안은 메모리 한정이다. TW-03의 선택 잠금·명시적 종료는 [차 느낌 설계](design-tea-feeling.md#draft-policy)로 결정했고, 재실행 복구·장기 초안 저장소는 후속 설계다. 타이머만 사용한 세션을 자동으로 기록함에 쌓지 않는다.
- **가벼운 설정과 사용자 자산을 분리한다.** 설정은 `localStorage`, 장기 `sessions`·`vocabulary`·향후 `recipes`는 IndexedDB를 후보로 둔다. 현재 설정 안의 `customTags`도 사용자 자산이므로 백업 대상에서 누락하지 않는다. 기존 ID·설정의 호환성과 태그 보존은 TW-01에서 먼저 처리했다.
- **앱 관찰·사용자 보고·권장값을 구분한다.** `observed`는 앱 안의 선택과 실행 시간이지 실제 물리적 우림의 측정값이 아니다. 실제 수온·찻잎 g·물 ml와 메모는 `reported`, 권장 시간·온도는 `recommended`로 구분한다. canonical ID와 표시 이름을 분리하고 개인 표현은 원문을 보존한다.
- **저장소보다 파일이 오래 살아야 한다.** 기본 프리셋·기본 단어·번역은 재생성 가능한 앱 자산이다. 개인 세션·단어·레시피·메모·커스텀 태그는 JSON 전체 백업·복원과 개별 JSON/Markdown 이동 대상이다. 자체 백업 복원부터 검증하고, 공개 스키마가 안정된 뒤 외부 호환 import를 연다.
- **열 잔과 보관 정책을 분리한다.** 기존 `teaTimer.cups.v1` 최근 10장·초과 자동 삭제안은 현행 계획에서 제외한다. 이는 무제한 보관 확정이 아니며 용량·삭제·복원 정책은 별도로 결정한다. 기록함은 기능 도입 후 빈 상태에서도 메뉴로 접근하고, 첫 저장 성공 뒤 맥락 링크·열 잔 이후 기록함 내부의 조용한 회고를 제공하는 [배치 설계](design-navigation.md)를 따른다. 홈에 개수 배지를 추가하지 않는다.
- **단어장은 기억을 돕고 레시피는 경험을 재사용한다.** 풍미 분류는 원전 조사 후 확정하고, 생활 속 표현과 개인 단어를 동등하게 다룬다. 현재 커스텀 태그는 개인 단어장 구현과 같지 않다. 이후 레시피는 이전 포별 시간 순서를 다시 쓰는 기능으로 검토하며 50잔·100잔 같은 고정 해금 조건은 두지 않는다.

사용자 기록을 중앙에 저장하지 않는 방향은 현재 도움말의 Worker/D1 박수·반응 집계와 별개다. 재고·구매·가격 관리, 커뮤니티/SNS는 제품의 비목표로 둔다.

### 7.2 PWA와 캐시
- manifest는 `display: standalone`, `orientation: portrait`, `theme_color: #120d09`를 사용한다.
- 현재 캐시는 `chahanjan-shell-v59`과 `chahanjan-static-v59`으로 분리한다. 설치 시 로컬 문서 셸·공통 저장 JS와 아이콘·다구·다하 자산을 사전 캐시하고, 활성화 시 `chahanjan-` 접두어의 이전 버전만 삭제한 뒤 열린 클라이언트를 즉시 제어한다.
- HTML·manifest·탐색 요청은 network-first로 최신 문서를 우선하고 오프라인이면 shell 캐시 또는 `index.html`로 폴백한다. 버전이 지정된 이미지·아이콘은 cache-first로 반환해 재방문 때 대형 정적 자산을 다시 요청하지 않는다.
- 외부 origin 요청은 가로채지 않고, 앱과 무관한 다른 Cache Storage 항목도 삭제하지 않는다.
- 앱 코드·자산 변경을 배포할 때는 `CACHE_VERSION`을 올려 설치된 PWA의 앱 셸을 갱신한다. 개발 문서만 바꿀 때는 런타임 캐시 버전을 올리지 않는다.
- 코드 수정 후 브라우저에서 옛 코드가 보이면 서비스워커 등록 해제와 캐시 삭제가 필요하다.
- 앱 아이콘 PNG는 이미 존재하므로 "아이콘 추가"는 더 이상 TODO가 아니다.
- 폰트는 아직 Google Fonts CDN에 의존하므로 완전 오프라인 기준에서는 미완료다.

### 7.3 타이머 정확도
- 우림 종료는 `performance.now()` 기반 절대 종료 시각으로 계산한다.
- rAF가 백그라운드에서 멈추더라도 복귀 후 다음 프레임에서 절대 종료 시각과 비교해 남은 시간 또는 완료 상태를 보정한다. 다만 백그라운드에 머무는 동안 완료음을 예약해 주는 구조는 아니다.
- `visibilitychange`로 포그라운드 복귀 시 Wake Lock을 재획득한다.
- `ensureAudio()`는 컨텍스트가 없거나 `closed`면 새로 만들고, `suspended`뿐 아니라 iOS Safari의 `interrupted`를 포함해 상태가 `running`이 아니면 `resume()`한다.
- 앱 복귀·다음 포 시작·tick/예고음/완료음 재생 직전에 이 복구 경로를 거친다. 백그라운드 정확도를 높이려면 WebAudio clock 예약 또는 Worker tick이 다음 단계다.

### 7.4 상태 머신

```text
idle
  └─ startBrew()
       └─ pour (0.9s)
            └─ steep
                 └─ finishSteep()
                      └─ done: 차 따라내기 / 버튼 눌러 내리기
                           └─ drainVessel() → draining
                                └─ done + isDrained: 다음 泡 우리기
```

<a id="early-pour-policy"></a>

#### 7.4.1 TW-04 즉시 출탕 — 확정·구현 대기

`steep` 중 메인 버튼을 일반 다구는 `지금 따르기`, 표일배는 `지금 내리기`로 활성화한다. 한 번 누르면 현재 포를 확정하고 바로 `draining`으로 이동한다. 중간에 `차 따라내기`를 다시 누르게 하지 않는다. `pour` 연출과 `draining` 중에는 버튼을 비활성화한다. reduced-motion에서는 pour 연출 없이 steep에 진입한 시점부터 가능하다.

**시간과 기록**

- 시간의 시작점은 기존 `steepStart`다. 일반 모드의 0.9초 붓기 연출과 출탕 연출 시간은 포함하지 않는다. 앱 내부 타이머 실행 시간이며 실제 물리적 우림 시간을 측정했다는 뜻이 아니다.
- 세션 메모리의 현재 포에 예정 시간, 확정 경과 밀리초, 완료 원인(`timer` / `early`)을 구분한다. 설정값 `sec`를 조기 경과 시간으로 바꾸거나 보정 저장 함수를 호출하지 않는다.
- 정상 완료는 예정 시간만큼 기록한다. 프레임·복귀가 늦어져도 초과 시간을 더하지 않는다. 조기 출탕은 `clamp(now - steepStart, 0, 예정 밀리초)`를 기록한다.
- 표시용 초는 경과 밀리초를 가장 가까운 정수로 반올림한다(0.5초는 올림). 양수인데 반올림 결과가 0이면 `1초 미만`, 정확히 0이면 `0초`로 표시한다. 원시 밀리초는 유지하고 메인·시트·텍스트·카드가 같은 포맷 규칙을 사용한다. 예: 8.49초→8초, 8.50초→9초, 0.20초→1초 미만.
- 현재 포는 완료를 처음 받아들이는 시점에 한 번만 확정한다. 다음 포 번호는 출탕 종료 때 한 번만 증가하며 시간은 기존 권장값과 저장 보정으로 계산한다. 장기 저장이나 백업 스키마를 추가하지 않는다.

**경계와 신호**

- 클릭을 처리하는 시각이 이미 종료 시각 이상이면 `timer`로 확정한다. 그 클릭은 출탕 요청도 처리하므로 새 버튼을 다시 누를 필요가 없다. 자동 완료와 클릭 중 먼저 처리한 쪽만 기록·완료 알림을 확정한다.
- 조기 완료에는 새 종료음·플래시를 발생시키지 않고 잔여 예고음·tick을 중단한다. 완료 문구·출탕 연출로 조작을 알린다. 탕색은 해당 경과 시점의 값을 사용하고 강제로 최종 농도로 올리지 않는다.
- 정상 완료의 기존 종료음·시각 신호는 한 번만 유지한다. 이후 출탕 요청은 이미 끝난 포의 알림을 다시 발생시키지 않는다.
- 연타·rAF·앱 복귀·지연된 오디오 resume·이전 drain 콜백이 기록/다음 포/소리를 중복 실행하지 않게 한다. `우림 끝`은 이전 포의 비동기 작업을 무효화하고, 중단 포를 완료로 기록하지 않는다.
- 기존 Wake Lock·오디오 복귀·렌더 예산을 유지하며 백그라운드 완료음 예약은 추가하지 않는다.

**통과 시나리오:** 종료 1ms 전/정각/1ms 후의 클릭, 자동 완료 직후 클릭, 연타, 출탕 중 종료, 오디오 resume 대기 중 종료, 앱 복귀를 확인한다. 5종 다구·일반/reduced-motion에서 기록 한 개·출탕 한 번·다음 포 증가 한 번·보정값 불변을 검증한다. 1초 미만 기록도 완료 1포와 구분해 정확히 표시한다.

### 7.5 제작자 반응 집계
- 메인 타이머 화면은 제작자 반응 요청을 보내지 않는다. 제작자 반응 진입점은 `help.html`의 응원 박수 모달에만 있다.
- 사용자가 `박수` 또는 `괜찮습니다`를 고르면 `POST /reaction`으로 `{app:"tea-timer", reaction:"clap"|"down"}`만 전송한다. 전송은 `keepalive:true`이며, 실패해도 도움말 사용을 막거나 오류 UI를 띄우지 않는다.
- `workers/reactions/`의 Cloudflare Worker는 허용된 Origin, 명시된 `Content-Length`가 1KB를 넘지 않는 JSON, 앱 ID와 두 반응값을 검증한 뒤 D1에 앱·반응·서버 시각을 저장한다. 사용자 계정이나 브라우저 식별자는 payload에 없다.
- `GET /admin/reactions`는 Bearer `ADMIN_TOKEN`이 있어야 전체 합계와 최근 일별 집계를 반환한다. `GET /health`는 배포 상태 확인용이다.

### 7.6 모바일 렌더·전력 예산
- 타이머의 기준 시각은 `steepStart`와 `steepMs`로 계산한다. 렌더가 건너뛰어져도 남은 시간과 완료 판정은 절대 경과시간에서 복구되어야 한다.
- 메인 애니메이션은 하나의 스케줄러만 소유한다. 배수는 별도 `requestAnimationFrame` 루프를 만들지 않고 `phase:"draining"` 상태로 같은 스케줄러에서 처리한다.
- 상태별 최대 시각 프레임은 `pour/steep/draining` 30fps, 완료 후 사용자의 따르기 행동을 기다리는 김·찻잎 연출 12fps다. `idle`과 배수 완료 상태는 이벤트 기반 단일 렌더만 허용한다.
- `prefers-reduced-motion: reduce`에서는 pour 전환을 즉시 처리하고, 우림 숫자·신호를 초 경계에 맞춰 갱신하되 연속 시각 프레임은 사용하지 않는다.
- 카운트다운 텍스트, 임박 문구·클래스, 정적 SVG 속성은 값이 바뀔 때만 DOM에 쓴다. 찻잎의 형태·색·크기와 흔들림 transform은 분리 캐시한다.
- 김 엘리먼트는 최대 개수를 한 번 만들어 재사용한다. 프레임마다 SVG 노드를 추가·삭제하지 않으며, 보이는 개수와 속성만 조절한다.
- Wake Lock은 놓침 방지 기능이므로 `pour/steep` 동안 유지하고 완료 즉시 해제한다. 화면 켜짐 비용을 상쇄하기 위해 위 렌더 예산을 지킨다.
- 음소거 상태에서는 `AudioContext`를 생성하거나 재개하지 않는다. 완료음이 끝나고 활성 우림이 없으면 컨텍스트를 suspend하되 다음 사용자 조작에서 복구한다. 음소거·초기화는 예약/재생 중 oscillator를 먼저 stop해 다음 우림에서 잔여음이 이어지지 않게 한다.
- 설치 캐시는 모든 필수 자산의 오프라인 사용을 보장한다. 버전이 지정된 이미지·아이콘은 cache-first, 문서 셸은 network-first로 갱신해 앱을 열 때 대형 정적 자산을 반복 검증하지 않는다.
- 다구 PNG는 오프라인 캐시에 모두 보관하되 정상 대기 상태의 SVG DOM에서는 현재 선택한 다구의 `href`만 활성화한다. 전환 중에만 기존·대상 자산을 함께 유지하고, `Image.decode()`와 숨긴 대상 SVG `<image>`의 실제 `load`를 모두 확인한 뒤 화면을 교체한다. 새 다구가 한 프레임 표시된 다음 이전 `href`를 제거해 디코드 메모리의 반환을 허용하고 전환 빈 프레임을 막는다. 브라우저 내부 캐시가 메모리를 즉시 반환한다는 보장은 없다.
- 저장된 시작 다구의 자산 요청과 UI 초기화는 원격 웹폰트 완료를 기다리지 않고 즉시 시작해 cold/offline 실행에서 빈 무대가 길어지지 않게 한다.
- 모든 다구를 Service Worker 설치 때 사전 캐시하므로 이 방식은 완전 오프라인 기능을 유지하며 CPU/GPU 디코드 상주량을 줄이기 위한 것이다. 첫 설치의 정적 자산 다운로드 용량 자체는 줄이지 않는다.
- 카드 PNG 생성은 `toBlob()`을 우선해 base64·binary·typed-array 삼중 복사를 피한다.

## 8. 접근성·모션·터치

### 8.1 반영된 기준
- `#timeLabel`은 평소 `aria-live="polite"`, 완료 시 `assertive`로 전환한다.
- 헤더의 선택 차·회차 정보는 시각적으로 숨긴 live region에서 보조기술에만 전달한다.
- 주요 버튼과 아이콘 버튼은 44px 이상 터치 타깃을 가진다.
- `prefers-reduced-motion`이면 urgent animation과 플래시 animation을 끈다.
- vessel/tea 셰브런 대비는 `--ink-dim`으로 보강되었다.
- 색만으로 완료를 알리지 않고 숫자, 메시지, 소리, 플래시를 같이 쓴다.
- 공통 토스트는 작은 말풍선 C와 ‘-습니다’체를 사용한다. 표시·문구 기준은 [공통 알림](design-navigation.md#common-toast)을 따른다.

### 8.2 접근성 검증 기준
- 새 제스처를 추가할 때는 기존 버튼 접근성과 충돌하지 않아야 한다.
- 완료 플래시는 reduced-motion 외에도 완료 메시지 가독성을 실제 화면으로 확인한다.
- 폰트 변경 시 fallback과 글자폭 변화가 모바일 레이아웃을 흔들지 않는지 확인한다.

- 입력 초안의 자동 보호와 장기 기록의 명시적 확정을 분리한다. 가벼운 설정은 localStorage, 장기 사용자 자산은 IndexedDB를 후보로 한다.
- 사용자 자산의 JSON 백업·복원, 개별 JSON/Markdown 이동, 공개 스키마와 canonical ID를 확장 기준으로 둔다.
- 감각 단어장·다국어·열 잔 회고·경험 기반 레시피는 후속 단계다. 이미 구현된 차 느낌 시트와 텍스트/PNG export를 미구현으로 되돌려 표기하지 않는다.

## 12. 검증 절차

### 12.1 서비스워커 캐시 초기화

```js
(async()=>{
  const registration = await navigator.serviceWorker.getRegistration();
  if (registration) await registration.unregister();
  for(const k of await caches.keys()) if(k.startsWith("chahanjan-")) await caches.delete(k);
  location.reload();
  return "reloaded";
})()
```

### 12.2 rAF 기반 시간 진행 검증

헤드리스 미리보기는 비활성 상태에서 `requestAnimationFrame`이 멈출 수 있다. 시간 진행은 eval 내부에서 rAF 루프를 돌려 확인한다.

```js
(async()=>{
  const slider = document.getElementById("slider");
  const brew = document.getElementById("brew");
  const time = document.getElementById("time");
  slider.value = 8;
  slider.dispatchEvent(new Event("input"));
  brew.click();
  const samples = [];
  for(let i = 0; i < 600; i++){
    await new Promise(r => requestAnimationFrame(r));
    samples.push(time.textContent);
    if(brew.textContent.includes("차 따라내기") || brew.textContent.includes("버튼 눌러 내리기")) break;
  }
  return { frames: samples.length, last: samples.at(-1) };
})()
```

### 12.3 시각 작업 판정
- 좌표 오버레이는 clip과 요소 위치를 확인하는 데만 쓴다.
- 좌표가 맞아도 물성은 틀릴 수 있다. 렌더 이미지를 처음 보는 사용자 시선으로 다시 평가한다.
- 같은 결함을 좌표만 바꿔 반복 수정하면 primitive가 틀렸다는 신호다. 액체는 영역 clip이 아니라 형태 path가 책임져야 한다.

### 12.4 차 느낌 기록·export 검증
- 첫 우림 전과 1포 이상 완료 후 각각 시트를 열어 자동 요약, 제목 수정, 태그, 자유 문장과 세션 초안 유지 범위를 확인한다.
- 텍스트 복사 결과에 차·다구·날짜·완료 포별 시간·태그·문장이 포함되는지 확인한다.
- 카드 PNG가 680×900으로 생성되고 Web Share 지원 환경에서는 파일 공유, 미지원·실패 환경에서는 다운로드로 이어지는지 확인한다.
- `우림 끝` 뒤 세션 초안이 사라지고 차·다구·시간 보정·음소거·커스텀 태그 같은 선호값은 유지되는지 확인한다.
- 키보드와 스크린리더로 시트·카드 모달의 진입, 포커스 순환, Escape 닫기, 원래 버튼으로의 포커스 복귀를 확인한다. 닫힌 레이어의 조작 요소는 포커스 순서에 없어야 하고 태그의 유효 터치 영역은 44px 이상이어야 한다.

### 12.5 iOS 오디오 복구 검증
- 소리 켜짐 상태에서 한 번 사용자 조작으로 오디오를 활성화한 뒤, 우림 중 다른 앱 전환·통화·미디어 재생 등으로 오디오 인터럽션을 발생시킨다.
- 앱으로 돌아와 현재 포의 예고음·tick·완료음이 재생되는지 확인하고, 이어서 `다음 泡 우리기`를 시작해 다음 포에서도 소리가 유지되는지 확인한다.
- 복귀 직후 `AudioContext.state`가 `running`으로 돌아오지 못하더라도 타이머·화면 완료 상태는 정상 동작해야 한다.

### 12.6 렌더·발열 회귀 검증
- 모바일 뷰포트에서 idle 상태의 SVG 시각 속성을 두 시점에 비교해, 사용자 입력이 없을 때 값이 변하지 않는지 확인한다.
- 5초 우림으로 `idle → pour → steep → urgent → done → draining → ready`를 통과시키고 숫자, 김, 찻잎, 완료 문구와 버튼 라벨이 기존 기능을 유지하는지 확인한다.
- 진행 중 시각 샘플 간격이 30fps 예산을 넘지 않고, done은 12fps 예산으로 낮아지며, 배수 완료 뒤에는 연속 갱신이 멈추는지 확인한다.
- reduced-motion 환경에서는 연속 시각 효과 없이도 카운트다운, 예고음, tick, 완료음, 플래시 대체 상태가 정상인지 확인한다.
- 첫 설치와 재방문 모두 오프라인 앱 셸을 제공하고, 재방문에서 대형 이미지·아이콘의 불필요한 백그라운드 재검증이 없는지 네트워크 기록으로 확인한다.
- 초기 화면에서 선택 다구에 해당하는 SVG image만 `href`를 가지는지, 다구 전환 중 이전 이미지가 유지되다가 선디코드와 대상 SVG load 완료 뒤 새 다구로 바뀌는지, 새 화면 한 프레임 뒤 다시 한 다구만 `href`를 가지는지 확인한다. 전환 실패·타임아웃과 로딩 중 차·우림·초기화 입력에서도 기존 다구와 조작 상태가 보존되어야 한다.
- 실제 iPhone의 Safari 및 홈 화면 PWA에서 cold/offline 시작 5종, 빠른 다구 연타·스와이프, 백그라운드 복귀, 음소거·초기화 직후 잔여 완료음, 카드 공유와 다운로드 폴백을 확인한다. 이는 데스크톱 자동화 통과와 별도로 실기기에서 수행한다.

## 13. 바꾸지 말 것

1. 제품명은 **차 한 잔의 시간 / Time for Tea**.
2. 미설정 기본 언어는 한국어다. TW-05·06 이후 사용자가 번체 중국어를 선택할 수 있으며, 번체 모드의 중국어는 실제 UI 언어다. 한국어 모드의 CJK 보조 표기와 구분한다.
3. 회차 표기는 **泡**를 쓴다. `煎`으로 바꾸지 않는다.
4. 표일배는 윗 거름망 챔버에서 우린 뒤 메인 버튼으로 아래 잔에 배수한다.
5. 과침 카운트업은 넣지 않는다.
6. 권장 온도와 권장 시간은 시간 영역의 `권장 우림` 한 줄로 상시 병기한다(현재 포 기준).
7. 고정 도구 위에 이미 자산이 표현하는 부품을 SVG로 다시 덧그리지 않는다.
8. 색만으로 완료를 알리지 않는다.
