# 화면 배치와 메뉴 표현 — 확장 설계

> 결정일: 2026-08-31
> 상태: **TW-05 언어·메뉴·공지·접힘 제목을 한국어 런타임에 반영, 사용자 화면 검토 대기**. 후속 기록 기능의 화면 내용과 데이터 모델은 각 Phase에서 설계·검증한다. 구현·검증 경계는 [TW-05 기록](CHANGELOG.md#tw-05-localization)을 따른다.
> 범위: TW의 언어·메뉴·공지사항과 Phase B–F·Later의 기록함·단어장·회고·레시피·데이터 이동. 공지사항은 사용자 요청으로 TW에 추가한 설계 범위이며, 후속 기록 기능의 Phase를 앞당기지 않는다.
> 관련 문서: [DESIGN](DESIGN.md), [ROADMAP](ROADMAP.md), [다국어](design-localization.md), [차 느낌](design-tea-feeling.md), [데이터 보존](data-portability.md), [단어장](sensory-vocabulary.md).

## 1. 메인은 계속 차를 우리는 화면이다

글자 크기·계층·메뉴 기준선·아이콘·조작 영역은 [공통 UI 기준](ui-guidelines.md)과 `styles/ui.css`에서 관리한다. 이 문서는 메뉴의 역할·동선과 배치 결정을 맡는다.

메인의 고정 영역은 **세션/앱 조작 → 차·다구·시간 → 출탕 → 소리·이번 차 느낌**으로 유지한다. 기록함·단어장·레시피를 위해 하단 탭이나 새 상시 아이콘 줄을 추가하지 않는다. 기능이 늘어도 기존 주요 조작의 위치가 이동하지 않게 한다.

```text
우림 끝                    [언어 아이콘 한국어 ▾] [☰ 메뉴]
                   차 한 잔의 시간
                      Time for Tea
               ‹ 차 선택 / 찻잎 미리보기 ›
                   ‹ 다구 / 남은 시간 ›
                 권장 우림 · 완료 포 기록
                        시간 조정
                 [우리기 시작 / 차 따라내기]
소리 아이콘 소리 끄기                         펜 아이콘 차 느낌
```

- 좌상단 `우림 끝`은 세션 경계를 뜻하는 텍스트 버튼으로 유지한다. 원형 화살표나 휴지통으로 대체하지 않는다.
- 우상단은 언어 선택과 `메뉴` 두 개다. 이전 제안의 `사용법 + 언어`에서 **사용법 자리를 메뉴로 대체**한다. 이 화면은 이용 안내로 이름을 바꾸어 메뉴 안으로 이동하고 설정도 메뉴에서 바로 접근한다.
- 언어는 `언어 아이콘 + 한국어/繁體 + ▾`, 메뉴는 `햄버거 아이콘 + 메뉴`다. 언어를 전역 메뉴 속에만 숨기지 않는다. 이름을 못 읽어도 언어 아이콘과 원어 선택지로 찾을 수 있게 한다.
- 기존 푸터의 소리와 차 느낌은 아이콘+문구를 유지한다. 여백이 있는 상태에서 굳이 이름을 없애지 않는다. 소리 문구는 기존 동작 라벨 `소리 켜기/끄기`와 아이콘 상태를 일치시킨다.
- 현재 포의 출탕과 다음 포는 항상 메인 주 버튼이다. 기록·공유·레시피 저장을 이 버튼에 섞지 않는다.

## 2. 전역 메뉴와 맥락 진입

**2026-08-31 사용자 확정:** 이용 안내와 설정의 우상단 상호 이동 아이콘을 제거한다. 두 페이지에는 좌상단 `← 처음으로`만 남기고 각 화면의 진입은 메인 메뉴에서 제공한다. 대체 아이콘이나 빈 버튼은 두지 않는다.

2026-08-31 사용자 검토에서 `help.html`의 상위 메뉴·페이지 제목을 **이용 안내**로 정했다. 사용법 외에 앱 설명·자유 사용·제작자 안내도 포함하므로 포괄적인 이름을 쓰고, 하위 접힘 항목 **사용법**은 유지한다. URL과 번역 키·이동 보호 동작은 바꾸지 않는다.

메뉴 안에서는 구현된 목적지만 같은 순서로 표시한다. 관련 항목이 있을 때만 그룹 간 여백을 둔다. 미구현 기능의 회색 행·잠금 아이콘·준비 중 배너를 예고용으로 보여주지 않는다.

| 기능 | 주 진입점 | 보조 진입점 / 해당 화면의 역할 |
|---|---|---|
| 이번 차 느낌 | 메인 푸터 `펜 + 차 느낌` | 현재 세션 한 장 작성. 과거 기록 목록을 이 버튼에 합치지 않음 |
| 기록함 | 메뉴 `노트 아이콘 + 기록함` | `브라우저 기록으로 남기기` 성공 후 `기록함 보기`, 개별 기록 상세·공유·삭제 |
| 감각 단어장 | 느낌 시트 태그 아래 `책 아이콘 + 단어 찾아보기` | 메뉴 `책 아이콘 + 단어장`은 독립 탐색. 안에서 감각 단어/내 단어 구분 |
| 레시피 | 메뉴 `순서 목록 아이콘 + 레시피` | 완료 기록/현재 완료 세션의 `이 우림 기억하기`로 작성, 레시피 상세에서 `이대로 준비하기` |
| 열 잔 회고 | 기록함 내부의 `지난 차 돌아보기` | 별도 메인 아이콘·탭 없음. 열 잔이 쌓였을 때 조용한 안내, 홈 배지/목표/자동 팝업 없음 |
| 공지사항 | 메뉴 `스피커 아이콘 + 공지사항` | 배포된 업데이트와 예정된 업데이트, 큰 UI 변경 뒤 기능 위치 안내 |
| 이용 안내 | 메뉴 `도움말 아이콘 + 이용 안내` | 사용법·앱 설명·제작자 연락·응원은 이 안에 유지 |
| 개인 설정 | 메뉴 `설정 아이콘 + 설정` | 언어, 차별 시간 보정, 태그 목록 편집, 설정 초기화 |
| 전체 백업·복원 | 설정의 `데이터 보관과 이동` | `백업 파일 내보내기` / `백업 파일 가져오기`. 개별 카드 공유와 구분 |
| 개별 기록 내보내기 | 기록 상세의 `공유·내보내기` | 텍스트·이미지·후속 JSON/Markdown 중 실제 지원하는 형식만 표시 |
| g·ml·실제 수온 | 느낌 시트의 접힌 `우림 정보 더 적기` | 선택 입력. 권장 수온을 실제 수온으로 자동 입력하지 않음 |
| 사용자 차 등록 | 향후 차 선택 상세의 `내 차 추가` | 메인에 새 + 버튼을 추가하거나 기본 캐러셀 조작과 혼합하지 않음 |

메뉴의 순서는 **기록함 → 단어장 → 레시피 / 공지사항 → 이용 안내 → 설정**이다. 언어는 메뉴 밖에 직접 노출하고 설정에서도 같은 선택값을 관리한다. 차 캐러셀 스와이프·개완 뚜껑·탕색·폰트·오디오 안정화에는 새 메뉴가 필요하지 않다.

레시피를 기록함 안에만 넣는 안도 검토했으나, 과거 기록을 읽는 일과 우림 전에 저장한 방식을 준비하는 일은 진입 목적이 다르므로 메뉴에서 독립 진입을 제공한다. 대신 레시피 작성은 실제 우림 기록의 맥락에서 시작한다. 레시피 선택만으로 타이머를 시작하거나 기존 초안·선호 보정을 덮어쓰지 않는다.

### 2.1 하위 화면의 2단계 메뉴 표현

- 이용 안내 안의 사용법 등 안내 항목, 설정 안의 메뉴처럼 **2단계 메뉴 행은 테두리 없이 텍스트를 가운데 정렬**한다. 항목은 선이나 카드 외곽선 대신 여백으로 구분한다.
- 아이콘이 필요한 항목도 텍스트 중심은 다른 행과 같게 유지한다. 아이콘 유무 때문에 메뉴명이 좌우로 밀리지 않도록 양쪽 공간을 대칭으로 확보한다.
- 전역 메뉴 popover의 외곽선과 왼쪽 정렬은 유지한다. 입력창·주요 실행 버튼·선택 태그와 긴 설명 본문에는 2단계 메뉴 규칙을 일괄 적용하지 않는다.
- 테두리 제거는 키보드 포커스 표시 제거를 뜻하지 않는다. 44px 이상의 조작 영역과 포커스·눌림 피드백을 유지한다.

### 2.2 공지사항 — 다음 UI 업데이트에 포함

- 이용 안내 바로 위에 `스피커 아이콘 + 공지사항`을 둔다. 소리 켜기/끄기와 구분되는 확성기 형태의 선형 스피커 아이콘을 쓰고, 공지를 여는 동작은 소리를 재생하거나 음소거를 바꾸지 않는다.
- 메뉴명 바로 오른쪽에 **공지 갱신일을 `MMDD` 위첨자**로 표시한다. 예: `공지사항⁰⁸³¹`. 붉은 점·배지 바탕 없이 작은 보조 문구로 두고, 공지를 읽어도 날짜는 남는다. 읽음 여부나 공지 개수를 뜻하지 않으며 별도 읽음 저장은 필요하지 않다.
- 기준은 배포된 공지 묶음의 `updatedOn`(`YYYY-MM-DD`)이다. 새 공지·기존 공지 수정·예정 내용 변경·삭제처럼 사용자에게 보이는 공지 내용이 바뀔 때 갱신한다. 앱 배포일·미래의 업데이트 예정일·접속일로 대체하거나 열람·언어 전환마다 갱신하지 않는다. 날짜에서 월·일을 그대로 꺼내 0을 채우며 시간대 변환으로 하루가 달라지지 않게 한다. 공지가 없거나 날짜가 유효하지 않으면 날짜만 숨긴다.
- 공지 창 제목은 `공지사항 (YYYY.MM.DD)`로 표시해 연도를 확인할 수 있게 하며, 아래에 별도의 `공지 업데이트` 문구를 반복하지 않는다. 메뉴의 접근성 설명에도 같은 전체 날짜를 제공하고 위첨자는 중복 낭독하지 않는다. 작은 날짜 자체를 별도 버튼으로 만들지 않고 메뉴 행 전체의 44px 조작 영역을 유지한다. 오프라인에서는 설치된 공지 내용과 그 갱신일을 함께 보여준다.
- **업데이트**에는 가장 최근에 배포한 묶음, **예정된 업데이트**에는 아직 적용하지 않은 계획, **지난 업데이트**에는 그 이전에 배포한 묶음을 표시한다. 세 구분은 같은 단계이며 `업데이트 → 예정된 업데이트 → 지난 업데이트` 순서다. 지난 업데이트는 하위 항목이 없으면 제목과 목록을 모두 숨긴다. 공지 제목과 날짜, 배포한 항목의 버전(있을 때), 사용자에게 달라지는 점을 간결하게 적는다. 일정 미정·변경 가능성을 숨기지 않고 예정 기능을 이미 사용할 수 있다고 안내하지 않는다. 목록은 각 그룹 안에서 최신순이다.
- `업데이트`·`예정된 업데이트`·`지난 업데이트` 구분 제목은 페이지 제목보다 조금 작은 금색으로 표시한다. 각 업데이트는 왼쪽 정렬의 접을 수 있는 불릿 목록으로 두고, 항목 제목도 현재 본문과 같은 글꼴·크기·색을 사용한다. 날짜·상태는 짧은 보조 문구, 펼친 상세 본문도 왼쪽 정렬로 둔다. 다음 UI 개편 공지에는 언어·메뉴·차 느낌의 위치와 기존 차·다구 이미지가 유지됨을 안내한다. 아직 없는 기록함 등을 다음 배포에 포함된 기능으로 섞지 않는다.
- 정적 공지 데이터의 `releases`는 실제 배포 묶음을 최신순으로 관리하고 `planned`는 별도로 둔다. 새 배포 묶음을 맨 앞에 추가하면 기존 최신 묶음은 자동으로 지난 업데이트로 분류된다. 빈 묶음은 분류에서 제외한다. `updatedOn` 수정·예정 내용 수정·날짜 경과만으로는 현재 업데이트를 과거로 옮기지 않는다. 실제 배포 없이 예정 내용을 자동으로 배포 완료로 바꾸거나 사용자 브라우저에 공지 이력을 저장하지 않는다.
- 공지는 사용자가 메뉴에서 열어 읽는다. 첫 버전은 자동 팝업·푸시·미열람 수 배지를 추가하지 않는다. 같은 문서의 읽기 전용 뷰로 열고 타이머·초안을 보존한다. **2026-08-31 사용자 결정:** 공지·메뉴·언어 선택의 눈에 보이는 우림 상태 안내와 `타이머로 돌아가기` 버튼은 제거한다. 공지는 X·Escape·배경으로, 메뉴·언어 선택은 기존 열기 버튼·Escape·바깥 클릭으로 닫으며 기존 포커스 복귀를 유지한다. 공지처럼 배경이 비활성화되는 창에는 시각적으로 숨긴 짧은 상태 알림만 유지하고, 완료가 창을 닫거나 포커스를 빼앗지 않는다. 이용 안내·설정의 기존 별도 문서 이동 보호와 실제 타이머의 완료·출탕 안내는 그대로다.
- 최초 구현은 앱과 함께 배포하는 정적 공지 데이터와 한국어·번체 문구로 구성한다. CMS·계정·별도 공지 서버를 추가하지 않는다. 공지 내용만 고칠 때도 배포가 필요하며 로컬 공지 자산은 SW 캐시에 포함한다. 오프라인에서는 설치된 앱에 포함된 공지를 보여주고 실시간 최신 정보라고 표시하지 않는다.
- 공지 문구는 개발 이력인 CHANGELOG 전체를 그대로 노출하지 않고 사용자에게 필요한 변화만 요약한다. TW-05에서 진입·읽기 구조, TW-06에서 번체 문구, TW-08에서 실제 배포 내용과 첫 공지의 일치·기존 설치 업데이트·오프라인·상태 보존을 확인한다. 예정 항목이 배포되면 예정 목록을 정리해 중복·오해를 막는다.

### 2.3 설정 화면 — 한국어 화면 검토 반영

- 주의사항을 설정 내용의 맨 위에 항상 펼쳐진 고정 구역으로 둔다. 접기 조작은 없으며 스크롤 시 화면을 가리는 고정 오버레이는 만들지 않는다.
- 바로 다음 언어 구역은 기본으로 펼쳐진 `details`로 둔다. `한국어` / `繁體中文（台灣）`를 가로형 네이티브 라디오 그룹으로 표시하고, 각 라벨의 44px 터치 영역·키보드 방향키 선택·포커스 표시를 유지한다. 선택·IME 유예·저장 실패 의미는 기존 언어 계약을 따른다.
- 시간 보정·차 느낌 단어장·데이터 초기화는 기존 순서를 유지한다. 기본 15개 전환과 기존 단어 보존은 [단어장 전환 결정](sensory-vocabulary.md#default-vocabulary)을 따른다. 단어장 탐색 기능은 이번 수정에 포함하지 않는다.

## 3. 기능 도입 단계와 사용 이력은 구분한다

| 단계 | 메인 고정 조작 | 메뉴 / 맥락 진입 |
|---|---|---|
| TW-01–03 완료 | 기존 화면 유지, 접근성과 상태 경계 안정화 | 기존 도움말/설정 동선에 이탈 보호 적용. TW-04는 보류 |
| TW-05·06 | 우상단 언어 + 메뉴 적용, 중앙/푸터 유지 | 메뉴에는 공지사항·이용 안내·설정. 언어 전환과 공지 열기는 같은 문서에서 수행 |
| Phase B: 장기 기록 구현 후 | 상시 기록 아이콘이나 숫자 배지 추가 없음 | 기록함 메뉴, 느낌 시트의 명시적 `브라우저 기록으로 남기기`, 성공 뒤 `기록함 보기` |
| Phase C: 데이터 이동 구현 후 | 변화 없음 | 설정에 백업·복원, 기록 상세에 구조화 내보내기 |
| Phase E·F 구현 후 | 변화 없음 | 단어장 메뉴·시트 맥락 진입, 기록함 안 선택적 회고 |
| Later: 레시피 구현 후 | 변화 없음 | 레시피 메뉴와 완료 기록의 작성 액션 |

- **기록함 메뉴는 기능이 구현되면 0개여도 접근 가능**하게 한다. 빈 기록함은 `아직 브라우저에 남긴 기록이 없습니다`와 타이머로 돌아가는 길만 제공하고, 목표·기록 강요·예시 사용자 데이터는 넣지 않는다.
- 앞서 검토한 `첫 저장 후에만 기록 메뉴를 노출`은 채택하지 않는다. 메뉴 안의 목적지 위치를 사용량에 따라 바꾸지 않고, 첫 저장 성공 때는 맥락 링크로 자연스럽게 발견하게 한다. 홈에 상시 기록 버튼을 추가하는 것과는 다르다.
- 단어장과 레시피도 해당 기능의 구현 여부로 노출한다. 기록 개수로 잠그지 않는다. 마지막 기록이나 레시피를 지웠다고 메뉴 자체를 없애지 않는다. 가져온 기록도 같은 위치에서 접근한다.
- 열 잔은 기록함 내부의 회고 제안 시점이다. `7/10`, 홈 개수 배지, 목표 달성 연출, 초과 기록 자동 삭제를 만들지 않는다. 회고 내용과 표본 선정은 Phase F에서 검증한다.

## 4. 아이콘과 문구를 고르는 기준

**위치를 기억하게 돕는 목적지에는 아이콘+이름, 결과를 정확히 말해야 하는 행동에는 문구, 주변 맥락만으로 의미가 분명한 작은 조작에는 아이콘만** 사용한다. 아이콘이 공간을 차지하는 만큼 실제로 찾거나 상태를 읽는 데 도움이 있어야 한다.

| 표현 | 적용 항목 | 판단 이유 / 조건 |
|---|---|---|
| 아이콘 + 메뉴명 | 언어 선택, 메뉴, 차 느낌 | 아이콘만으로 뜻이 확정되지 않고 첫 사용자가 발견해야 함 |
| 아이콘 + 메뉴명 | 기록함, 단어장, 레시피, 공지사항, 이용 안내, 설정 | 서로 다른 목적지를 훑어 찾기 쉽게 하고 뜻은 이름이 전달. 메뉴 행의 아이콘 열을 일관되게 유지 |
| 아이콘 + 문구 | 소리 켜기/끄기 | 소리 유무는 중요한 상태. 스피커/빗금과 동작 문구로 중복 전달 |
| 아이콘 + 문구 | 타이머로 돌아가기, 단어 찾아보기, 텍스트 복사, 이미지 저장, 공유·내보내기 | 돌아갈 곳이나 결과 형식이 분명해야 함. 그림만으로 복사/공유/다운로드를 추측하게 하지 않음 |
| 아이콘 + 문구 | 모바일 기기 아이콘 + 브라우저 기록으로 남기기 | 사용자 선택에 따라 스마트폰 선형 아이콘을 붙임. 저장 범위는 아이콘이 아니라 문구·안내로 설명 |
| 문구 중심 | 우리기 시작, 차 따라내기/버튼 눌러 내리기, 다음 포 우리기, 우림 끝 | 상태별로 결과가 달라짐. 재생/정지/리셋 그림보다 실제 행동을 말하는 문구가 정확. 조기 출탕은 TW-04 보류 |
| 문구 중심 | 임시저장, 이 우림 기억하기, 이대로 준비하기 | 임시 유지·레시피 작성·실행 준비의 의미를 구분. 플로피 디스크 그림으로 통일하지 않음 |
| 문구 중심 | 취소, 삭제, 초기화, 백업 가져오기, 확인 | 파괴적이거나 결과가 중요한 동작. 휴지통·체크만으로 대체하지 않음 |
| 문구 중심 | 한국어 / 繁體中文（台灣）, 태그, 감각 단어/내 단어, 설정 행 | 내용 자체가 구분 기준. 선택 체크·접힘 화살표는 보조 상태 표시 |
| 아이콘만 | 차/다구 이전·다음, 시간 −/+, 닫기 X | 조작 대상이 바로 옆에 있고 관례가 명확. 접근성 이름은 대상·동작을 구체적으로 제공 |
| 아이콘만, 맥락 한정 | 차 이름 옆 편집 펜, 개별 기록 행의 더보기 | 대상이 같은 행에 명확하고 위험한 실행을 직접 하지 않을 때만. 더보기 안의 삭제는 문구+확인 |

- 언어를 국기로 표시하지 않는다. 언어 아이콘과 원어 이름을 쓴다. 햄버거는 전역 목적지, 세 점은 특정 기록의 추가 동작으로 역할을 구분한다.
- 느낌 시트의 `임시저장`은 현재 세션 초안을 유지하고 닫는 동작이다. `임시저장은 이번 우림 동안만 유지됩니다.`를 함께 표시하며 저장 수명은 [초안 정책](design-tea-feeling.md#draft-policy)을 따른다. `브라우저 기록으로 남기기`는 별도의 명시적 장기 기록이며 Phase B에 도입한다. 브라우저 방문 기록·기기간 동기화를 의미하지 않는다.
- 실제 앱의 제어 아이콘은 기존 선형 SVG 계열로 통일한다. 이모지는 차의 표현이나 사용자 원문에 남길 수 있지만, 플랫폼마다 모습이 다른 이모지를 조작 아이콘 체계로 늘리지 않는다.
- 아이콘만 있는 모든 버튼도 실제 button과 접근성 이름을 갖는다. 예: `이전 차`, `다음 다구`, `우림 시간 1초 줄이기`, `느낌 시트 닫기`, `아리산 기록의 추가 동작`.
- 시각·유효 터치 크기를 구분한다. 아이콘은 약 18–20px로 작아도 조작 영역은 44×44px 이상이며 이웃과 겹치지 않는다. 툴팁은 보조이며 모바일에서 이름을 대체하지 않는다.
- 언어 버튼/메뉴는 펼침 상태, 소리는 눌림 상태, 언어·태그는 선택 상태를 보조기술에도 전달한다. 색 하나로만 구분하지 않는다.

### 4.1 공통 토스트 알림 — C 시안 채택 (2026-08-31)

- 사용자가 비교한 세 안 중 **C의 작은 말풍선**을 공통 토스트에 적용한다. 9px 모서리·상단 왼쪽의 작은 꼬리·얇은 갈색 금빛 테두리·불투명한 짙은 갈색 면을 사용하고, 기존 고운바탕과 밝은 본문색을 유지한다. 알약 모양·큰 그림자·이모지 장식은 사용하지 않는다.
- 문구는 **‘-습니다’체**의 짧은 문장으로 통일한다. 예: `이번 차를 마무리했습니다.`, `텍스트를 복사했습니다.`, `기기에 저장하지 못했습니다. 이번 화면에서만 적용됩니다.` 명사형 실패 메시지와 이모지를 문장으로 정리하되 실제 성공·실패 의미를 바꾸지 않는다.
- 앱 상단 조작 아래, 앱 콘텐츠 왼쪽에서 16px에 둔다. 기본 세로 위치는 상단 safe area + 58px이며 폭은 문구에 맞추고 앱 폭(최대 460px)에서 양쪽 16px을 남긴다. 긴 문구는 왼쪽 정렬로 줄바꿈하고 화면 밖으로 넘기지 않는다. 짧게 나타나는 토스트는 입력·출탕 버튼의 조작을 가로채지 않는다.
- 기존 발생 조건·표시 시간·`role="status"`·포커스 비이동을 유지한다. 설정의 지속적인 저장 실패 안내나 확인창을 일시적인 토스트로 바꾸지 않는다. 시트·카드 접근성과 초안·세션 정책은 각각 TW-02 본 작업·TW-03에 남긴다.
- TW-02 보조 UI 정리로 먼저 반영한다. 375×660·320px에서 짧은/긴 문구와 꼬리·줄바꿈·포커스 유지, 실제 세션 마감 흐름을 검증하며 이 변경만으로 TW-02 전체를 완료로 표시하지 않는다.

## 5. 열기·닫기와 진행 중 우림

### TW 범위

- 언어와 전역 메뉴는 같은 문서의 작은 popover로 열며 둘을 동시에 겹쳐 열지 않는다. 메뉴를 여는 것 자체는 타이머·초안을 바꾸지 않는다. 언어 선택·Escape로 닫으면 트리거로 포커스를 돌린다. 목적지 선택은 해당 화면으로 포커스를 넘기고, 바깥의 다른 조작을 눌러 닫았으면 그 조작의 포커스를 빼앗지 않는다.
- **메인에서 사용자가 직접 고른 언어는 우림 중에도 문구만 갱신**한다. 선택한 차·다구·시간·완료 포·태그·메모를 그대로 유지하고 완료음을 재실행하지 않는다. IME 조합 중이거나 공유용 스냅샷 생성 중에는 해당 작업을 마친 뒤 적용한다.
- 언어 선택은 다른 HTML로 이동하지 않는다. 따라서 이전의 안전 idle까지 페이지 이동을 미루는 규칙과 구분한다. 다른 탭에서 들어온 언어 변경은 기존대로 안전한 상태까지 유예해 작성 도중 예고 없이 문구를 바꾸지 않는다.
- 메뉴의 이용 안내·설정은 현재 별도 문서이므로 [이탈 보호](design-localization.md#navigation-policy)를 계속 적용한다. 이 정책 때문에 언어까지 잠그지 않는다. 메뉴를 자동으로 목적지로 이동시키거나 초안을 대신 삭제하지 않는다.
- 메뉴나 언어 popover를 열어도 타이머 완료음은 계속 동작한다. 어느 popover든 중요한 시간/출탕을 가린 상태에서 완료되면 그 안에서도 완료 상태와 `타이머로 돌아가기`를 제공한다. 이 동작은 popover를 닫고 메인 출탕 버튼에 포커스를 두며 출탕 자체를 실행하지 않는다. 자동 포커스 이동이나 기록 시트 자동 열기는 하지 않는다.

### 장기 기록·단어장 이후

- 느낌 시트에서 여는 단어장은 **같은 문서 안의 보조 뷰**다. 새로운 페이지로 떠나지 않는다. 태그·메모·입력 위치를 유지하고 `느낌으로 돌아가기`로 복귀한다. 시트 안에서 다시 시트가 무한히 쌓이지 않도록 최대 한 단계의 보조 뷰로 제한한다.
- 메뉴에서 여는 단어장과 시트에서 여는 단어장은 같은 내용을 사용하지만 돌아갈 곳이 다르다. 뒤로 가기는 항상 진입 맥락으로 복귀하고 사용자 입력을 초기화하지 않는다.
- 단어를 읽거나 상세를 여는 것만으로 태그·메모를 바꾸지 않는다. 느낌에서 들어왔을 때만 `이 단어 고르기` 같은 명시적 동작으로 선택 태그에 반영하고 느낌으로 돌아온다. 이미 선택된 단어를 중복 추가하거나 메모에 설명문을 자동 삽입하지 않는다. 단어장의 ID·개인 단어와 기존 태그의 연결은 Phase E 데이터 설계에서 확정한다.
- 기록함·레시피 같은 후속 전체 화면은 타이머 상태를 보존하는 같은 문서 내 뷰를 우선한다. 활성 세션이 있을 때는 짧은 진행 상태와 `타이머로` 복귀 액션을 화면에 유지한다. 상태 공유·접근성·완료 알림 검증 전에는 활성 세션에서 별도 문서로 보내지 않는다.
- 레시피 불러오기·다른 차 준비처럼 현재 세션을 대체하는 행동은 단순 탐색과 구분한다. 활성 세션/초안이 있으면 보호 절차를 거치고 자동 폐기하지 않는다. 선택한 레시피를 확인해 `이대로 준비하기`를 눌러도 실제 우림 시작은 메인 주 버튼에서 한다.

## 6. 검토한 대안과 보류 이유

| 대안 | 판단 |
|---|---|
| 하단에 타이머·기록·단어장·레시피 탭 4개 | 보류. 375×660의 출탕 영역을 줄이고 기록하지 않는 사용자에게 상시 목적지를 강요함 |
| 기록함 하나에 단어장·레시피·회고를 모두 숨김 | 회고만 채택. 단어 탐색·우림 준비는 기록 읽기와 목적이 다르고 저장 기록이 없어도 접근할 수 있어야 함 |
| 메인에 언어·설정·기록·단어장 아이콘만 나열 | 채택하지 않음. 슬롯이 늘어나고 그림의 뜻을 외워야 함 |
| 모든 버튼에 아이콘 추가 | 채택하지 않음. `우림 끝`과 `임시저장`처럼 문구만으로 충분한 행동은 문구를 쓴다. 브라우저 기록 저장에는 사용자 선택에 따라 모바일 아이콘을 병기 |
| 장기 기록 첫 저장 전에는 메뉴 위치 숨김 | 채택하지 않음. 홈을 늘리지 않고 메뉴 안에서 안정된 위치를 제공. 첫 저장 후 안내는 맥락 링크로 처리 |

탭은 추후 **같은 세션에서 타이머↔기록 왕복이 반복되고**, 메뉴가 실제 탐색 실패·불필요한 반복 조작을 만들며, 작은 화면에서 시간·출탕·44px 조작 영역을 지킨다는 근거가 있을 때만 재검토한다. 기능 수가 늘었다는 사실만으로 탭을 도입하지 않는다.

## 7. 검증과 구현 경계

- 375×660 및 더 좁은 320px에서 한국어·번체 상단 조작이 줄바꿈/겹침 없이 표시되는지 확인한다. 좁아져도 언어·메뉴 이름을 아이콘만으로 몰래 바꾸지 않는다. 가용 공간에 맞춰 제목/장식 간격을 먼저 줄인다.
- 타이머만 사용한 첫 방문자, 빈 기록함, 첫 명시적 저장, 기존 기록 가져오기, 마지막 기록 삭제, 열 잔 회고, 레시피 준비를 각각 확인한다. 자동 기록·사용량 잠금·홈 개수 배지가 없어야 한다.
- 키보드·스크린리더로 메뉴/언어의 열기·닫기·포커스 복귀, 느낌→단어장→느낌 복귀, 모달 밖 포커스 차단, 태그 선택과 소리 상태를 확인한다.
- 활성 우림 중 언어 변경·메뉴 열기·정상 완료·출탕, 메모 IME 입력, export 중 전환, 레시피로 교체하려는 동작에서 상태 보존을 확인한다. [TW-04 보류](DESIGN.md#early-pour-policy)에 따라 조기 완료는 이번 검증에서 제외한다.
- TW-05에 포함되는 구현은 언어 popover·전역 메뉴·공지사항 읽기와 기존 이용 안내/설정 연결이다. 기록함·장기 저장·백업·단어장·회고·레시피·선택 입력은 각각의 Phase에 남긴다.
- 이번 인터랙티브 미리보기는 배치와 진입을 검토하는 예시다. 실제 저장·타이머·번역 전체·접근성·PWA 구현 완료의 근거로 사용하지 않는다. 구체적 검증 기록은 구현 시 CHANGELOG에 구분해 남긴다.
