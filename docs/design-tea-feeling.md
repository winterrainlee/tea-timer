## 1. 기능 정의

### 1.1 한 줄 정의
차를 마시는 세션 중이나 마친 뒤, **한 잔의 감각을 자기만의 말로 한두 줄 남기는 작은 시음 카드**. 차 정보 백과도, 긴 기록장도 아니다.

### 1.2 왜 만드는가
타이머만 사용해도 제품은 완전하고 **기록하지 않은 차도 온전한 차 한 잔**이다. 혼자 마실 때나 다회에서나, 조금 더 남겨보고 싶은 사람이 원할 때만 여는 얇은 기록의 입구다. 앱이 차·다구·포수·시간을 이미 알고 있다면 다시 입력시키지 않고 사용자만 알 수 있는 감각을 선택적으로 묻는다. 열 잔은 기록 목표가 아니라 경험이 자연스럽게 쌓였을 때 회고가 의미를 갖는 발견 시점이다.

### 1.3 무엇이 아닌가
- 장기 통계, 별점, 점수화, 복잡한 맛 평가표가 아니다.
- "전문가식 향미 정답"을 맞히는 시험이 아니다.
- **앱 안에 모든 기록을 붙잡아 두는 데이터 락인(Data Lock-in) 기록장이 아니다.** 기존 차 기록 앱(`차담`, `MyTeaPal` 등)이나 개인 노트(`Notion`, `Obsidian`, `기본 메모장`)와 경쟁하지 않으며, 유저의 데이터를 종속시키지 않고 원하는 곳 어디로든 자유롭게 내보내고 이동(No Lock-in)할 수 있는 오픈 도구를 지향한다.

## 2. 목표와 비목표

### 2.1 목표
- 차 초보자가 시음노트를 "맞혀야 하는 정답"으로 느끼지 않게 한다.
- `단맛`, `꽃향`, `구운맛` 같은 기본 감각 태그와 함께 자기만의 비유를 남길 수 있게 한다.
- 전체 우림이 끝났을 때 그날의 느낌을 한 장의 이미지나 텍스트로 내보낼 수 있게 한다.
- 개인적이고 이상한 비유를 허용한다. 기억에 남고 다른 사람에게 설명하기 쉬운 표현이면 좋은 기록이다.

### 2.2 비목표
- 기록 습관의 강요. 기록하지 않아도 타이머 경험은 온전해야 한다.
- 기록 개수를 목표로 제시하지 않는다. 진행률·streak·등급·AI 취향 판정은 넣지 않는다. 누적 기록은 명시적으로 장기 저장을 선택한 사용자를 위한 후속 기능이다(§8).
- 커뮤니티·공유 기능. 카드 이미지는 사용자가 직접 공유하는 소재일 뿐, 앱이 공유 채널을 갖지 않는다.

## 3. 진입 흐름

핵심 제약: **기록 화면은 자동으로 튀어나오지 않는다.** 따르기, 표일배 배수, `다음 泡 우리기` 같은 타이머 행동과 분리하고 사용자가 원할 때만 연다.

- 진입점은 화면 우하단 푸터의 `차 느낌` 버튼이다. 음소거 버튼과 같은 선형 연필 SVG와 한국어 텍스트 레이블을 쓴다. 제작자 응원 박수는 메인에서 제거하고 `help.html`에만 둔다.
- 현재 버튼은 idle·pour·steep·done 모두에서 보인다. 첫 우림 전에도 열 수 있지만 자동 요약은 `완료된 우림 없음`으로 표시한다. 우림 중 열더라도 타이머 상태를 바꾸거나 완료 행동을 대신하지 않는다.
- 과거 설계의 `done` 한정 노출과는 다르다. 2026-08-31에 상시 노출을 유지하기로 정했다. 첫 우림 전 보호 동작은 아래 §3.1에 따라 TW-03에서 반영했다.
- 버튼을 누르면 저장하는 것이 아니라 현재 세션 요약을 갱신하고 바텀시트를 연다. 같은 세션에서 다시 열면 메모리에 둔 제목·태그·문장을 이어 쓰며 완료된 포별 시간은 최신 값으로 다시 계산한다.
- 기록 단위는 세션 전체 한 장이다. 매 포별 입력란을 만들지 않고, 포별 변화는 자유 문장과 자동 시간 요약으로 흡수한다.
- `우림 끝`이 명시적 세션 경계다. 초안이 있으면 삭제 확인 뒤 제목·태그·문장 초안과 우림 기록을 함께 지운다. 새로고침과 앱 재실행도 초안을 복원하지 않는다.
- 완료 포 또는 내용 있는 초안이 있으면 `우림 끝` 전에는 차·다구를 바꿀 수 없다. 선택 차단·종료 취소는 기록과 초안을 유지한다.

<a id="draft-policy"></a>

### 3.1 TW-03 초안·종료 정책 — 구현·로컬 검증 완료

**상시 진입 + 내용이 있는 초안의 선택 잠금 + 명시적 종료**를 채택한다. 첫 잔을 우리기 전에 차 이름이나 첫인상을 적을 수 있게 하되, 다른 차로 내용이 옮겨가거나 선택 버튼 한 번으로 사라지는 일을 막는다. 차·다구별 초안을 여러 개 보관하는 기능은 추가하지 않는다.

- `내용 있는 초안`은 사용자 지정 제목, 선택 태그 하나 이상, 공백을 제외한 메모 중 하나라도 있는 상태다. 제목 편집을 열었다가 변경 없이 닫은 것은 사용자 지정 제목으로 만들지 않는다. 판정에만 공백 검사를 쓰며 저장한 원문을 일괄 trim/정규화하지 않는다.
- 입력 중 제목·메모도 현재 초안에 포함한다. 인라인 입력과 IME 조합을 처리한 뒤 닫기·종료를 판정하고, 아직 blur되지 않은 내용이 보호에서 빠지지 않게 한다.
- 완료 포가 없고 초안도 비어 있을 때만 차·다구 변경을 허용한다. 초안이 있으면 현재 선택과 내용을 모두 유지하고 `작성한 느낌이 있습니다. 차나 다구는 [우림 끝]을 누른 뒤 바꿀 수 있습니다.`라고 안내한다. 선택 시 자동 삭제 확인창이나 초안 이동은 만들지 않는다.
- `pour`·`steep`·`draining`과 다구 이미지 전환 중 선택 제한은 유지한다. 변경이 허용된 다구도 준비 실패·취소 시 기존 선택·초안을 바꾸지 않는다.
- `우림 끝`은 세션을 폐기하고 1포·idle로 돌아가는 동작이다. 초안이 있으면 `느낌을 지우고 우림을 끝냅니다. 내보내지 않은 내용은 사라집니다.`와 `취소` / `느낌 지우고 끝내기`를 표시하고 기본 포커스는 취소에 둔다. 취소·Escape는 선택·기록·초안·타이머를 유지한다.
- 초안이 없으면 `우림 끝`의 기존 즉시 종료를 유지한다. 진행 중 포는 완료로 기록하지 않고 예정된 음·콜백을 무효화한다. 종료는 저장된 차·다구·시간 보정·음소거·태그 목록·언어를 삭제하지 않는다.
- 닫기 버튼·배경·Escape와 `임시저장`은 입력을 현재 세션 메모리에 유지하고 시트만 닫는다. 2026-08-31 사용자 검토에 따라 버튼명은 `내용 유지하고 닫기` 대신 `임시저장`으로 정한다. `임시저장은 이번 우림 동안만 유지됩니다.`를 버튼 근처에 표시하고, 새로고침·앱 종료 뒤 복원되지 않으며 오래 남기려면 텍스트나 이미지로 내보내야 함을 안내한다. 시트를 다시 열면 최신 완료 포와 기존 초안을 함께 표시한다.
- 복사·이미지 공유의 성공·취소·실패는 초안을 지우거나 세션을 끝내지 않는다. 내보냈더라도 이후 삭제 확인을 생략하지 않는다.
- 메모리 수명은 그대로다. 앱 종료·새로고침·재실행 복구나 IndexedDB 저장은 추가하지 않는다. 앱 내부 도움말/설정 이동 보호는 [언어·이동 정책](design-localization.md#navigation-policy)을 따르며, 브라우저·OS가 종료한 페이지의 복원을 보장하지 않는다.

**TW-03 구현 경계(2026-08-31):** 삭제 확인은 TW-02의 모달 규칙을 재사용하고 취소를 기본 포커스로 둔다. 확인을 기다리는 동안 타이머는 계속되며 승인한 시점의 세션만 한 번 종료한다. 다구 자산 준비가 끝나기 전 새 초안이 생기면 선택 변경을 취소한다. 종료 시 프레임·출탕 콜백과 대기 중 오디오/Wake Lock 요청을 무효화해 늦은 완료 신호가 새 세션에 들어오지 않도록 한다. 안내·확인 본문은 공통 알림과 같은 ‘-습니다’체다.

**기록 표현:** 완료된 포가 0이면 시트·텍스트·카드 미리보기·PNG 모두 `완료된 우림 없음`으로 표시한다. 첫 우림 전뿐 아니라 첫 포 진행 중에도 같다. 0을 1로 바꾸거나 진행 중 포의 예정 시간을 완료 기록에 넣지 않는다. 0포 카드 export는 허용한다. TW-04는 보류했으며 조기 출탕 시간 표시는 이번 범위에 포함하지 않는다. 이전 시간 규칙은 [보류 결정·설계](DESIGN.md#early-pour-policy)에 보존한다.

**통과 시나리오:** 첫 우림 전 제목/태그/메모를 각각 작성 → 차·다구 변경 차단 → 종료 취소로 원상 유지 → 시트 재진입 → 명시적 종료 후 선택 가능. 내용이 없는 경우 선택은 즉시 가능해야 한다. 0포·첫 포 진행 중·1포 완료 후의 네 출력 경로, 공유 취소 후 초안, 인라인 제목/IME 입력 중 닫기와 종료도 확인한다.

<a id="modal-accessibility"></a>

### 3.2 TW-02 시트·카드 접근성 계약 (2026-08-31)

- 시트와 카드 내부 영역은 각각 제목이 연결된 dialog다. 닫힌 레이어는 `hidden`·`inert`로 탭 순서와 접근성 트리에서 제외한다. 열린 최상위 창만 활성화하고, 메인과 아래쪽 시트는 `inert`로 조작을 막는다.
- 첫 포커스는 각 창의 닫기 버튼이다. Tab/Shift+Tab은 최상위 창 안에서 순환하고 동적으로 생기는 제목 입력도 포함한다. 닫으면 실제 진입 버튼으로 복귀한다. 카드의 별도 닫기 버튼·바깥 배경·Escape는 공유 없이 카드만 닫고 `카드 이미지 저장` 버튼으로 돌아간다. 다음 Escape는 느낌 시트를 닫는다.
- 제목 편집은 현재 원문을 직접 읽고 확정 처리를 한 번만 한다. Enter로 확정하면 편집 버튼으로 돌아가며, Escape로 시트를 닫을 때도 작성한 제목·메모·태그를 유지한다. 빈 제목만 기본 이름으로 표시하고 사용자 원문 공백·이모지는 정규화하지 않는다. IME 조합 중 Enter/Escape는 조합에 맡기고, 버튼으로 요청한 닫기·카드 열기는 조합 완료 후 처리한다.
- 닫기·제목 편집·태그·공유 조작은 최소 44×44px이며 태그의 선택 상태를 `aria-pressed`로 전달한다. 제목·메모 입력에 접근성 이름과 뚜렷한 포커스를 제공한다. 긴 입력·태그로 창이 길어져도 내부 스크롤로 모든 조작에 접근할 수 있다.
- 배경 비활성화는 타이머 정지를 뜻하지 않는다. **2026-08-31 사용자 화면 검토 후 조정:** 느낌 작성 시트와 카드 미리보기에서는 타이머 안내 문단·`타이머로 돌아가기` 버튼을 표시하지 않는다. 우림 이력은 자동 요약에서 확인하고 우상단 X·Escape로 닫는다. 카드 X는 카드만 닫고 작성 시트로, 시트 X는 메인 느낌 진입 버튼으로 포커스를 돌려준다. 초안·타이머를 유지하며 출탕 자체를 실행하지 않는다. 최상위 창의 시각적으로 숨긴 스크린리더 상태 영역으로 우림 진행·완료를 알리되, 완료가 창을 닫거나 포커스를 빼앗지 않는다. 공지·종료 확인의 상태 안내는 기존대로 유지한다.
- TW-02는 접근성과 입력 보존만 다뤘다. 이후 TW-03에서 임시저장·삭제 확인·선택 잠금·완료 0포 표현을 §3.1대로 반영했다. Canvas 크기·공유 포맷은 그대로다.

## 4. 입력 및 UI 설계

현재 입력은 자동 요약 위에 태그·자유 문장을 얹는 구조다. 모든 입력은 선택 사항이며 순서 강제가 없다. 향후에도 `자동 정보 → 한 번 탭하는 태그 → 원하는 사람만 쓰는 메모·측정값`의 점진적 구조를 유지한다.

**작성 시트 상단 여백 조정(2026-08-31):** 기존의 하단 부착·최대 88dvh 높이와 상단 패딩 20px, 장식 손잡이 및 아래 여백 20px가 중첩되어 제목 위 공간이 커졌다. 바텀시트 표현 외에 넓은 공백을 유지할 별도 근거는 없고 손잡이의 드래그 동작도 구현하지 않았다. 손잡이를 제거하고 상단 패딩은 12px, 제목 행 아래 간격은 8px로 줄인다. 시트 높이 상한은 화면 위쪽에 최소 16px 또는 기기 안전 영역을 남기는 정도로 늘리되, 짧은 내용은 필요한 높이만 사용한다. X의 44px 영역과 내부 스크롤·입력/포커스 보호는 유지한다. 내보내는 PNG와 TW-07 A안의 카드 조판은 이번 작성 화면 수정과 구분한다.

### 4.1 상단 세션 자동 요약 & 차 이름 수정 (✏️)
- 차 이름, 도구, 날짜, 완료 포 수, 포별 타이머 실행 시간이 상단 카드로 자동 렌더링된다. 실제로 마셨는지나 물리적 우림 시간을 측정하는 것은 아니다.
- 기본적으로 세션 프리셋(예: 청향 우롱)이 노출되지만, 요약 헤더 우측의 **연필 아이콘(✏️)**을 클릭하여 `2024 대만 아리산 청향 우롱`처럼 차/도구 이름을 자유롭게 인라인 수정할 수 있다.
- **차종 상징 이모지 2계열 분류**: 시각적 조잡함을 피하고 절제된 미학을 위해 차종 이모지는 2계열로만 심플하게 나눈다: `🍃` 청차계 (녹차, 말차, 백차, 황차, 청향 우롱, 포종, 봉황단총, 보이 생차) vs `🍂` 농차/숙차계 (농향 우롱, 무이암차[대홍포·육계·수선], 동방미인, 호지차, 홍차, 흑차/보이 숙차).

### 4.2 오늘 떠오른 단어 (감각 태그)
- 타이틀: **`오늘 떠오른 단어`**
- 현재 기본 목록은 [한국어 기본 15개 확정 목록](sensory-vocabulary.md#default-vocabulary)의 향 5개·맛 5개·입안 감각 5개다. 태그 설정이 없거나 명시적으로 기본 복원을 선택하면 적용하며, 이미 저장된 목록·이전 14개 ID·원문·빈 목록은 그대로 유지한다.
- 기본 목록 밖의 세부 표현을 단어장에서 찾아 추가하는 동작은 Phase E에 남긴다. 구운 향은 향에 두며 입안 감각에는 텁텁함을 채택했다. 새 분류를 이유로 기존 기록의 구운맛 등이나 사용자의 자유 표현을 자동 교정하지 않는다.

- **2026-08-31 칩 여백 조정:** 작성 시트의 단어 칩은 설정 단어장과 같은 한 줄 배경 높이 32px·글자 .85rem/20px·좌우 여백 8px로 맞춘다. 실제 버튼은 최소 44px를 유지하고 배경만 위아래 6px씩 안으로 그린다. 배경을 줄인 뒤 행 간격이 과해지지 않도록 추가 세로 gap은 0으로 한다(한 줄 칩 배경 사이는 12px). 가로 gap은 기존 6.4px를 유지한다. `+ 단어 추가`의 점선 배경도 같은 높이를 쓰며, 긴 원문은 여러 줄로 늘어나고 선택 색·글로우·포커스와 원문/저장 동작은 유지한다. 버튼 영역을 겹치거나 터치 영역을 줄여 간격을 맞추지 않는다. 설정 화면 자체와 내보내는 PNG의 칩 배치는 이번 수정에서 바꾸지 않는다.

#### 작성 중 새 단어 추가 — 2026-08-31 구현 계약

- 태그 끝의 `+ 단어 추가`로 같은 시트 안에 입력창을 연다. 추가하면 이번 카드에 즉시 선택하고 설정과 같은 `tagItems` 목록에 저장한다. 우림 종료는 카드 선택·미확정 입력만 비우며 저장한 단어는 남긴다.
- 설정과 같은 10자 입력 제한을 사용한다. 새 입력의 바깥 공백과 맨 앞 표시용 `#` 하나를 제거한 뒤 바깥 공백을 정리한다. 내부 공백·사용자 표현과 기존 저장 원문은 바꾸지 않는다. 같은 custom 원문은 재사용해 한 번만 선택하고, 표시 이름이 같은 builtin과 custom은 별개로 유지한다.
- 추가 직전 최신 설정을 읽어 병합한다. 다른 탭에서 이미 저장한 단어·빈 목록·알 수 없는 필드를 보존한다. localStorage의 동시 쓰기 원자성까지 보장하지는 않는다.
- 설정의 추가도 같은 저장 경계를 사용한다. 설정에서 삭제 저장에 실패하면 해당 단어를 목록에 남겨 명시적으로 재시도하게 한다. 실패한 과거 목록을 나중의 추가 때 덮어써 다른 탭의 새 단어를 잃지 않도록 한다.
- 저장 실패·손상 데이터 보호 시 성공으로 처리하거나 이번 카드에만 몰래 추가하지 않는다. 입력을 유지하고 인라인 오류를 표시해 재시도하게 한다. 손상된 목록의 복원은 설정의 명시적 복원 동작에 맡긴다.
- 미확정 단어 입력도 초안 보호 대상이다. 시트를 닫았다 열어도 유지하고, 입력창의 취소/Escape만 미확정 입력을 지운다. IME 조합 중 Enter는 추가하지 않고 조합 중 버튼 동작은 최종 입력 뒤 처리한다.
- 다른 탭의 목록 변경은 선택 중인 카드 단어·제목·메모·미확정 입력과 우림을 건드리지 않는다. 새 단어 추가 성공 후 해당 선택 칩에 포커스를 둔다.
- 범위는 직접 입력과 공통 설정 저장이다. 참고용 단어장 탐색, 언어별 기본 단어 재설계, TW-07 카드 배치 변경은 포함하지 않는다. 검증은 저장 실패/재시도·중복·기존 데이터·IME·초안·타이머·375/320px·텍스트 및 실제 PNG를 포함한다.

### 5.1 구성
- 텍스트와 실제 PNG는 완료 포별 시간을 포함한다. 카드에는 제목·도구·날짜·완료 포 수·선택 태그·문장도 담는다. 이전의 `카드에는 포별 시간을 넣지 않는다`는 설명은 현재 코드와 달라 정정했다. TW-03에서 DOM 미리보기·텍스트·PNG의 완료 포 수를 맞췄다. 첫 포가 완료되면 열린 시트·카드도 입력을 건드리지 않고 완료 정보를 갱신한다.
- 긴 제목·태그·포 기록·메모의 카드 표시 범위와 줄바꿈은 TW-07에서 검증한다. 고정 크기 카드에 원문 전체가 들어가지 않으면 표시용으로만 생략 부호를 쓰고 원문과 전체 텍스트 export를 훼손하지 않는다.

#### TW-07 카드 배치 — A안(균형형) 확정·구현 대기

**2026-08-31 사용자 확정:** 세 가지 카드 배치 시안 중 **A안(균형형)**을 채택한다. 아래 배치 방향과 표시 한도는 TW-07 구현 기준이며, 실제 앱 적용·검증 완료를 뜻하지 않는다. 카드 크기는 680×900으로 유지한다.

| 영역 | 확정 표시 한도 |
|---|---|
| 차 이름 | 최대 2줄. 초과하면 마지막에 `…` |

| 포별 시간 | 첫 포부터 순서대로 최대 2줄. 초과하면 `외 3포`처럼 생략한 포 수 표시 |

- **배치 방향:** 위에서부터 `TIME FOR TEA → 차 이름 → 다구·완료 포 수 → 포별 시간 → 단어 → 메모 → 날짜·앱 이름` 순서로 놓는다. 제목·요약·포별 시간·단어는 가운데 정렬하고, 메모는 은은한 어두운 바탕과 왼쪽 금색 선으로 구분한 영역 안에 왼쪽 정렬한다. 날짜는 하단 왼쪽, 앱 이름은 하단 오른쪽에 둔다.
- 어두운 갈색 배경과 얇은 금색 이중 테두리, 기존 서체 분위기를 유지한다. 단어와 메모에 균형 있게 공간을 배분하고 어느 한 영역이 다른 영역을 밀어내지 않게 한다. 번체·한국어 혼합 글꼴은 [글꼴 계약](design-localization.md#font-policy)을 따른다. 세부 여백·글자 크기는 실제 렌더에서 조정하되 확정한 순서와 표시 한도를 지킨다.
- 태그는 개수 대신 실제 너비로 행을 구성한다. 긴 태그는 다음 행으로 넘기고, 하나의 태그가 카드 너비를 넘으면 그 표시만 생략한다. 원문은 바꾸지 않는다.
- 줄 수는 최대치이며 짧은 내용을 억지로 채우지 않는다. 내용이 많다고 글자를 계속 축소하지 않고, 포별 시간·단어가 메모 공간을 모두 차지하지 않게 한다. 내용이 적으면 여백을 살린다. 생략 부호와 생략 개수 안내도 각 영역의 한도 안에 포함한다.
- **원문 보존:** 줄바꿈·생략은 카드 미리보기와 PNG의 표시 처리에만 적용한다. 차 이름·포별 기록·선택 단어·메모의 저장 원문, 설정의 단어 목록, 전체 텍스트 export를 자르거나 덮어쓰지 않는다. 카드에서 생략된 내용도 편집과 전체 텍스트 출력에는 그대로 남는다.
- 미리보기와 실제 PNG는 같은 내용·줄바꿈·생략 범위를 보여준다. 생략 안내도 언어별 UI 문구로 제공한다. TW-07에서 짧은 기록·단어가 많은 기록·긴 제목과 메모가 있는 기록, 번체·한국어 혼합 입력으로 실제 화면과 PNG를 확인한다.

### 5.2 두 가지 출력

- **태그 텍스트 처리(2026-08-31 사용자 확인):** 일반 텍스트 복사는 SNS 해시태그 전용 출력이 아니다. 현재처럼 표시 이름 앞에 `#`을 붙이고 항목 사이를 공백으로 연결한다. `달콤한 향`은 `#달콤한 향`으로 출력하며 내부 공백을 제거하거나 따옴표·밑줄로 변환하지 않는다. 화면·카드의 `#` 표기도 유지한다. 다른 앱에서 하나의 해시태그로 인식되는지는 보장하지 않는다.
- 표시용 `#`을 데이터에 추가 저장하지 않는다. 기본 태그는 ID, 사용자 단어는 원문으로 보존하는 [태그 계약](design-localization.md#tag-compatibility)을 유지한다. 사용자 원문에 이미 포함된 기호도 임의로 삭제하지 않는다. 후속 공개 스키마에서도 구조화한 태그와 표시 문자열을 구분하며, 이번에는 스키마·출력 코드·저장값을 바꾸지 않는다.

| 형식 | 용도 | 현재 방식 |
|---|---|---|
| 카드 이미지 | 공유용 | 680×900 canvas 렌더 → PNG Blob·File. Web Share API가 파일 공유를 지원하면 공유 시트, 아니면 object URL 다운로드 |
| 텍스트 | 개인 메모 앱 붙여넣기용 | 클립보드 복사. `차담`, `Notion`, `Obsidian`, `기본 메모장` 등 사용자가 이미 쓰는 어떤 앱에 붙여넣어도 깔끔한 오픈 텍스트(Plain Text) 형태 |

- 빌드 없는 단일 `index.html` 원칙을 지키기 위해 이미지 생성 라이브러리를 들이지 않고 canvas에 직접 렌더한다.
- 현재 텍스트 export 예시:
  ```text
  [차 한 잔의 시간 시음 노트]
  🍃 청향 우롱 · 개완
  📅 2026.07.28 (3포 우림)
  ⏱️ 1포 20초 / 2포 25초 / 3포 30초
  🏷️ #단맛 #꽃향
  💬 "흰 쌀밥을 오래 씹은 듯 고소하고 달다."
  ```

### 5.3 구조화 데이터 · 미구현

현재 Plain Text/PNG는 빠른 공유용이다. 장기 보관과 도구 간 이동에는 Tea Session JSON·Markdown, 전체 사용자 자산 JSON 백업/복원을 추가하는 방향을 검토한다. 공개 스키마와 import는 [data-portability.md](data-portability.md)의 단계에 맞춰 별도로 구현한다.

## 6. 상태와 데이터 저장

### 6.1 현재 구현: 세션 초안과 선호 태그

- `customTitle`, `sessionDraftTags`, `sessionDraftNote`는 JavaScript 메모리에만 둔다. 시트를 닫거나 `임시저장`을 눌러도 현재 페이지와 세션 안에서는 유지되지만 새로고침·앱 재실행·`우림 끝` 뒤에는 사라진다.
- `임시저장`은 현재 입력값을 세션 초안 변수에 반영하고 시트를 닫는다. 영구 저장은 하지 않는다.
- 사용자가 설정 페이지에서 편집한 감각 태그 목록은 `teaTimer.preferences.v1.customTags`에 저장한다.
- TW-01에서 메인·설정의 필드별 저장을 공통화해 `customTags`와 빈 목록을 보존한다. 상세는 [설정 보존 계약](data-portability.md#preferences-contract)을 따른다.
- 사용자 기록의 영구 보관은 현재 텍스트 복사와 PNG 공유·다운로드가 담당한다.

### 6.2 확장 방향: 초안 보호와 명시적 장기 저장 · 미구현

핵심 원칙은 **타이머 사용 ≠ 기록 의사**다.

- 타이머만 사용한 세션은 자동으로 장기 기록에 쌓지 않는다.
- 사용자가 태그나 메모를 쓰기 시작했다면 작성 중 내용을 보호한다. 현재 메모리 초안에 더해 입력 중 자동 보존, 페이지 이탈·재실행 복원, 종료·삭제 경계를 정해야 한다. IndexedDB 임시 store를 사용할지는 아직 미확정이다.
- 느낌 시트의 `모바일 기기 아이콘 + 브라우저 기록으로 남기기`로 Tea Session을 확정한다. 현재 브라우저의 앱 기록 저장소에 남기는 의미이며 방문 기록에 추가하거나 다른 브라우저·기기로 자동 동기화하는 동작이 아니다. 문구와 위치는 [배치 설계](design-navigation.md)로 결정했고, 저장 실패·수정 처리와 저장소 구현은 Phase B에 남긴다.
- 장기 사용자 자산은 IndexedDB의 `sessions`, `vocabulary`, 이후 `recipes`를 기본 후보로 삼고 가벼운 설정과 분리한다. 이 모델과 화면은 아직 구현하지 않았다.
- 세션의 차·다구 ID, 사용자 표시 이름, 완료 포별 시간, 태그·메모, 선택 측정값을 보존한다. 표시 문자열·UI 인덱스가 아닌 안정된 ID와 사용자 원문을 기준으로 설계한다.
- 저장하지 않고 현재 텍스트/PNG로 export만 하는 경로도 계속 허용한다. 기록 저장 실패가 타이머를 막아서는 안 된다.

### 6.3 보관·삭제와 백업

- 기존 `teaTimer.cups.v1` 최근 10장·초과분 자동 삭제안은 현행 계획에서 제외한다. 실제 구현된 데이터가 없으므로 여기서 수행할 데이터 마이그레이션도 없다.
- 10은 회고가 시작되는 시점이지 보관 상한이 아니다. 보관량·삭제 동의·용량 부족 처리는 별도로 결정하며 무제한 보관을 보장한다는 뜻도 아니다.
- 장기 세션과 개인 단어장, 현재 커스텀 태그는 백업해야 할 사용자 자산이다. 기본 태그와 앱 프리셋은 재생성 가능한 앱 자산으로 구분한다.
- 설정 초기화와 기록 삭제의 범위, 초안 수명, 백업·복원은 [data-portability.md](data-portability.md)에 맞춰 결정한다. IndexedDB만을 최종 보관 포맷으로 삼지 않는다.

## 8. 선택형 확장: `[차 열 잔의 기록]`

- 열 잔은 목표가 아니다. 명시적으로 남긴 기록이 어느새 쌓였을 때 회고가 의미 있어지는 발견 시점이다.
- [배치 설계](design-navigation.md)에 따라 기록함 기능 도입 후에는 빈 상태에서도 메뉴로 접근한다. 첫 명시적 저장 성공 뒤에는 `기록함 보기` 링크, 열 잔 이후에는 기록함 내부의 조용한 `지난 차 돌아보기`를 제공한다. 아직 구현하지 않았고 회고 내용·구체적 연출은 Phase F에서 검증한다.
- 홈의 찻잔 아이콘·개수 배지와 설정 토글 전용 노출안은 채택하지 않는다. 기본 타이머를 쓰는 사용자에게 기록 목표나 상시 추가 조작을 강요하지 않는 원칙은 유지한다.
- `7/10`, 진행률, `3잔 남았어요`, streak는 쓰지 않는다.
- 자주 고른 감각어·다구, 첫 기록과 최근 표현, 새로 등장한 개인 단어와 문장을 보여준다. `열 잔 중 여섯 잔에서 꽃향을 골랐어요` 같은 사실만 제시한다.
- 취향 점수나 `당신은 Floral Lover입니다` 같은 판정은 하지 않는다. 앱은 해석자보다 거울에 가깝게 남는다.
- 회고 화면의 범위와 데이터 보관·삭제 정책은 별개다. 열 장을 넘었다는 이유로 기존 기록을 버리지 않는다.

## 9. 개인 단어장·레시피와의 관계 · 미구현

- 시음 기록은 당시의 경험, 개인 단어장은 경험을 통해 사용자가 얻은 감각 기준점을 남긴다. `꽃향`에서 `비 온 뒤 돈나무꽃`처럼 자기 표현으로 깊어지는 것을 돕는다.
- 개인 단어는 기본 단어와 분리해 원문을 보존하고 시음 기록과 함께 백업한다. 세부 정보 구조는 [sensory-vocabulary.md](sensory-vocabulary.md)를 따른다.
- 레시피북은 맛있었던 포별 우림 순서를 다음에 불러오는 후속 실험이다. 재고·구매 관리나 기록 수에 따른 등급이 아니다.
- 기존 `[차 백 잔의 창고]`는 현행 단계별 계획에서 제외한다. 백 잔이나 50잔을 확장 기능의 확정 해금 조건으로 삼지 않는다.

## 10. 열린 질문

- 설정 초기화와 장기 기록 삭제를 분리할지, 초안·세션·개인 단어별 삭제·백업 범위를 어떻게 안내할지.
- 초안 보호에 쓸 로컬 저장소와 복원 시점, 페이지 이탈·재실행·우림 끝의 수명을 어떻게 정할지. 메모리만 쓰는 현재 동작과 향후 자동 보호 원칙을 구분한다.
- 장기 저장의 확인·실패·수정 처리와 열 잔 이후 회고 안내의 강도. `브라우저 기록으로 남기기`는 느낌 시트, 기록함은 메뉴, 회고는 기록함 내부로 [진입 위치를 결정](design-navigation.md)했으며 구체적 화면은 각 Phase에서 검증한다.
- 장기 기록의 보관량·용량 부족·삭제 정책. 10장 제한이나 무제한 보관을 전제하지 않는다.
- 확정한 기본 15종이 실제 사용에서 구분하기 쉬운지 확인. 특히 텁텁함·떫음·깔끔함의 설명은 후속 단어장 탐색 구현에서 검토한다.
- 현재 680×900 카드 비율이 메신저·SNS·사진 저장에서 충분한지 실사용으로 확인.
- 노트 버튼 노출과 첫 우림 전 선택 변경 정책은 §3.1에서 결정했다. 메모리 초안의 장기 자동 보호 방식은 여전히 후속 설계다.

## 12. `help.html` (사용법) & `settings.html` (개인 설정) 2원화 명세

아래는 현재 구현 동선이다. TW-05 이후에는 [배치 설계](design-navigation.md)에 따라 메인 우상단의 언어 선택·메뉴와 메뉴 안 사용법·설정으로 바꾸며, 별도 문서 이동의 세션 보호는 유지한다. 서브 페이지의 목적지 링크도 아이콘+이름을 기본으로 검토한다.

1. **`help.html` (사용법 전용 페이지)**:
   - 좌상단: `← 처음으로` (index.html 메인으로 이동)
   - 우상단: `⚙️` (settings.html 설정 페이지로 이동)
   - 내용: 5단계 가이드 (`차/다구 고르기`, `시간 맞추기 & 우리기`, `다음 泡 우리기 & 표일배 배수`, `차 느낌 남기기`, `우림 끝내기`), 자유롭게 쓰세요(오프라인/오픈소스), 제작자 이야기 & 👏 응원 박수
2. **`settings.html` (개인 설정 전용 페이지)**:
   - 좌상단: `← 처음으로` (index.html 메인으로 이동)
   - 우상단: `ⓘ` (help.html 사용법 페이지로 이동)
   - 내용:
     - 7종 차별 권장/보정 시간 관리 (- / + 조작 및 차별 기본값 복원)
     - 차 느낌 단어장 (새 단어 추가 / ✕ 삭제 / 기본 15종 복원)
     - 기억한 설정 지우기 (현재 선호 설정·커스텀 태그 초기화. 향후 장기 기록 삭제 범위는 별도 설계)
3. **네비게이션 규칙**:
   - 메인 화면(`index.html`) 상단 우측 메뉴 `사용법` ➔ `help.html`로 연결.
   - 서브 페이지들(`help.html`, `settings.html`)의 메인 복귀 버튼 텍스트는 **`← 처음으로`**로 통일.

## 13. 차 느낌 기능에 적용하는 디자인 원칙

전체 화면 레이아웃, 여백, 가장 작은 모바일 화면 검증 기준은 `DESIGN.md` §§1.3, 3, 8, 12를 따른다. 이 문서에는 기록 기능에 특화된 원칙만 남긴다.

1. **정답을 요구하지 않는 언어**: `오늘 떠오른 단어`, `조금 더 자세히 적는다면`처럼 어떤 경험도 기록이 될 수 있다는 허용의 톤을 쓴다.
2. **데이터 락인 배제**: 회원가입과 중앙 사용자 DB를 전제로 하지 않는다. 현재 일반 텍스트·PNG는 빠른 공유용이고 향후 사용자 자산의 장기 보관·이동은 JSON·Markdown·공개 스키마로 보강한다.
3. **조밀하지만 안전한 태그**: 4px 모서리의 소프트 면 배지로 정보 밀도를 유지하되 유효 터치 영역과 키보드 포커스 표시는 접근성 기준을 충족한다.
4. **세션 흐름 우선**: 기록 시트는 자동으로 열리지 않고 출탕·다음 포·우림 종료를 대신하지 않는다.
5. **가변 콘텐츠 균형**: 카드의 선택 태그는 개수에 따라 줄별로 균등 분배해 어떤 조합에서도 중심과 여백을 유지한다.
