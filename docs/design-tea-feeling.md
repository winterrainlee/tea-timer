## 1. 기능 정의

### 1.1 한 줄 정의
차를 마시는 세션 중이나 마친 뒤, **한 잔의 감각을 자기만의 말로 한두 줄 남기는 작은 시음 카드**. 차 정보 백과도, 긴 기록장도 아니다.

### 1.2 왜 만드는가
타이머만 사용해도 제품은 완전하고 **기록하지 않은 차도 온전한 차 한 잔**이다. 혼자 마실 때나 다회에서나, 조금 더 남겨보고 싶은 사람이 원할 때만 여는 얇은 기록의 입구다. 앱이 차·다구·포수·시간을 이미 알고 있다면 다시 입력시키지 않고 사용자만 알 수 있는 감각을 선택적으로 묻는다. 열 잔은 기록 목표가 아니라 경험이 자연스럽게 쌓였을 때 회고가 의미를 갖는 발견 시점이다.

### 1.3 무엇이 아닌가
- 장기 통계, 별점, 점수화, 복잡한 맛 평가표가 아니다.
- "전문가식 향미 정답"을 맞히는 시험이 아니다.
- **앱 안에 모든 기록을 붙잡아 두는 데이터 락인(Data Lock-in) 기록장이 아니다.** 기존 차 기록 앱(`차담`, `MyTeaPal` 등)이나 개인 노트(`Notion`, `Obsidian`, `기본 메모장`)와 경쟁하지 않으며, 유저의 데이터를 종속시키지 않고 원하는 곳 어디로든 자유롭게 내보내고 이동(No Lock-in)할 수 있는 오픈 도구를 지향한다.

## 2. 목표와 비목표

### 2.1 목표
- 차 초보자가 시음노트를 "맞혀야 하는 정답"으로 느끼지 않게 한다.
- `단맛`, `꽃향`, `구운맛` 같은 기본 감각 태그와 함께 자기만의 비유를 남길 수 있게 한다.
- 전체 우림이 끝났을 때 그날의 느낌을 한 장의 이미지나 텍스트로 내보낼 수 있게 한다.
- 개인적이고 이상한 비유를 허용한다. 기억에 남고 다른 사람에게 설명하기 쉬운 표현이면 좋은 기록이다.

### 2.2 비목표
- 기록 습관의 강요. 기록하지 않아도 타이머 경험은 온전해야 한다.
- 기록 개수를 목표로 제시하지 않는다. 진행률·streak·등급·AI 취향 판정은 넣지 않는다. 누적 기록은 명시적으로 장기 저장을 선택한 사용자를 위한 후속 기능이다(§8).
- 커뮤니티·공유 기능. 카드 이미지는 사용자가 직접 공유하는 소재일 뿐, 앱이 공유 채널을 갖지 않는다.

## 3. 진입 흐름

핵심 제약: **기록 화면은 자동으로 튀어나오지 않는다.** 따르기, 표일배 배수, `다음 泡 우리기` 같은 타이머 행동과 분리하고 사용자가 원할 때만 연다.

- 진입점은 화면 우하단 푸터의 `차 느낌` 버튼이다. 음소거 버튼과 같은 선형 연필 SVG와 한국어 텍스트 레이블을 쓴다. 제작자 응원 박수는 메인에서 제거하고 `help.html`에만 둔다.
- 현재 버튼은 idle·pour·steep·done 모두에서 보인다. 첫 우림 전에도 열 수 있지만 자동 요약은 `우림 완료 기록 없음`으로 표시한다. 우림 중 열더라도 타이머 상태를 바꾸거나 완료 행동을 대신하지 않는다.
- 과거 설계의 `done` 한정 노출과는 다르다. 상시 노출을 유지할지 완료된 포가 있을 때만 보일지는 열린 결정이며, 이 문서는 현재 구현을 완료된 제품 결정으로 간주하지 않는다.
- 버튼을 누르면 저장하는 것이 아니라 현재 세션 요약을 갱신하고 바텀시트를 연다. 같은 세션에서 다시 열면 메모리에 둔 제목·태그·문장을 이어 쓰며 완료된 포별 시간은 최신 값으로 다시 계산한다.
- 기록 단위는 세션 전체 한 장이다. 매 포별 입력란을 만들지 않고, 포별 변화는 자유 문장과 자동 시간 요약으로 흡수한다.
- `우림 끝`이 명시적 세션 경계다. 누르면 제목·태그·문장 초안과 우림 기록이 함께 사라진다. 새로고침과 앱 재실행도 초안을 복원하지 않는다.
- 1포 이상 완료하면 세션 잠금 때문에 `우림 끝` 전에는 차·다구를 바꿀 수 없다. 첫 우림 전 차·다구 변경 시 이미 작성한 초안을 어떻게 다룰지는 현재 구현이 명확히 처리하지 않으므로 `ROADMAP.md`의 안정화 항목으로 남긴다.

## 4. 입력 및 UI 설계

현재 입력은 자동 요약 위에 태그·자유 문장을 얹는 구조다. 모든 입력은 선택 사항이며 순서 강제가 없다. 향후에도 `자동 정보 → 한 번 탭하는 태그 → 원하는 사람만 쓰는 메모·측정값`의 점진적 구조를 유지한다.

### 4.1 상단 세션 자동 요약 & 차 이름 수정 (✏️)
- 차 이름, 도구, 날짜, 완료 포 수, 포별 타이머 실행 시간이 상단 카드로 자동 렌더링된다. 실제로 마셨는지나 물리적 우림 시간을 측정하는 것은 아니다.
- 기본적으로 세션 프리셋(예: 청향 우롱)이 노출되지만, 요약 헤더 우측의 **연필 아이콘(✏️)**을 클릭하여 `2024 대만 아리산 청향 우롱`처럼 차/도구 이름을 자유롭게 인라인 수정할 수 있다.
- **차종 상징 이모지 2계열 분류**: 시각적 조잡함을 피하고 절제된 미학을 위해 차종 이모지는 2계열로만 심플하게 나눈다: `🍃` 청차계 (녹차, 말차, 백차, 황차, 청향 우롱, 포종, 봉황단총, 보이 생차) vs `🍂` 농차/숙차계 (농향 우롱, 무이암차[대홍포·육계·수선], 동방미인, 호지차, 홍차, 흑차/보이 숙차).

### 4.2 오늘 떠오른 단어 (감각 태그)
- 타이틀: **`오늘 떠오른 단어`**
- 앱이 제안하는 기본 태그 14종:
  > 단맛 · 꽃향 · 과일 · 곡물 · 구운맛 · 견과 · 풀 · 나무 · 흙 · 연기 · 떫음 · 부드러움 · 맑음 · 묵직함
- 태그는 모서리 4px의 테두리 없는 소프트 면 배지로 표시한다. 선택하면 금색 계열 면·글로우·굵기로 상태를 중복 표현한다.
- 현재 시각 높이는 30px다. 조밀한 외형은 유지하더라도 투명 패딩이나 래퍼를 포함한 유효 터치 영역은 44px 이상이어야 하며, 이 보강은 아직 미완료다.

### 4.3 조금 더 자세히 적는다면 (자유 입력창)
- 타이틀: **`조금 더 자세히 적는다면`**
- 별도 캡션을 늘리지 않고 입력창 placeholder에 비유·분위기·장소를 자유롭게 적어도 된다는 안내를 통합한다.
- 사용자가 직접 한두 줄을 자유롭게 쓴다. (예: `흰 쌀밥을 오래 씹은 맛`, `비 오는 날 창가에서 마심`, `3포째가 제일 달았다`)

### 4.4 하단 액션 버튼 (3종)
1. **`💾 임시 저장`**: 포(泡) 사이사이에 기록을 남기고 닫아도, 세션이 유지되는 동안 내용이 지워지지 않고 보존된다.
2. **`📋 텍스트 복사`**: 클립보드 복사 (`차담`, `Notion`, `Obsidian`, `기본 메모장` 등 붙여넣기용).
3. **`🖼️ 카드 이미지 저장`**: 680×900 Canvas PNG 시음 카드를 생성하고 파일 공유를 우선한 뒤 다운로드로 폴백한다.

### 4.5 표현이 막힌다면 · 미구현 제안

기본 태그 아래에 `전혀 감이 안 온다면 향과 맛의 단어장 📗을 구경해 보세요` 같은 작은 링크를 둔다. 단어를 반드시 고르거나 교육 단계를 완료하게 하지 않고 구경한 뒤 자기 문장을 써도 된다. 상세 방향은 [sensory-vocabulary.md](sensory-vocabulary.md)를 따른다.

### 4.6 더 남기고 싶다면 · 미구현 제안

- 찻잎 g·물 ml·실제 수온은 접힌 선택 영역으로 검토한다. 입력하지 않아도 완전한 기록이다.
- 앱의 권장 온도를 실제 수온으로 채우지 않는다. 실제 수온을 사용자가 보고하지 않았다면 비워 둔다.
- 프리셋 ID와 사용자가 바꾼 이름을 별도로 보존하고, 선택 이력·실행 시간과 실제 물리 상태를 혼동하지 않는다.

## 5. export 카드

### 5.1 구성
- 텍스트는 자동 정보(§4.1)의 완료 포별 시간까지 포함하고, 카드 이미지는 현재 제목·도구·날짜·총 포 수·선택 태그·문장을 담는다. 카드 이미지에 포별 상세 시간은 넣지 않는다.
- 시각 톤은 앱과 같은 어두운 배경·Gowun Batang·금색 포인트를 쓴다. 선택 태그 수에 따라 행을 균등 분배해 카드 중심을 맞춘다.

### 5.2 두 가지 출력
| 형식 | 용도 | 현재 방식 |
|---|---|---|
| 카드 이미지 | 공유용 | 680×900 canvas 렌더 → PNG Blob·File. Web Share API가 파일 공유를 지원하면 공유 시트, 아니면 object URL 다운로드 |
| 텍스트 | 개인 메모 앱 붙여넣기용 | 클립보드 복사. `차담`, `Notion`, `Obsidian`, `기본 메모장` 등 사용자가 이미 쓰는 어떤 앱에 붙여넣어도 깔끔한 오픈 텍스트(Plain Text) 형태 |

- 빌드 없는 단일 `index.html` 원칙을 지키기 위해 이미지 생성 라이브러리를 들이지 않고 canvas에 직접 렌더한다.
- 현재 텍스트 export 예시:
  ```text
  [차 한 잔의 시간 시음 노트]
  🍃 청향 우롱 · 개완
  📅 2026.07.28 (3포 우림)
  ⏱️ 1포 20초 / 2포 25초 / 3포 30초
  🏷️ #단맛 #꽃향
  💬 "흰 쌀밥을 오래 씹은 듯 고소하고 달다."
  ```

### 5.3 구조화 데이터 · 미구현

현재 Plain Text/PNG는 빠른 공유용이다. 장기 보관과 도구 간 이동에는 Tea Session JSON·Markdown, 전체 사용자 자산 JSON 백업/복원을 추가하는 방향을 검토한다. 공개 스키마와 import는 [data-portability.md](data-portability.md)의 단계에 맞춰 별도로 구현한다.

## 6. 상태와 데이터 저장

### 6.1 현재 구현: 세션 초안과 선호 태그

- `customTitle`, `sessionDraftTags`, `sessionDraftNote`는 JavaScript 메모리에만 둔다. 시트를 닫거나 `임시 저장`을 눌러도 현재 페이지와 세션 안에서는 유지되지만 새로고침·앱 재실행·`우림 끝` 뒤에는 사라진다.
- `임시 저장`은 영구 저장이 아니라 현재 입력값을 세션 초안 변수에 반영하는 동작이다.
- 사용자가 설정 페이지에서 편집한 감각 태그 목록은 `teaTimer.preferences.v1.customTags`에 저장한다.
- 현재 메인 화면의 `savePreferences()`가 같은 키를 새 객체로 덮어쓸 때 `customTags`를 병합하지 않아 태그가 사라질 수 있다. 이 결함은 `ROADMAP.md`의 MVP 안정화 범위다.
- 사용자 기록의 영구 보관은 현재 텍스트 복사와 PNG 공유·다운로드가 담당한다.

### 6.2 확장 방향: 초안 보호와 명시적 장기 저장 · 미구현

핵심 원칙은 **타이머 사용 ≠ 기록 의사**다.

- 타이머만 사용한 세션은 자동으로 장기 기록에 쌓지 않는다.
- 사용자가 태그나 메모를 쓰기 시작했다면 작성 중 내용을 보호한다. 현재 메모리 초안에 더해 입력 중 자동 보존, 페이지 이탈·재실행 복원, 종료·삭제 경계를 정해야 한다. IndexedDB 임시 store를 사용할지는 아직 미확정이다.
- `기기에 남기기` 같은 명시적 동작으로 Tea Session을 확정하는 방향을 우선 검토한다. 버튼 문구·위치·저장 실패 피드백은 설계 중이다.
- 장기 사용자 자산은 IndexedDB의 `sessions`, `vocabulary`, 이후 `recipes`를 기본 후보로 삼고 가벼운 설정과 분리한다. 이 모델과 화면은 아직 구현하지 않았다.
- 세션의 차·다구 ID, 사용자 표시 이름, 완료 포별 시간, 태그·메모, 선택 측정값을 보존한다. 표시 문자열·UI 인덱스가 아닌 안정된 ID와 사용자 원문을 기준으로 설계한다.
- 저장하지 않고 현재 텍스트/PNG로 export만 하는 경로도 계속 허용한다. 기록 저장 실패가 타이머를 막아서는 안 된다.

### 6.3 보관·삭제와 백업

- 기존 `teaTimer.cups.v1` 최근 10장·초과분 자동 삭제안은 현행 계획에서 제외한다. 실제 구현된 데이터가 없으므로 여기서 수행할 데이터 마이그레이션도 없다.
- 10은 회고가 시작되는 시점이지 보관 상한이 아니다. 보관량·삭제 동의·용량 부족 처리는 별도로 결정하며 무제한 보관을 보장한다는 뜻도 아니다.
- 장기 세션과 개인 단어장, 현재 커스텀 태그는 백업해야 할 사용자 자산이다. 기본 태그와 앱 프리셋은 재생성 가능한 앱 자산으로 구분한다.
- 설정 초기화와 기록 삭제의 범위, 초안 수명, 백업·복원은 [data-portability.md](data-portability.md)에 맞춰 결정한다. IndexedDB만을 최종 보관 포맷으로 삼지 않는다.

## 8. 선택형 확장: `[차 열 잔의 기록]`

- 열 잔은 목표가 아니다. 명시적으로 남긴 기록이 어느새 쌓였을 때 회고가 의미 있어지는 발견 시점이다.
- 첫 장기 저장 뒤 작은 찻잔 아이콘·개수 배지를 보여주고 열 번째 기록에 `어느새 열 잔의 기록이 모였어요`라고 조용히 알리는 방향을 검토한다. 아직 구현하지 않았고 정확한 시점·모션은 미확정이다.
- 이전의 설정 토글 전용 노출안을 확정 규칙으로 유지하지 않는다. 기본 타이머를 쓰는 사용자에게 기록 메뉴·목표를 강요하지 않는 원칙은 유지한다.
- `7/10`, 진행률, `3잔 남았어요`, streak는 쓰지 않는다.
- 자주 고른 감각어·다구, 첫 기록과 최근 표현, 새로 등장한 개인 단어와 문장을 보여준다. `열 잔 중 여섯 잔에서 꽃향을 골랐어요` 같은 사실만 제시한다.
- 취향 점수나 `당신은 Floral Lover입니다` 같은 판정은 하지 않는다. 앱은 해석자보다 거울에 가깝게 남는다.
- 회고 화면의 범위와 데이터 보관·삭제 정책은 별개다. 열 장을 넘었다는 이유로 기존 기록을 버리지 않는다.

## 9. 개인 단어장·레시피와의 관계 · 미구현

- 시음 기록은 당시의 경험, 개인 단어장은 경험을 통해 사용자가 얻은 감각 기준점을 남긴다. `꽃향`에서 `비 온 뒤 돈나무꽃`처럼 자기 표현으로 깊어지는 것을 돕는다.
- 개인 단어는 기본 단어와 분리해 원문을 보존하고 시음 기록과 함께 백업한다. 세부 정보 구조는 [sensory-vocabulary.md](sensory-vocabulary.md)를 따른다.
- 레시피북은 맛있었던 포별 우림 순서를 다음에 불러오는 후속 실험이다. 재고·구매 관리나 기록 수에 따른 등급이 아니다.
- 기존 `[차 백 잔의 창고]`는 현행 단계별 계획에서 제외한다. 백 잔이나 50잔을 확장 기능의 확정 해금 조건으로 삼지 않는다.

## 10. 열린 질문

- 설정 초기화와 장기 기록 삭제를 분리할지, 초안·세션·개인 단어별 삭제·백업 범위를 어떻게 안내할지.
- 초안 보호에 쓸 로컬 저장소와 복원 시점, 페이지 이탈·재실행·우림 끝의 수명을 어떻게 정할지. 메모리만 쓰는 현재 동작과 향후 자동 보호 원칙을 구분한다.
- `기기에 남기기` 버튼 문구·위치와 첫 저장 후 기록 메뉴 노출 시점, 열 번째 기록의 회고 안내 강도.
- 장기 기록의 보관량·용량 부족·삭제 정책. 10장 제한이나 무제한 보관을 전제하지 않는다.
- 태그 문구 14종의 확정. 초보자 관점에서 겹치거나(부드러움/묵직함 vs 떫음) 어렵게 느껴지는 것이 없는지 실제 사용으로 확인.
- 현재 680×900 카드 비율이 메신저·SNS·사진 저장에서 충분한지 실사용으로 확인.
- 노트 버튼을 현재처럼 항상 보일지, 기존 설계처럼 완료된 포가 있는 `done` 상태에만 보일지.
- 첫 우림 전에 만든 초안을 차·다구 변경 시 유지할지, 선택 변경과 함께 비울지. 다른 차의 초안으로 오인되지 않는 것이 우선이다.

1. **`help.html` (사용법 전용 페이지)**:
   - 좌상단: `← 처음으로` (index.html 메인으로 이동)
   - 우상단: `⚙️` (settings.html 설정 페이지로 이동)
   - 내용: 5단계 가이드 (`차/다구 고르기`, `시간 맞추기 & 우리기`, `다음 泡 우리기 & 표일배 배수`, `차 느낌 남기기`, `우림 끝내기`), 자유롭게 쓰세요(오프라인/오픈소스), 제작자 이야기 & 👏 응원 박수
2. **`settings.html` (개인 설정 전용 페이지)**:
   - 좌상단: `← 처음으로` (index.html 메인으로 이동)
   - 우상단: `ⓘ` (help.html 사용법 페이지로 이동)
   - 내용:
     - 7종 차별 권장/보정 시간 관리 (- / + 조작 및 차별 기본값 복원)
     - 오늘 떠오른 단어 태그 관리 (새 단어 추가 / ✕ 삭제 / 기본 14종 복원)
     - 기억한 설정 지우기 (현재 선호 설정·커스텀 태그 초기화. 향후 장기 기록 삭제 범위는 별도 설계)

   - 메인 화면(`index.html`) 상단 우측 메뉴 `사용법` ➔ `help.html`로 연결.
   - 서브 페이지들(`help.html`, `settings.html`)의 메인 복귀 버튼 텍스트는 **`← 처음으로`**로 통일.

## 13. 차 느낌 기능에 적용하는 디자인 원칙

전체 화면 레이아웃, 여백, 가장 작은 모바일 화면 검증 기준은 `DESIGN.md` §§1.3, 3, 8, 12를 따른다. 이 문서에는 기록 기능에 특화된 원칙만 남긴다.

1. **정답을 요구하지 않는 언어**: `오늘 떠오른 단어`, `조금 더 자세히 적는다면`처럼 어떤 경험도 기록이 될 수 있다는 허용의 톤을 쓴다.
2. **데이터 락인 배제**: 회원가입과 중앙 사용자 DB를 전제로 하지 않는다. 현재 일반 텍스트·PNG는 빠른 공유용이고 향후 사용자 자산의 장기 보관·이동은 JSON·Markdown·공개 스키마로 보강한다.
3. **조밀하지만 안전한 태그**: 4px 모서리의 소프트 면 배지로 정보 밀도를 유지하되 유효 터치 영역과 키보드 포커스 표시는 접근성 기준을 충족한다.
4. **세션 흐름 우선**: 기록 시트는 자동으로 열리지 않고 출탕·다음 포·우림 종료를 대신하지 않는다.
5. **가변 콘텐츠 균형**: 카드의 선택 태그는 개수에 따라 줄별로 균등 분배해 어떤 조합에서도 중심과 여백을 유지한다.
