## 권장 순서

착수 전 검토안 중 채택한 정책은 [DESIGN §6.5](DESIGN.md), [차 느낌](design-tea-feeling.md#draft-policy), [저장 계약](data-portability.md#preferences-contract), [다국어 설계](design-localization.md)에 반영했다. 아래 코드 위험은 검토 당시의 근거이며, 동작 정책은 해당 상세 설계가 기준이다.

**동작·데이터 계약 정리 → TW-01 → TW-02 → TW-03 → TW-05 → TW-06 → TW-07 → TW-08** 순서로 진행한다. TW-04는 [실사용 수요에 따른 보류 결정](DESIGN.md#early-pour-policy)으로 이번 묶음의 선행 조건·완료 기준에서 제외한다. 번호는 유지하며 번역 구조와 글꼴의 위험 확인은 앞당긴다.

| 단계 | 구현 범위와 선행 이유 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 착수 전 — 문서 완료 | 초안 경계, 조기 출탕 시간, 언어 전환·태그 호환 정책을 관련 설계에 반영했다 | 문서·코드 대조와 검증 시나리오 정의 완료. 런타임 구현·통과 결과는 별도 |
| TW-01 | 설정의 읽기·검증·부분 갱신 계약을 통일한다. 태그 소실뿐 아니라 아래 차 ID 불일치도 함께 해결한다 | 메인과 설정을 오가며 태그·차별 보정·음소거·미지의 추가 필드가 보존된다. 기존 ID 별칭의 이관을 검증한다 |

| TW-03 | 확정한 초안·선택 잠금·종료·페이지 이동 보호 정책을 적용한다. 요약·텍스트·PNG의 완료 포 수를 일치시킨다 | 선택 차단·종료 취소 시 초안 유지, 허용한 변경 후 다른 차의 기록으로 오인되지 않음, 0포를 1포로 표시하지 않음 |

| TW-05 | 안정된 기능의 표시 문자열을 분리한다. 공용 번역 조회, 메인 언어 선택·기본 메뉴·정적 공지 읽기, 언어 기억, 기본 태그 ID, 사용자 원문, 누락 키 폴백을 구현한다 | 한국어 동작 회귀 없음, 기존 차·다구 ID 유지, 우림 중 언어 전환·공지 열기 시 타이머·초안 보존, 문서 이동 보호 유지, 기존 태그 원문 보존 |

| TW-08 | 로컬 검증·배포 준비 후 GitHub Pages에 배포하고 세 언어(`ko`·`zh-TW`·`zh-CN`)의 모바일 브라우저/설치형 PWA, 기존 설치 업데이트, 오프라인·오디오 복귀를 공개 HTTPS에서 검증한다 | 자동 검증 결과와 실제 기기 결과를 구분해 기록하고, 미검증 항목을 완료로 표시하지 않음 |

TW-01–03은 한국어로 구현·로컬 검증을 완료했다. TW-04를 기다리지 않고 TW-05에서 한국어 카탈로그를 먼저 적용했으며, 한국어 회귀와 사용자 실제 화면 검토를 마쳤다. TW-05 기능 브랜치는 `codex/tw-05-localization-foundation`이며 통합 병합·회귀 결과는 [마감 기록](CHANGELOG.md#tw-05-close)을 따른다. TW-06은 `codex/tw-06-traditional-chinese`에서 구현·검증 후 통합했다. TW-07 A안도 구현·로컬 검증했고 실기기 확인 및 TW-08을 남겨 둔다([기록](CHANGELOG.md#tw-07-balanced-card)). 조기 출탕, 프레임워크 전환이나 앱 전체 구조 개편은 선행 조건으로 두지 않는다.

## 착수 전 코드에서 확인한 선행 위험

### 1. TW-01은 태그 필드 한 개를 추가하는 수정으로 끝내지 않는다

이 절의 결함은 TW-01에서 수정·검증했다. 당시 위험을 설명하는 원문이며 현재 저장 동작은 [공통 저장 계약](data-portability.md#preferences-contract)을 따른다.

- `index.html:1726`의 `savePreferences()`는 같은 저장 키를 새 객체로 덮어써 `customTags`와 추후 언어 설정을 잃는다. `settings.html:209`도 페이지를 열 때 읽은 `prefs` 전체를 다시 저장하므로 오래 열린 다른 페이지의 변경을 되돌릴 수 있다.
- 차 ID가 불일치한다. 메인의 `nong`, `sheng`, `shou`에 대응하는 설정 ID는 `dark-oolong`, `sheng-puer`, `shou-puer`다 (`index.html:1655`, `settings.html:179`). 메인 loader는 자기 ID만 읽으므로 세 차의 설정 보정값이 적용되지 않는다.
- **결정:** 기존 메인 ID를 유지하고 설정 별칭을 호환 읽기한다. 유효한 canonical 값 우선, 그렇지 않으면 유효한 별칭을 채택하며 자동 호환 처리로 별칭 원본을 삭제하지 않는다. 저장 직전에 최신 값을 읽어 해당 필드만 갱신하고, 차별 보정은 해당 차 항목만 갱신한다. 상세 충돌·초기화 규칙은 저장 계약을 따른다. 단순 병합을 여러 탭의 원자적 저장 보장으로 설명하지 않는다.
- 버전 불일치 시 메인은 전체 기본값으로 돌아가지만 설정은 다른 검증을 사용한다. `locale` 추가만을 위해 무작정 버전을 올리지 말고 호환 읽기·쓰기 계약부터 정한다.
- 두 페이지 모두 빈 `customTags` 배열을 기본 태그로 되돌린다. TW-01에서 빈 배열은 빈 목록으로 유지하고, 필드 누락 때만 화면 기본값을 사용하기로 정했다.

### 2. TW-02와 TW-03은 연결되지만 서로 다른 완료 조건이다

- **TW-02 반영:** 착수 전에는 opacity/pointer-events만 사용했으나, 현재는 named dialog·중첩 inert·Tab 순환·Escape·진입 버튼 복귀·44px를 구현했다. 인라인 제목/합성 IME·카드 중첩·우림 완료 후 복귀를 로컬 검증했으며 실기기 한계는 [기록](CHANGELOG.md#tw-02-accessibility)을 따른다.
- **착수 전 위험, TW-03 해결:** `selectTea()`·`selectVessel()`은 타이머의 `reset()`을 호출하지만 초안 변수는 지우지 않았다. 초안 삭제는 `우림 끝` 클릭 핸들러에 따로 있다 (`index.html:2136`, `2174`, `2468`, `2963`). 당시 선택 변경이 초안을 다른 차에 붙일 수 있었으며, 현재는 초안이 있으면 변경을 막고 자산 준비 뒤에도 재검사한다.
- **TW-03 해결:** 착수 전 카드 미리보기/PNG의 0→1 대체를 제거했다. 시트·텍스트·DOM 카드·PNG 모두 완료 0포를 `완료된 우림 없음`으로 표시한다.
- 현재 PNG에는 포별 시간이 실제로 그려지지만 검토 당시 차 느낌 설계 §5.1에는 넣지 않는다고 적혀 있었다 (`index.html:2825`). 착수 전 문서를 정정했고, TW-03에서 DOM 미리보기와 실제 출력의 완료 포 수를 맞췄다.

### 3. TW-04의 위험은 버튼보다 완료 부작용에 있다 — 보류 전 검토

아래는 보류 전 위험 분석이며 TW-05 착수나 이번 배포의 선행 작업이 아니다. 재착수 시 [보류 결정·이전 설계](DESIGN.md#early-pour-policy)와 함께 다시 검토한다.

- `startBrew()`는 설정한 초를 `activeBrew.sec`에 넣는다. `finishSteep()`는 그것을 기록하고 종료음·플래시·최종 탕색을 적용한다 (`index.html:2414`, `2435`, `2479`). 조기 출탕에서 그대로 호출하면 실제 경과 시간 대신 예정 시간이 남는다.
- `recordActiveBrew()`의 포 번호 중복 방지만으로 종료음이나 다음 포 증가까지 중복 방지되는 것은 아니다. 상태 전이와 부작용 전체가 한 번만 실행되어야 한다.
- **결정:** 기존 `enterSteep()` 시점을 경과 시간 시작으로 삼고 `pour` 연출 중에는 조기 출탕을 비활성화한다. 조기 출탕은 한 번의 버튼 조작으로 기록 확정과 출탕에 진입한다. 반올림·정상 완료와의 경계·잔여음 처리·보정 불변의 상세 규칙은 [출탕 정책](DESIGN.md#early-pour-policy)에 반영했다.
- 로드맵의 난이도 ‘낮음’보다 검증 부담은 크다. 별도 변경 단위로 두고 종료 직전 경계·5종 다구·reduced-motion을 확인한다.

### 4. TW-05는 화면의 한국어 치환보다 범위가 넓다

- 기본 태그와 사용자 태그가 같은 문자열 배열에 있다. 기존 문자열이 기본 목록과 같다는 이유만으로 번역 가능한 기본 태그로 바꾸면 안 된다. **새 기본 태그는 ID로, 출처가 불분명한 기존 문자열은 사용자 원문으로** 다루기로 정했다. TW-05의 선택 필드 `tagItems`와 기존 `customTags`의 우선순위는 [태그 호환](design-localization.md#tag-compatibility)을 따른다.
- `getTeaEmoji()`는 한국어 이름의 정규식에 의존한다 (`index.html:2591`). 앱의 기본 차 표현은 번역된 이름이 아니라 기존 차 ID로 결정해야 한다. 사용자가 편집한 제목도 기본 표시명과 분리한다.
- 메인→도움말→설정은 별도 HTML 문서 이동이다 (`index.html:1350`, `help.html:93`). TW-03에서 안전한 idle 전까지 현재 문서를 떠나는 앱 내부 이동을 막았다. TW-05에서 언어 전환을 연동한다. 브라우저 뒤로 가기 복원에 의존하지 않는다.
- 명시적으로 기억한 언어 우선, 미설정 시 기존 한국어 기본값을 유지한다. [배치 설계](design-navigation.md)에 따라 메인 우상단과 설정 모두에서 언어를 선택한다. 메인에서 직접 바꾸면 우림 중에도 같은 문서에서 상태를 보존해 적용하며, 자동 감지는 도입하지 않는다. 다른 탭의 변경은 안전한 상태까지 유예한다. 사용법 자리는 공지사항·사용법·설정 메뉴로 바꾼다. 사용자 요청으로 정적 공지 읽기를 TW에 추가하며 기록함 등 후속 기능은 앞당기지 않는다.
- `html lang`, 제목·접근성 라벨·토스트·동적 시간 문구·텍스트 export·Canvas·파일 공유 제목을 모두 목록화한다. 앱 이름/설치명은 기존 제품명 원칙과 함께 별도 결정하고 일반 UI 언어 전환과 구분해 검증한다.
- 번역 파일을 외부 JS/JSON으로 추가한다면 그 단계부터 SW 사전 캐시 목록에도 넣는다. 현재 SW는 명시된 앱 파일만 캐시한다. TW-08까지 캐시 대응을 미루지 않는다.

## 앞당겨도 좋은 작업과 병렬 작업의 경계

- **TW-01에서 정한 계약 활용:** TW-05의 설정 필드·태그 호환 계약을 바탕으로 번역 키를 구체화한다. 실제 전체 문자열 추출은 완료한 TW-02·03의 동작·문구를 기준으로 하며, 보류한 TW-04의 문구는 제외한다.
- **TW-05와 병행 가능한 준비:** 대만 차·다구·정상 출탕 용어 초안과 긴 번체 예문을 준비한다. 아직 바뀔 수 있는 조작 문구는 확정 번역으로 취급하지 않는다.
- **TW-05 초반:** TW-07의 짧은 사전 점검으로 번체와 한국어 혼합 문장을 화면·PNG에 렌더하고 네트워크 차단 시 폴백을 확인한다. 전체 글꼴 셀프호스팅은 전제하지 않는다.
- **최종 TW-07·08:** 실제 번역과 모든 안정화 변경이 합쳐진 버전으로 다시 검증한다. 사전 점검을 최종 통과로 대체하지 않는다.
- **사용자 검증 환경:** 맥 브라우저와 같은 Wi-Fi의 iPhone 13 mini를 사용한다. [접속·검증 범위](design-localization.md#device-validation-scope)에 따라 LAN HTTP의 화면·입력·PNG 확인과 HTTPS의 PWA·오프라인·Wake Lock·공유 검증을 구분한다. 2026-08-31 사용자 결정으로 임시 인증서 방식을 중단하고 [GitHub Pages 배포 후 공개 HTTPS에서 확인](design-localization.md#pages-device-validation)한다. 로컬 검증·공지/버전·배포 준비는 먼저 수행하고, 실제 브라우저·OS 버전과 접속 결과를 기록한다. 기존 공개 설치의 업데이트 검증을 위해 배포 전에 구버전 설치·캐시·테스트 설정을 보존한다. 배포 성공과 TW-07/08 검증 완료를 구분한다.
- 후속 TW-05·06도 큰 `index.html`의 상태·시트·문구를 건드리므로 동시 코드 편집보다 순차 구현을 권장한다. 병렬화는 번역 초안, 테스트 시나리오, 독립 검토에 우선 사용한다.

## 변경 단위와 검증 기록

TW별로 검토 가능한 커밋을 나누고, TW-05는 ‘한국어 공통 기반’과 ‘태그/언어 호환’ 정도로 더 나눌 수 있다. 기존 작업 트리의 ROADMAP·DESIGN·CHANGELOG 변경은 사용자의 문서 변경으로 보존하고 런타임 수정과 섞어 완료로 기록하지 않는다.

1. TW-01: 실제 기존 저장값 fixture로 태그, 빈 목록, ID 별칭, 보정값 충돌, 추가 필드, 손상된 저장값을 확인한다.
2. TW-02·03: 키보드·접근성 트리와 입력/선택 변경 시나리오로 포커스와 초안 보존을 확인한다.
3. TW-04 보류: 조기 완료 경계 검증은 이번 필수 검증에서 제외한다. 재착수 시의 시나리오는 [이전 설계](DESIGN.md#early-pour-policy)에 보존한다.
4. TW-05·06: 키 집합과 치환 변수 일치, 한국어 폴백, 사용자 원문 불변, 차/다구 ID 동일성을 확인한다.
5. TW-07: 세 언어 375×660 화면과 680×900 원본 PNG를 남긴다. 긴 입력과 폰트 미로딩도 확인한다.
6. TW-08: 언어 3종 × 모바일 브라우저/설치형 PWA에서 정상 완료→출탕→다음 포→기록·공유를 확인하고, 세션 종료·연타·앱 복귀에도 기록/출탕/다음 포/종료음이 중복되지 않는지 검증한다. 오프라인 재실행·기존 설치 업데이트·오디오 인터럽션 복귀를 더한다. 조기 출탕은 제외하며, 공지 4개가 실제 배포 내용과 일치하는지·예정 항목을 구분하는지·세 언어·오프라인 표시를 확인한다. 실기기에서 확인하지 못한 조합은 미검증으로 남긴다.

**아래는 초기 문서 단계의 수행 범위다.** TW-01의 실제 구현·검증 결과와 혼동하지 않는다.

초기 검토와 착수 전 단계에서는 파일과 상태 전이 코드를 읽고 정책·시나리오를 정했다. 문서 간 상태 표기·링크·diff를 확인하고 통합 브랜치에 문서 기준점을 남긴다. 기능 구현, 브라우저 실행 검증, SW 캐시 변경, 푸시·배포는 하지 않는다. 백그라운드 완료음 보장, 장기 기록·백업, 다른 언어, 캐러셀·다구 연출 확장은 이번 선행 조건에 넣지 않는다.

## 현재 배포 실행 체크리스트 — 2026-08-31

이 절은 위 착수 전 검토와 구분한 실제 배포 준비 기록이다. `ko`·`zh-TW`·`zh-CN`과 의견함을 포함하며, 운영 의견함 확인 전에는 공지를 정식 게시하거나 정적 앱을 먼저 배포하지 않는다.

### 확인한 기준점

- GitHub Pages API에서 배포 원본은 `main`의 `/`, 상태는 `built`, HTTPS 강제 사용을 확인했다. 원격 `main`과 마지막 Pages 빌드 커밋은 `2bfc01e8f134c18327fa551097681c95dbf49b39`, 공개 `sw.js`는 `v57`이다. 이 커밋은 현재 통합 브랜치의 조상이며 확인 시점의 원격 변경 누락은 없다. 실제 배포 직전에 다시 확인한다.
- 준비 중 런타임은 `4a85f79`의 `v82`다. UI 가이드라인과 세 언어 검증 계획은 각각 `03bf9f0`, `50f1539`로 커밋했다. 뒤이은 검증 도구·문서 변경은 앱 런타임을 바꾸지 않는다.
- GitHub 인증은 유효하지만 Cloudflare Wrangler 인증이 만료됐다. 재로그인은 외부 계정의 인증 세션을 갱신하는 작업이므로 자동 안전 검토에서 명시적 승인 요구로 차단됐다. 우회하지 않으며 계정 재인증 후 아래 운영 단계를 재개한다. 현재 운영 Worker·DB·Pages를 변경하지 않았다.

### 운영 반영 순서

1. **계정·기준점 재확인:** Cloudflare 재인증을 마치고 계정·기존 Worker 버전·D1의 적용 migration·비밀키 이름·rate-limit namespace 중복 여부를 확인한다. 비밀키 값이나 실제 의견 본문은 로그·문서에 남기지 않는다. 사용자의 구버전 PWA·테스트 설정 보존 여부는 실기기 확인 항목으로 남긴다.
2. **의견함 준비:** [의견함 배포 절차](creator-feedback.md#배포-순서와-남은-확인)대로 기존 D1의 백업/복구 가능 시점을 확보하고 migration runner로 미적용 `0001`·`0002`를 적용한다. 기존 박수와 메시지의 행·ID·본문을 보존한다. 필요한 두 비밀키·제한기·일일 만료 삭제를 준비하고 `ADMIN_TOKEN`은 유지한다. 실제 배포 설정의 `FEEDBACK_ENABLED=true` 반영까지 확인하며 대시보드만 바꾸고 저장소의 `false`를 다시 배포하지 않는다.
3. **Worker 먼저 검증:** Worker 배포 후 접수·인증 조회·동일 요청 재시도·만료 처리와 박수 API의 기존 계약을 확인한다. 운영 검증용 메시지는 테스트임을 명시하고, 실제 박수 수를 늘리는 요청은 보내지 않는다. 인증 없는 조회 차단도 확인한다. 서버가 준비되지 않으면 정적 앱 배포를 중단한다.
4. **공지·캐시 승격:** 검토한 네 항목을 `draft`에서 첫 `releases` 묶음으로 옮기고 초안을 비운다. `updatedOn`은 실제 게시일, SW는 그 시점의 새 버전으로 정한다. 예정 항목은 준비 중으로 유지한다. 현재 상태를 검사하는 Node 기대값·캐시 검사도 함께 갱신하고, 세 언어 공지·언어 전환 중 타이머·PNG·캐시 회귀를 확인한다.
5. **정적 앱 배포:** 준비 브랜치의 코드·문서·검증 결과를 통합한 뒤 배포할 최종 커밋을 기록한다. 원격의 새로운 변경이 없는지 재확인하고 `main`에 반영·푸시한다. Pages 빌드의 커밋·상태와 공개 HTML/JS/SW가 일치하는지 확인한다. 푸시만 성공한 것을 배포 완료로 보고하지 않는다.
6. **실기기 검증:** [세 언어 Safari/PWA 순서](design-localization.md#pages-device-validation)를 수행한다. 기존 설치 업데이트·오프라인·실제 공유·오디오 복귀·VoiceOver·OS IME·글꼴 검증과 현지인 표현 검수를 구분해 기록한다. 배포 성공만으로 TW-07/08을 완료 처리하지 않는다. 의견 정기 조회 자동화는 별도 주기 결정 후 등록한다.

### 장애 대응

- 우선 수정 배포를 사용하고 배포 커밋·Worker 버전·SW 버전을 함께 남긴다. 의견함 장애는 쓰기를 비활성화한 수정 배포로 제한하며 기존 박수, DB와 만료 보관 정책은 유지한다. 성공으로 위장하거나 미전송 본문을 지우지 않는다.
- 공개 `v57`은 비교·복구 검토의 기준점이지 무조건 되돌릴 대상이 아니다. TW 이전 설정 저장에는 이미 수정한 데이터 보존 결함이 있으므로, 새 버전에서 작성한 단어·설정과의 호환을 검증하지 않고 과거 프런트엔드를 통째로 복구하지 않는다. 긴급 수정에서도 현재의 저장·원문 보호 계약을 유지한다.
- D1 역방향 migration, 사용자 사이트 데이터/캐시 삭제, `main` 강제 푸시를 복구 절차로 사용하지 않는다. 자산 복구가 필요하면 별도 수정 커밋과 새 SW 버전으로 배포하고 기존 설정을 보존한 업데이트 경로를 검증한다.
