# 공통 UI 기준

> 기준일: 2026-08-31 · TW-05 한국어 화면 검토
> 적용 대상: 메인·이용 안내·설정의 메뉴, 일반 화면의 텍스트 계층과 정렬.
> 구현 기준: [`styles/ui.css`](../styles/ui.css). 메뉴의 목적·순서·이동 정책은 [화면 배치 설계](design-navigation.md)를 따른다.

## 1. 역할에 따라 정한다

화면마다 임의의 숫자를 추가하지 않고 같은 역할에는 같은 토큰을 사용한다. 글꼴은 기존 Gowun Batang과 CJK 폴백, 숫자·영문 부제는 Space Mono를 유지한다. 아래 px는 기본 16px 환경의 환산값이며 글자 크기는 rem으로 정의한다.

| 역할 | 크기 | 행 높이 | 굵기·색·정렬 |
|---|---:|---:|---|
| 하위 페이지 제목 | 1.45rem / 23.2px | 1.4 | 700·금색·가운데 |
| 메인 제품명·공지/응원 창 제목 | 1.18rem / 18.88px | 1.5 | 제품명 700, 공지 제목 400·금색 |
| 구역 제목·접힘 메뉴 | 1.04rem / 16.64px | 1.5 | 700·금색·가운데. 공지 소제목은 400·왼쪽 |
| 상하단 메뉴·목적지·일반 버튼 | .94rem / 15.04px | 1.3125rem / 21px | 400·메뉴는 보조 본문색·아이콘과 수직 중앙 |
| 본문·선택지 | .9rem / 14.4px | 1.75 | 400·기본 본문색 또는 기존 보조색·긴 글은 왼쪽 |
| 보조 안내 | .82rem / 13.12px | 1.65 | 400·보조 본문색 |
| 제품명 각주 | .78rem / 12.48px | 1.6 | 400·흐린 색·가운데. 메뉴 버튼과 구분 |
| 영문 부제 | .68rem / 10.88px | 1.5 | Space Mono·보조색·가운데 |

주 실행 버튼(우리기 등)은 .98rem·700과 기존 강조 면을 유지한다. 읽기용 공지 상세의 행 높이는 기존 1.85를 유지한다. 입력창·태그처럼 별도 공간 제약이 있는 요소는 해당 토큰으로 명시한다. 단어장 칩은 .85rem/20px, 시각 배경 32px·삭제 영역 44px의 최근 결정을 유지한다. 차 느낌의 선택 칩도 같은 배경 크기를 사용하며, [칩 여백 계약](design-tea-feeling.md#42-오늘-떠오른-단어-감각-태그)에 따라 추가 세로 간격 없이 44px 터치 영역을 유지한다. 느낌 시트의 3열 보조 작업 버튼은 기존 .82rem·700/44px 영역을 유지하며 일반 상하단 메뉴와 구분한다. `+`/`−` 같은 기호 버튼은 아이콘 크기 19px과 최소 44px 영역을 사용한다.

타이머 숫자·차/다구 선택·느낌 시트/시음 카드 안의 콘텐츠와 680×900 PNG는 일반 메뉴 계층에 강제로 맞추지 않는다. 크기를 바꿀 때 해당 기능의 실제 화면·산출물 검증을 함께 수행한다.

## 2. 메뉴의 위치와 정렬

- 화면 프레임 최대 폭은 460px이며 가운데 놓는다. 본문 좌우 여백은 1.05rem이다. 높이 720px 이하 메인의 타이머 콘텐츠만 기존 .9rem 압축 여백을 유지하며, 이 경우에도 메뉴 기준선은 바뀌지 않는다.
- 상하단 조작의 좌우 기준선은 프레임 안쪽 .8rem, 340px 이하에서는 .7rem이다. safe area가 있으면 해당 여백을 더한다. 메인 상단·푸터와 하위 페이지 상단은 같은 기준선을 사용한다.
- 상단 조작 행은 위에서 .65rem + safe area에 놓고 최소 높이 44px을 확보한다. 메인은 기존 고정 배치와 제목 위 3.9rem + safe area의 메뉴 공간을 유지하며 짧은 화면에서도 이 공간을 줄이지 않는다. 읽기 페이지는 문서 흐름을 유지한다. 하위 화면을 스크롤할 때 상단 메뉴를 새로 고정하지 않는다.
- 상단·하단 메뉴는 글자 행 높이 21px, 아이콘 19×19px, 아이콘과 글자 간격 .3rem, 수직 중앙 정렬을 공유한다. 44px는 최소 조작 영역이며 글자나 배경을 44px 크기로 키우라는 뜻이 아니다.
- 메인 하단 조작과 이용 안내의 박수 버튼은 아래에서 .45rem + safe area의 같은 기준을 쓴다. 박수 버튼은 넓은 화면에서도 460px 프레임 밖으로 밀려나지 않으며, 제품명 각주가 버튼과 겹치지 않도록 문서 끝에 공간을 둔다. 검증 중 실제 박수는 전송하지 않는다.
- 가운데 정렬하는 접힘 제목은 양쪽에 같은 아이콘 공간을 예약한다. 펼침 화살표는 오른쪽에 독립 배치해 **문구 자체의 중심**이 움직이지 않게 한다. 긴 제목은 줄바꿈하며 좌우를 자르지 않는다.
- 이용 안내는 2026-08-31 사용자 요청에 따라 본문·접힘 제목·메시지/박수 창의 글을 왼쪽 정렬한다. 페이지 맨 위 제목·하단 제품명·버튼은 기존 배치를 유지하며, 설정의 가운데 접힘 제목에는 영향을 주지 않는다. 언어별 줄바꿈은 [§3](#locale-line-breaking)을 따른다.
- 언어 선택은 한국어·번체·간체 순서다. 설정의 라디오는 좁은 화면에서 줄바꿈을 허용하며 단일 행을 강제하지 않고 각 선택지의 44px 조작 영역을 유지한다.
- popover 목적지와 긴 설명·불릿은 왼쪽 정렬한다. popover 항목은 위아래 .6rem·좌우 .65rem 여백과 .65rem 아이콘 간격을 별도 공통 토큰으로 사용한다. 가운데 제목 원칙을 본문이나 입력값까지 확대하지 않는다. 같은 구역의 간격은 공통 값을 사용하되 기본 펼침 언어 구역의 압축 배치는 유지한다.

## 3. 언어별 줄바꿈

**2026-08-31 사전 결정:** 한국어·대만 번체에 더해 향후 중국어 간체·일본어·영어에도 아래 규칙을 적용한다. 이용 안내에는 한국어·번체·간체 규칙을 적용한다. 일본어·영어의 카탈로그·글꼴·선택 UI 추가와 다른 화면·PNG로의 적용은 각 기능 착수 때 구현·검증하며, 사전 규정만으로 지원 완료로 보지 않는다.

### 기본 규칙

가로쓰기의 긴 설명은 왼쪽 정렬한다. 단어 간격을 늘려 양끝을 맞추지 않으며, 기존 제목·버튼의 정렬은 역할별 기준을 유지한다. 언어별 본문 CSS의 출발점은 다음과 같다.

| 언어 | 줄바꿈 기준 | 기본 CSS 방향 | 주의할 부분 |
|---|---|---|---|
| 한국어 (`ko`) | 공백을 기준으로 어절을 유지 | `word-break: keep-all` | 조사·어미를 포함한 어절 중간을 평소에 끊지 않음 |
| 대만 번체 (`zh-TW`) | 한자 사이에서 줄바꿈 허용 | `word-break: normal; line-break: strict` | `，。！？`·닫는 괄호/인용부호는 줄 머리에, 여는 괄호/인용부호는 줄 끝에 홀로 남지 않도록 확인 |
| 중국어 간체 (`zh-CN`, 중국 대륙 기준) | 번체와 같은 글자 단위 줄바꿈 | `word-break: normal; line-break: strict` | 표준 중국어 문어체·간체를 사용하고 대륙의 인용부호·구두점·글꼴로 별도 검증 |
| 일본어 (`ja`) | 한자·가나 사이에서 줄바꿈 허용, 금칙 적용 | `word-break: normal; line-break: strict` | `、。`·닫는 괄호뿐 아니라 작은 가나 `っゃゅょッャュョ`·장음 `ー`가 줄 머리에 남는지 확인 |
| 영어 (`en`) | 공백 중심으로 단어를 유지 | `word-break: normal; hyphens: manual` | 자동 하이픈 삽입은 기본적으로 사용하지 않음. 원문에 있는 하이픈은 보존 |

`strict`는 브라우저의 문장부호·금칙 처리를 활용하는 기본값이며, 모든 조판 규칙을 완벽히 보장한다는 뜻은 아니다. 번체·간체는 줄바꿈 처리의 대부분을 공유할 수 있지만, 지역별 구두점 관습까지 같다고 가정하지 않는다. 일본어는 한국어용 `keep-all`을 물려받지 않게 한다.

간체의 지역 기준은 같은 날 사용자가 말한 ‘표준 북경어’를 중국 대륙의 표준 중국어 문어체·간체(`zh-CN`)로 구체화한다. 북경 방언의 구어 표현을 넣는다는 뜻이 아니다. 이번 구현의 포함 범위는 [현지화 설계의 확정 결정](design-localization.md#simplified-chinese-review)을 따른다.

### 넘침·혼합 언어·원문 보존

- 본문은 정상 줄바꿈을 먼저 쓰고, 긴 URL·이메일·공백 없는 입력처럼 한 덩어리가 가용 폭을 넘을 때만 `overflow-wrap: anywhere`로 예외 분리한다. `word-break: break-all`이나 `line-break: anywhere`를 전체 본문에 적용하지 않는다.
- 문서의 `lang`을 실제 표시 언어와 일치시킨다. 언어가 명확한 별도 인용·설명에는 해당 요소의 `lang`을 지정할 수 있으나, 사용자 입력의 언어를 임의로 단정하거나 저장된 언어 선택을 변경하지 않는다. CJK 문장 속 영문 단어·숫자와 단위도 함께 확인한다.
- 줄 모양을 맞추려고 번역 문자열이나 사용자 원문에 공백·강제 개행·보이지 않는 구분 문자를 삽입하지 않는다. 사용자가 직접 넣은 개행은 해당 입력/출력의 기존 보존 계약을 따른다. 표시 중 불가피하게 나누더라도 결합 문자·이모지의 한 글자 단위는 쪼개지 않는다.
- 제목·버튼·태그는 먼저 가용 폭·줄 수·높이로 대응한다. 카드의 행 수·생략은 기존 [카드 설계](design-tea-feeling.md)를 유지하고, 잘린 표시로 원문을 덮어쓰지 않는다. Canvas PNG는 CSS 줄바꿈이 자동 적용되지 않으므로 별도 조판과 원본 이미지 검증이 필요하다.

### 언어 추가 시 확인

320×660·375×660·넓은 화면에서 실제 번역·대상 언어 글꼴로 본문, 긴 제목/버튼, 메시지·오류 안내, 혼합 영문·숫자, URL·이메일을 확인한다. 일반 단어의 중간 분리, 금칙 문자 위치, 글자 누락, 가로 넘침, 44px 조작 영역을 검증한다. 일본어의 작은 가나·장음, 중국어의 연속 구두점·`……`·`——` 등은 줄 경계에 걸리는 사례도 포함한다. Chrome과 실제 Safari/iPhone 결과를 구분해 남기며 공유 기능을 제공하는 언어는 실제 PNG도 확인한다.

## 4. 조작과 유지보수

- 버튼·라디오 라벨·접기 제목은 44px 이상의 유효 영역을 유지한다. 포커스는 2px 금색 외곽선으로 표시하며, 배경이나 아이콘 크기를 줄여도 조작 영역·접근성 이름을 줄이지 않는다.
- `styles/ui.css`는 세 HTML의 로컬 스타일 다음에 로드하는 공통 기준이다. 같은 메뉴 역할의 글자·아이콘·여백을 개별 페이지에서 다시 덮어쓰지 않는다. 새 하위 화면은 `ui-subpage`와 기존 상단/제목/본문 구조를 재사용한다.
- 일반 UI 토큰과 메뉴·하위 페이지 공통 규칙은 공통 CSS에서 관리한다. 타이머 연출·상태 표시·카드 출력 등 기능 전용 스타일은 기존 파일에서 유지한다. 캐시에는 공통 CSS를 처음부터 포함한다.
- 변경 시 320×660·375×660과 넓은 화면에서 프레임 기준선·수직 중앙·제목 중심·줄바꿈·넘침·44px 영역을 확인한다. 색이나 숫자만 같다는 이유로 실제 정렬 검증을 생략하지 않는다. 언어 전환·모달·타이머/초안 보호 회귀도 영향 범위에 맞게 확인한다.
- 로컬 렌더·합성 키 이벤트와 실제 모바일/PWA·스크린리더 검증을 구분한다. 공통 스타일 수정만으로 미검증 실기기를 통과했다고 표시하지 않는다.
