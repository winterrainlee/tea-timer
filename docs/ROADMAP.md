## 현재 우선 처리 — 대만 실사용: Phase A 핵심 + D-1 번체 중국어

**2026-08-31 우선순위 결정.** 대만에서 약 3개월간 중국어를 공부하고 사람들과 차를 마시는 실사용을 위해, 한국어를 유지하면서 대만 표현을 기준으로 한 번체 중국어를 먼저 지원한다. 앱 철학의 `친구에게 부담 없이 권하기`와 `차를 마시는 일이 먼저`를 이번 작업 선택의 기준으로 삼는다.

Phase A 전체 완료나 Phase B·C의 장기 저장·백업을 기다리지 않는다. 아래 묶음을 현재 실행 우선순위로 사용하며, 기존 Phase는 범위와 후속 계획을 설명하는 분류로 유지한다. **TW-01–03은 구현·로컬 검증 완료, TW-04는 보류, TW-05는 한국어 구현·로컬 검증·사용자 화면 검토 완료, TW-06은 구현·로컬 검증·통합 완료, TW-07은 A안 구현·로컬 검증 후 실기기 확인 대기, TW-08은 GitHub Pages 배포 후 실기기 검증 예정**다. TW-04는 이번 묶음의 선행 조건·완료 기준에서 제외하며, 로컬 검증·배포 준비 뒤 GitHub Pages에 배포하고, 전체 묶음 완료는 배포 후 TW-07·08의 필수 실기기 검증까지 확인한 뒤 판단한다.

**진행 상태(2026-08-31):** 통합 브랜치 `codex/tw-readiness`에서 [개발 흐름](../AGENTS.md)에 따라 기능별 분기·검증·병합한다. TW-01–03과 [TW-05 한국어 공통 기반·UI](CHANGELOG.md#tw-05-close)에 이어 [TW-06 번체 문구·독립 기본 단어](CHANGELOG.md#tw-06-traditional-chinese)를 구현·검증·통합했다. TW-07 A안 카드 조판을 구현·로컬 검증했다([기록](CHANGELOG.md#tw-07-balanced-card)). 실기기 확인과 TW-08은 남아 있다. TW-04는 [실사용 수요에 따라 보류](DESIGN.md#early-pour-policy)하며, `main` 반영·원격 푸시·배포는 하지 않았다.

## 앱 철학

`차 한 잔의 시간`은 많은 차 기록을 관리하는 전문 앱이 아니라, **짧은 우림 순간을 놓치지 않게 돕고 차에 재미를 붙이게 하는 작은 도구**다. 차를 처음 마시는 친구에게도 가볍게 추천할 수 있는 앱을 목표로 한다.

일반 타이머보다 나아야 하는 지점은 기능의 양이 아니라 감각의 밀도다. 차를 고르고, 도구를 보고, 물을 붓고, 곧 따라낼 때가 왔음을 자연스럽게 알아차리는 흐름이 핵심이다.

기본 타이머로도 차 우림 시간은 잴 수 있지만, 차를 우리는 사람에게 필요한 것은 단순한 초 단위 알람만이 아니다. 레시피를 일일이 뒤지지 않아도 잎과 다구 모양을 보고 대략적인 우림 시간을 잡고, 마지막 몇 초에는 "이제 곧 따라야 한다"는 마음의 준비를 할 수 있어야 한다.

특히 초보자는 차 이름, 다구 종류, 우림 시간, 따르는 타이밍을 한 번에 판단하기 어렵다. 그래서 이 앱은 설명을 많이 읽히기보다 화면만 보고도 "이 잎은 이 정도, 이 도구에서는 이쯤"이라고 직관적으로 이해되는 방향을 우선한다.

이 앱의 목표는 사용자를 차 전문가처럼 만들거나 방대한 기록 습관을 강요하는 것이 아니다. 차 이름을 정확히 모르더라도 잎 모양을 보고 고르고, 전문 시음어를 모르더라도 자기만의 말로 느낌을 남기면서 "차 마시는 일이 조금 재밌다"는 감각을 만드는 것이다. 그런 기록이 쌓여 사용자가 더 깊고 체계적인 기록을 원하게 되면, 그때는 전문 기록 앱이나 노트 도구로 넘어가면 된다.

가장 중요한 일은 **차를 마시는 것**이다. 기록하지 않은 차도 온전한 차 한 잔이며, 타이머만 사용해도 제품은 완전하다. 열 잔은 목표나 보관 상한이 아니라, 기록이 자연스럽게 쌓였을 때 회고가 의미 있어지는 발견 시점이다.

처음에는 한 잔을 우리는 타이머로 시작한다. 원하면 `[이번 차의 느낌]`을 남기고, 경험이 쌓였을 때 단어장·회고·자기 우림 재사용을 선택할 수 있다. 기록 개수로 목표·등급·업적을 만들지 않으며, 사용자를 앱에 붙잡기보다 데이터를 더 적합한 도구로 가져갈 수 있게 한다.

앞으로 기능을 추가할 때도 다음 기준을 우선한다.

- **우림 순간을 더 잘 감지하게 하는가.** 숫자만 늘리는 기능보다 탕색, 김, 링, 소리, 플래시처럼 즉각적인 신호를 강화한다.
- **차 도구의 감각을 해치지 않는가.** 화면은 도구 앱처럼 정돈하되, 중앙 도구와 차의 분위기는 따뜻하게 남긴다.
- **초보자가 이름을 몰라도 접근할 수 있는가.** 차 선택은 이름뿐 아니라 잎의 모양, 색, 탕색처럼 눈으로 확인할 수 있는 단서를 함께 제공한다.
- **친구에게 부담 없이 권할 수 있는가.** 첫 화면에서 설명서, 전문 용어, 기록 의무가 앞서지 않아야 한다.
- **짧은 시간 조작을 더 쉽게 하는가.** 수십 초 단위의 차 우림에 맞춰 손가락 동선과 피드백을 줄인다.
- **실제 차 우리는 행동과 이어지는가.** 완료는 0초가 아니라 따르기, 분리하기, 다음 포로 넘어가기다.
- **한 잔의 느낌을 오래 붙잡게 하는가.** 기록은 정답형 시음노트가 아니라, 사용자가 자기 감각의 말을 찾도록 돕는 방식이어야 한다.
- **작고 즉시 실행 가능한가.** 설치와 오프라인 실행이 쉬운 PWA 성격을 유지한다.
- **이미 아는 것을 다시 묻지 않는가.** 앱 사용으로 생긴 정보는 자동 요약하고 사용자에게 감각과 선택 정보만 묻는다.
- **혼자 장기 유지할 수 있는가.** 서버·필수 계정·중앙 사용자 DB 없이 유지 가능한 복잡도를 우선한다.

기능은 실제 차를 마시며 반복해서 겪는 작은 장벽을 해결해야 한다. 차를 더 즐겁게 하는지, 초보자의 부담을 높이지 않는지, 현재 화면의 조용함을 지키는지 확인하고 여러 기준을 충족하지 못하면 추가하지 않는다.

## 카테고리 정의와 경계

카테고리는 **어떤 사용자 경험과 문제를 책임지는가**, Phase는 **어떤 순서와 의존성으로 구현하는가**를 나타낸다. 개발 방향과 완료 내역은 같은 카테고리를 사용한다. 아래 순서는 우선순위가 아니며, 문서의 카테고리가 그대로 앱의 탭이나 메뉴가 되는 것도 아니다.

| 카테고리 | 책임 범위 | 연결되는 앱 철학 | 다른 카테고리와의 경계 |
|---|---|---|---|
| 우림 감각·다구 표현 | 탕색·김·찻잎·다구·임박 신호로 우림 상태를 알아차리게 한다. 잎 모양으로 차를 고르는 시각 단서도 포함한다 | 숫자보다 감각 신호, 따뜻한 차 도구, 이름을 몰라도 접근 | 찻잎의 형태는 여기, 선택 영역의 배치·제스처는 UI. 신호의 표현은 여기, 오디오 재생 신뢰성과 렌더 비용은 성능 |
| 조작·세션 흐름 | 차·다구 선택의 동작 규칙, 시간 조정, 출탕·다음 포·세션 종료·잠금, 선택값을 기억해 재사용하는 흐름 | 수십 초 조작의 마찰 감소, 실제 따르기·분리와 연결, 이미 아는 정보 재사용 | 무엇을 언제 할 수 있는지는 여기, 버튼 위치·진입 동선은 UI, 저장 손실·마이그레이션은 데이터. 레시피 실행 순서는 여기, 레시피 작성 경험은 차 느낌 |
| UI·화면 구조·내비게이션 | 메인 화면의 역할, 기능별 진입점·아이콘·탭·메뉴, 화면 간 이동, 레이아웃·타이포그래피·반응형·접근성 | 타이머만으로도 완전한 사용, 첫 화면의 부담과 입력 밀도 억제, 작은 화면·엄지 조작 우선 | 기능이 **어디에 있고 어떻게 접근되는지**를 담당한다. 기록 내용·저장 정책·세션 규칙 자체는 해당 기능 카테고리. 화면에 보인다는 이유만으로 모든 기능을 UI로 분류하지 않는다 |
| 차 느낌·감각 확장 | 선택적인 태그·메모, 감각 단어장, 사실 중심 회고, 경험을 다시 쓰는 레시피 작성 | 기록의 선택권, 자기 감각의 말 찾기, 열 잔은 목표가 아닌 발견 | 무엇을 표현하고 돌아볼지는 여기, 기록함의 위치는 UI, 초안 보호·영구 저장·내보내기 형식·복원은 데이터. 단어장의 의미·분류와 번역 작업도 구분한다 |
| 데이터 보존·이동성 | 초안과 확정 기록의 저장 경계, 설정·커스텀 태그 보존, 안정된 ID, 삭제·이관·백업·복원·내보내기 | 데이터 락인 배제, 재생성할 수 없는 사용자 자산 보호, 기록하지 않을 권리 | 어떤 값을 안전하게 남기고 옮기는지는 여기, 설정을 사용해 타이머가 어떻게 시작되는지는 조작, 저장 화면의 배치는 UI. IndexedDB 사용 자체보다 자산 보존이 목적 |
| 성능·PWA·오디오 | 시간 정확도·백그라운드 신호·오디오 복구, 렌더·발열·자산 로딩, 서비스워커·오프라인 실행 | 작고 즉시 실행 가능한 도구, 우림 순간을 놓치지 않는 신뢰성, 장기 유지 가능한 복잡도 | 소리·모션이 무엇을 전달하는지는 감각, 언제나 제때 실행되는지는 여기. 폰트 로딩·캐시는 여기, 서체·글자 크기는 UI |
| 도움말·설정·언어 | 사용법·설정의 설명과 문구, 다국어·문화권별 표현, 제작자 연락·반응 안내 | 전문 지식 없이 부담 없이 권하기, 궁금한 만큼만 설명, 로컬 설정과 데이터 책임을 알리기 | 설명할 내용과 언어를 담당한다. 도움말·설정으로 가는 경로는 UI, 설정 동작은 조작, 저장·삭제 범위는 데이터. 반응 집계는 사용자 기록의 중앙 저장과 별개 |

### 경계 판단과 공통 품질 기준

- **파일이나 기술이 아니라 변경의 주목적으로 분류한다.** `index.html` 수정, SVG 사용, localStorage 사용만으로 카테고리를 정하지 않는다.
- 아이템마다 주분류는 하나만 둔다. 다른 영역은 상세 기록에서 관련 분류로 연결한다. 한 기능에 독립적으로 검증할 일이 여러 개라면 아이템을 나눈다. 기존 묶음 이력은 원문을 보존하고 주목적으로 한 번만 색인한다.
- 예: `카드 이미지 내보내기 추가`는 데이터, `카드 글꼴·여백 개선`은 UI, `카드에 남길 감각 표현 설계`는 차 느낌이다. 기존 `차 느낌 MVP`처럼 세 가지가 함께 들어간 이력은 기능 전체의 주목적인 차 느낌으로 둔다.
- 예: `기록함 탭 배치`는 UI, `기록의 확정·삭제 정책`은 데이터, `열 잔 회고에서 보여줄 내용`은 차 느낌이다. 탭을 추가했다고 기록을 자동 저장할 권한이 생기지는 않는다.
- 접근성·작은 화면·오프라인·타이머 비차단·사용자 자산 보호는 모든 카테고리의 공통 완료 조건이다. UI가 접근성 기준을 맡더라도 다른 영역의 검증에서 제외하지 않는다.

### 카테고리 수정 규칙

새 기능은 `실제 사용에서 겪는 장벽 → 연결되는 앱 철학 → 책임 카테고리 → Phase와 완료 기준` 순서로 검토한다. 카테고리는 철학을 실행 가능한 책임으로 나눈 것이지, 기능을 늘릴 근거가 아니다.

1. **추가**: 새 화면이나 기술이 생겼다는 이유만으로 추가하지 않는다. 기존 경계로 설명할 수 없는 지속적인 책임이 생겼을 때 정의·연결 철학·포함/제외 범위·대표 아이템을 함께 적는다.
2. **분리·통합·이름 변경**: 기존 아이템을 실제로 대입해 겹침과 누락을 확인한다. 변경 이유와 `이전 분류 → 새 분류`, 영향을 받는 아이템을 문서 변경 기록에 남긴다.
3. **연결 갱신**: 이 정의표, 개발 방향, 완료 아이템의 분류, 상세 기록의 분류·링크를 함께 맞춘다. 과거 완료일·구현 내용·관련 커밋은 분류 변경으로 다시 쓰지 않는다.
4. **우선순위와 상태 보존**: 카테고리 이동은 Phase 이동이나 구현 완료를 뜻하지 않는다. 우선순위·상태를 바꿀 때는 별도 이유를 남긴다.
5. **철학과 충돌 시 중단**: 기록 강요·메인 타이머 잠식·데이터 종속을 새 카테고리로 정당화하지 않는다. 정말 제품 원칙을 바꿔야 한다면 [DESIGN.md](DESIGN.md)의 결정 근거와 이 문서의 앱 철학부터 별도로 검토한다.

카테고리 정리에서는 기존 개발 방향의 주제를 위 7개 책임 영역으로 정규화했다. 특히 UI의 책임을 화면 장식에서 기능 확장에 따른 화면 구조까지 명시하고, 데이터 보존·이동성을 감각 기록과 분리했다. 분류 변경 자체로 구현 상태나 Phase 순서를 바꾸지 않는다. 대만 실사용을 위한 D-1 선행은 별도로 결정한 [현재 우선 처리](#taiwan-priority)를 따른다.

## 개발 방향

### 카테고리별 방향

- **우림 감각·다구 표현**: 개완 뚜껑·회차별 탕색·도구 전환 전이와 차 선택의 잎 모양 단서를 강화한다.
- **조작·세션 흐름**: 구현한 초안·선택 변경 경계, 선택값 기억과 모든 다구의 정상 완료·출탕 흐름을 유지한다. 즉시 출탕은 실사용 수요 확인 후 재검토한다.
- **UI·화면 구조·내비게이션**: 현재 시트·카드의 접근성과 차 캐러셀 스와이프를 보강한다. 기능 확장 전 메인 역할·새 아이콘·탭 도입 여부·화면 간 복귀를 검토한다.
- **차 느낌·감각 확장**: 구현된 세션 기록 경험을 안정화한 뒤 단어장·선택형 회고·레시피로 확장한다. 기록 개수와 전문 표현을 요구하지 않는다.
- **데이터 보존·이동성**: `customTags` 보존 결함을 먼저 해결하고, 로컬 초안 보호·명시적 장기 저장·전체 백업·개별 내보내기·복원을 설계한다.
- **성능·PWA·오디오**: 백그라운드 완료 신호 예약과 폰트 셀프호스팅을 검토한다. 구현된 렌더 예산·자산 지연 로딩·캐시 분리·iOS 오디오 복구를 회귀 검증한다.
- **도움말·설정·언어**: 실제 구현과 설명을 일치시키고, 대만 실사용을 위해 번체 중국어를 먼저 지원한다. 나머지 다국어와 문화권별 생활 표현은 후속으로 추가한다. 설명을 읽지 않아도 기본 우림이 가능해야 한다.

### UI 확장 설계 — 배치 결정·기능 구현 대기

2026-08-31에 기능별 진입점과 아이콘·문구 기준을 [화면 배치와 메뉴 표현](design-navigation.md)으로 분리했다. 기능의 화면 내용·저장 모델·실기기 결과까지 확정한 것은 아니며 Phase 순서와 미구현 상태는 유지한다. 현재 시트 접근성 안정화는 Phase A에서 별도로 진행한다.

- **메인**: 좌상단 우림 끝, 우상단 언어+메뉴, 중앙 타이머, 푸터 소리·차 느낌을 유지한다. 하단 탭·상시 기록 아이콘·개수 배지는 추가하지 않는다.
- **목적지**: 기록함·단어장·레시피 / 공지사항·이용 안내·설정 순서의 메뉴에 구현된 기능만 노출한다. 빈 기록함도 접근 가능하며 첫 저장이나 기록 개수로 메뉴를 잠그지 않는다.
- **맥락 진입**: 느낌 시트 안 단어장, 기록함 안 회고, 완료 기록의 레시피 작성, 설정의 전체 백업·복원을 배치한다. 입력 중 단어장을 열어도 같은 문서에서 초안을 유지하고 돌아온다.
- **표현 기준**: 목적지는 아이콘+이름, 행동 결과는 문구, 맥락이 분명한 작은 조작은 아이콘만 쓴다. 구체적 항목별 기준과 접근성 이름은 상세 설계에 둔다.
- **구현 검증**: 375×660 및 320px, 한국어·번체, 44px 터치 영역·포커스·타이머와 초안 보존을 기능별로 검증한다. 탭은 반복 왕복의 실제 필요와 공간 검증을 근거로만 재검토한다.

TW-05에는 언어 선택·기본 메뉴와 [공지사항](design-navigation.md#announcements)을 반영한다. 공지는 실제 업데이트와 예정 사항을 구분하며 큰 UI 개편 뒤 위치 안내를 제공한다. TW-08에서 첫 공지와 실제 배포 내용의 일치·오프라인 표시를 확인한다. 아래 Phase B·C·E·F·Later의 기능은 각각 도입할 때 이 배치를 적용한다.

### 천천히 볼 것

- 차 커스텀 등록, 긴 우림 기록, 번체 중국어 이외의 다국어는 핵심 타이머 경험이 안정된 뒤 확장한다. 번체 지원은 현재 우선 처리 묶음에서 먼저 진행한다.
- 데이터 관리 기능은 화면 밀도와 조작 복잡도를 크게 늘릴 수 있으므로, "차를 우리던 흐름"을 방해하지 않을 때만 추가한다.
- `[차 열 잔의 기록]`은 장기 기록을 명시적으로 남긴 사용자에게 제안하는 선택형 회고다. 기록함 메뉴 자체는 빈 상태에서도 유지하고 열 잔 이후 기록함 안에서 조용히 안내한다. 회고 내용과 구체적 연출은 Phase F에서 검증한다.
- 개인 감각 단어와 우림 재사용은 후속 단계로 검토하고, 커뮤니티/SNS는 비목표로 둔다. 사용자가 직접 내보내는 카드 공유는 유지한다.

### 피할 것

- 차 전문 앱처럼 모든 것을 이 앱 안에서 관리하려는 방향.
- 일반 생산성 타이머처럼 범용 기능을 늘리는 방향.
- 차 정보 백과, 긴 기록장, 복잡한 통계처럼 짧은 우림 흐름을 밀어내는 기능.
- 작은 모바일 화면에서 장식만 늘어나고 신호성은 떨어지는 시각 요소.
- 필수 계정, 클라우드 동기화를 기본 책임으로 삼기, 차 재고·구매처·가격 관리, 커뮤니티/SNS.
- streak·목표 진행률·레벨·업적, AI 취향 판정, 사용자를 붙잡기 위한 푸시 알림.

## Phase A — 현재 기능 안정화와 핵심 타이머 완성

현재의 `관찰(김·찻잎·탕색) → 준비(예고음·임박 강조) → 행동(완료음·실제 출탕)` 흐름을 우선한다. 기록 시트와 카드 export는 이미 구현됐으므로 재구현 항목으로 되돌리지 않고 알려진 결함부터 안정화한다.

아래 번호는 기존 Phase A 내부 순위를 보존한 것이다. 현재 착수 순서는 상단의 [대만 실사용 우선 처리](#taiwan-priority)가 우선하며, Phase A 전체 완료를 번체 지원의 선행 조건으로 삼지 않는다. `차 느낌 MVP 안정화`는 TW-01·02·03으로 나눠 확인한다.

### 다구·우림법 확장 원칙

- 모양만 다른 다구보다 우림 행동이나 찻잎·찻물 분리 방식이 다른지를 먼저 본다.
- 향후 모델은 `vessel`, `brewingMethod`, `separationMethod`를 구분한다. 개완·다호·티팟의 `pour`, 표일배의 `drain`, 티백·바스켓의 `lift`, 잎을 그대로 두는 머그의 `none`은 개념 예시다.
- 현재 구현은 모든 다구에 출탕 단계를 제공한다. `lift`·`none`이나 우림법 선택 UI가 구현됐다는 뜻은 아니며, 현재 다구 ID와 호환되는 전환 설계를 먼저 정한다.

## Phase B — 기록 기반 확장 · 미구현

현재 세션 요약·태그·메모·텍스트/PNG export 위에 장기 기록 기반을 추가하는 단계다.

1. 차·다구·감각 태그의 canonical ID와 표시 문자열을 분리한다. 기존 ID·커스텀 태그는 보존·이관 경로를 먼저 정한다.
2. Tea Session 모델에서 앱이 관찰한 값, 사용자가 입력한 값, 추천값을 구분한다. 앱의 선택 이력을 실제 물리 상태 측정으로 간주하지 않는다.
3. 설정은 localStorage에 두고 장기 사용자 자산은 IndexedDB의 `sessions`, `vocabulary`, 이후 `recipes`를 기본 후보로 한다.
4. **타이머 사용 ≠ 기록 의사.** 입력을 시작한 초안은 보호하되 장기 기록은 `브라우저 기록으로 남기기` 같은 명시적 행동으로 확정한다. 초안의 저장 위치·복원·삭제 경계는 별도 결정한다.
5. 찻잎 g·물 ml·실제 수온은 접힌 선택 입력으로 검토한다. 권장 수온을 실제 수온으로 채우지 않는다.

기록함과 명시적 저장의 진입점은 [배치 설계](design-navigation.md)를 따른다. 기록함은 첫 저장 전에도 메뉴에서 열 수 있고, 메인 차 느낌 버튼은 현재 세션 작성만 담당한다.

기존 `teaTimer.cups.v1` 최근 10장·초과분 자동 삭제 제안은 현행 계획에서 제외한다. 10은 회고 시점이며 보관 상한이 아니다. 보관량과 삭제 정책은 사용자 자산 보호·백업과 함께 별도 결정한다.

## Phase C — 데이터 이동권 · 미구현

상세 원칙은 [data-portability.md](data-portability.md), 설정의 전체 백업·복원과 기록 상세의 개별 내보내기 배치는 [배치 설계](design-navigation.md)를 따른다.

- 세션·개인 단어·커스텀 태그·향후 레시피를 사용자 자산으로 보고 전체 JSON 백업/복원을 제공한다. 기본 프리셋·번역·기본 단어장은 재생성 가능한 앱 자산으로 분리한다.
- Tea Session과 개인 단어장은 개별 JSON·Markdown으로 내보낼 수 있게 한다. 현재 Plain Text/PNG는 빠른 공유용으로 유지한다.
- 공개 스키마는 UI 인덱스가 아니라 차 경험을 표현해야 한다. 실제 JSON Schema 파일은 모델 안정화 후 만든다.
- 우선 자체 백업 복원을 검증하고, 외부 호환 import는 스키마 안정화 후 연다. 버전·검증·마이그레이션을 함께 설계한다.

## Phase D — 다국어 · 공통 기반과 번체 문구 구현, 로컬 검증 완료

### D-1 — 번체 중국어 선행 지원

한국어를 유지하면서 대만 표현 기준의 번체 중국어를 먼저 추가한다. Phase B·C보다 앞서 Phase A 핵심 안정화와 함께 진행하며, 실행 범위·완료 확인·선행 결정은 [현재 우선 처리의 TW-05–08](#taiwan-priority)을 따른다. 장기 저장이나 전체 사용자 자산 스키마 완성을 요구하지 않는다. 기본 문자열 분리·태그 호환·사용자 원문 보존은 이 단계에 필요한 최소 기반이다.

### D-2 — 나머지 언어 확장

영어·중국어 간체·일본어는 D-1 실사용 검증 이후 검토한다. 개인 단어장 등 아직 구현되지 않은 기능의 번역은 해당 기능 구현 때 추가한다.

### 공통 원칙

- 목표 언어는 한국어·영어·중국어 번체·중국어 간체·일본어다.
- canonical ID는 언어와 무관하게 유지하고 표시 문자열을 분리한다. 차 문화 용어와 생활 예시는 문화권에 맞게 현지화한다.
- 개인 단어와 메모는 원문을 보존하고 자동 번역으로 덮어쓰지 않는다.
- 번역할 문구 자체를 줄이고 언어를 읽지 않아도 핵심 우림 흐름이 전달되게 한다.

## Phase E — 향과 맛의 단어장 · 미구현

차 느낌 작성 중 직접 입력한 단어를 이번 카드에 선택하고 설정에도 저장하는 소규모 보강은 [구현·로컬 검증 후 통합했다](CHANGELOG.md#feeling-inline-tags). 아래 참고용 단어장 탐색·설명 페이지의 구현 완료를 뜻하지 않는다.

상세 설계는 [sensory-vocabulary.md](sensory-vocabulary.md), 느낌 시트의 맥락 진입과 메뉴의 독립 탐색은 [배치 설계](design-navigation.md)를 따른다.

조사·결정: [대만 특색차 풍미륜 1.0·2.0과 기본 14개 비교](research-taiwan-tea-flavor-wheel.md), [한국어 후기 및 최종 15개·출처](research-korean-tea-review-vocabulary.md#confirmed-vocabulary). 기본 15개는 TW-05 설정 검토에서 먼저 적용했고 기존 목록·ID 보존을 검증했다. 세부어 분류·번체 문구·해설·이용 범위와 단어장 탐색·추가 구현은 남아 있다.

- 차 느낌에서 표현이 막힐 때만 선택적으로 여는 작은 도움말이다. 전문 시음 정답이나 필수 교육 과정이 아니다.
- [기본 15개 확정 목록](sensory-vocabulary.md#default-vocabulary): 향 5개·맛 5개·입안 감각 5개의 기본 제공은 적용했다. 구운 향은 향에, 텁텁함은 입안 감각에 둔다. 기존 저장 목록은 자동으로 바꾸지 않는다. 후속 탐색에서 세부 표현을 참고해 추가하고, 생활 예시와 자기 표현을 자유롭게 확장하는 방향을 유지한다.
- 개인 단어장은 기본 단어와 분리한 사용자 자산으로 저장·백업한다. 현재 커스텀 태그 목록만으로 단어장이 구현됐다고 보지 않는다.
- 단어 수집률이나 취향 평가 대신 사용자가 자기 기억에 빗대어 표현하게 돕는다.

## Phase F — 차 열 잔의 기록 · 미구현

- 열 잔은 목표가 아니라 자연스럽게 쌓인 기록을 돌아보는 발견 시점이다.
- [배치 설계](design-navigation.md)에 따라 열 잔 이후 기록함 안에서 `지난 차 돌아보기`를 조용히 안내한다. 홈의 찻잔 아이콘·개수 배지나 설정 토글로 해금하는 방식은 채택하지 않는다.
- `7/10`, 진행률, `3잔 남았어요`, streak는 쓰지 않는다.
- 자주 선택한 감각어·다구, 첫 기록과 최근 표현, 새 개인 단어와 문장을 보여준다. `열 잔 중 여섯 잔에서 꽃향을 골랐어요`처럼 사실만 제시하고 AI 취향·성격 판정을 하지 않는다.
- 열 잔 회고를 열기 위해 기록을 자동 삭제하거나 보관량을 열 장으로 제한하지 않는다.

## Later / Experiment — 나의 레시피북

맛있게 마신 우림 순서를 `이 우림 기억하기`로 남기고 다음에 `이대로 준비하기`로 불러오는 방향을 검토한다. 메뉴에 독립 레시피 진입점을 두며 불러오기만으로 우림을 자동 시작하지 않는다. [배치 설계](design-navigation.md)를 따르며 목적은 재고·구매 관리가 아니라 반복되는 자기 방식을 덜 귀찮게 불러오는 것이다.

`50잔` 같은 해금 기준은 확정하지 않는다. 이전 `[차 백 잔의 창고]`는 현재 단계별 계획에서 제외하며, 기록 개수에 따른 등급이나 대형 기록장 확장의 약속으로 쓰지 않는다.

## `[이번 차의 느낌]` 기능 방향

상세 설계는 [design-tea-feeling.md](design-tea-feeling.md)에서 관리한다. 요지만 남긴다.

- 차 정보 백과나 긴 기록장이 아니라, **한 잔을 마신 직후의 감각을 오래 기억하게 돕는 작은 시음 카드**다.
- 현재 푸터의 노트 버튼은 항상 보이지만 시트가 자동으로 열리지는 않는다. 사용자가 직접 열어 감각 태그 + 자기만의 비유 한두 줄 + 자동 포별 시간 요약을 카드 이미지·텍스트로 export한다. 기록 단위는 포별이 아니라 세션 전체 한 장이다.
- 초안은 현재 실행 중인 세션 메모리에만 있고 `우림 끝`·새로고침·앱 재실행 뒤에는 복원되지 않는다. 영구 보관은 사용자가 선택한 export가 담당한다.
- IndexedDB 장기 기록과 `[차 열 잔의 기록]`은 현재 MVP와 분리한 미구현 확장이다. 커스텀 태그 저장 병합은 TW-01, 시트·카드 접근성은 TW-02에서 반영했으며 초안·세션 경계는 TW-03에서 반영했다.
- 점수화·복잡한 통계·전문가식 정답 강요는 하지 않고, 기본 흐름은 끝까지 타이머에 집중한다. 회고에서 단순한 선택 빈도를 사실대로 보여주는 것과는 구분한다.
- 기록 입력이 시작된 초안 보호와 명시적 장기 저장을 구분한다. 현재 메모리 초안이 이미 IndexedDB에 보관되는 것으로 설명하지 않는다.

## 점검 메모

- 차 캐러셀 스와이프를 구현하면 버튼 접근성과 충돌하지 않는지 확인한다.
- 백그라운드 완료 신호 예약은 실제 모바일 브라우저와 설치형 PWA에서 앱 전환·화면 잠금 중에도 완료 신호가 늦지 않는지 우선 확인한다. 현재 절대 시각 보정은 복귀 후 화면 상태를 맞추지만, 백그라운드 중 소리를 선예약하지는 않는다.
- iOS 오디오 복구는 다른 앱·통화·미디어 재생으로 인터럽션을 만든 뒤 앱에 돌아와 현재 포와 다음 포의 예고음·tick·완료음이 모두 다시 나는지 회귀 점검한다.
- 우림 중 즉시 멈춤은 숨은 long-press에만 기대지 말고, 사용자가 차 색이나 향을 보고 바로 "지금 따르기"를 이해할 수 있는지 확인한다.
- 완료 플래시 대비는 reduced-motion 외에도 완료 메시지 가독성을 실제 화면으로 재검증한다.
- 폰트 셀프호스팅 후 fallback과 글자폭 변화가 모바일 레이아웃을 흔들지 않는지 확인한다.
- 아이콘을 다시 바꾸면 `icons/icon-source.jpeg`를 교체하고 `python3 scripts/generate_icons.py`로 PNG 세트를 재생성한 뒤 `sw.js` 캐시 버전을 올린다.
- `[이번 차의 느낌]`은 자동으로 열지 않는다. 시트·카드가 닫힌 동안 포커스 순서에서 제외되는지, 열 때 dialog 의미와 포커스 이동·복귀·Escape 닫기가 동작하는지 확인한다.
- 태그 칩의 시각 크기는 조밀하게 유지할 수 있지만 유효 터치 영역은 44px 이상이어야 한다.
- 설정 페이지에서 커스텀 태그를 바꾼 뒤 메인에서 차·다구·시간·음소거를 변경해도 태그가 보존되는지 확인한다.
- 첫 우림 전에 작성한 초안이 차·다구 변경과 어떻게 결합되는지 명시하고, 다른 차의 카드로 초안이 의도치 않게 넘어가지 않게 한다.
- 사용자 자산 스키마 변경 시 기존 ID·태그·기록의 이관과 export/import 호환성을 먼저 검토한다.
- 단어장·회고·레시피가 생겨도 첫 화면의 입력 밀도를 높이거나 기록 개수를 목표로 제시하지 않는다.
