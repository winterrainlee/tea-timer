# 한국어·대만 번체 중국어 — 설계

> 결정일: 2026-08-31
> 상태: **TW-06 번체 카탈로그·언어별 기본 단어 구현·로컬 검증·통합 완료**. 검증·통합 결과는 [TW-06 기록](CHANGELOG.md#tw-06-traditional-chinese)을 따른다. TW-07 카드 조판은 구현·로컬 검증했고 실기기 글꼴 확인과 TW-08 실기기·PWA 검증은 남아 있으며 현지인 문구 검수는 배포 후 진행한다.
> 범위: [ROADMAP의 대만 우선 처리](ROADMAP.md#taiwan-priority). 설정 저장은 [데이터 보존 계약](data-portability.md#preferences-contract), 초안은 [차 느낌 설계](design-tea-feeling.md#draft-policy)를 따른다.

## 1. 목표와 제외 범위

기존 타이머와 선택적 기록을 대만에서 함께 차 마시는 사람이 쓸 수 있게 한다. 기존 차·다구 ID, 보정값, 사용자 차 이름·태그·메모를 보존한다. [배치 설계](design-navigation.md)에 따라 메인 우상단에 언어 선택을 추가하고 기존 사용법 자리를 공지사항·이용 안내·설정 메뉴로 바꾼다. 공지 UI와 정적 공지 내용도 두 언어로 제공한다. 그 외 메인 탭·기능 아이콘 증설, 프레임워크 전환, 장기 기록·백업, 영어·간체·일본어 지원은 도입하지 않는다.

## 2. 언어 선택과 적용

현재 한국어·번체 및 후속 간체·일본어·영어의 표시 줄바꿈은 [공통 UI 기준](ui-guidelines.md#locale-line-breaking)을 따른다. 후속 언어의 사전 규정이며 이번 구현의 지원 locale을 추가하는 변경은 아니다.

- 지원 locale은 `ko`와 `zh-TW`다. `zh-TW` 카탈로그는 대만 표현 기준의 번체를 사용한다. 메인 우상단의 `언어 아이콘 + 한국어/繁體 + ▾`에서 `한국어` / `繁體中文（台灣）`를 각 언어의 원어로 표시한다. 설정 화면 상단에서도 같은 선택값을 관리한다. 설정에서만 선택하던 착수 전 정책을 확장한 결정이다.
- 기억한 유효 locale을 우선하고, 선택이 없거나 지원하지 않는 값이면 한국어로 표시한다. 첫 버전에서는 브라우저 언어 자동 감지를 하지 않는다. 기존 한국어 기본값을 유지하고 사용자의 명시적 선택만 기억한다.
- `locale`은 preferences v1의 선택 필드다. 언어만 바꿀 때 다른 선호값을 다시 저장하거나 세션을 초기화하지 않는다. 저장 실패 시 화면 적용과 기기 기억 실패를 구분해 알린다.
- 메인과 설정 모두 선택 즉시 문구와 `html lang`을 갱신하되 문서 전체 reload를 하지 않는다. 메인의 명시적 전환은 우림 중에도 가능하며 타이머·차·다구·태그·초안·완료 포를 유지하고 완료음을 재실행하지 않는다. IME 조합·공유 스냅샷 생성 중에는 해당 작업을 마친 뒤 적용한다. 다음 문서를 열 때도 같은 선택을 읽는다. 번체 페이지의 `html lang`은 `zh-TW`다.
- 다른 탭에서 언어를 바꿨을 때 활성 세션의 메인 화면은 현재 언어를 유지한다. 아래의 안전한 idle 상태에 도달하면 대기한 최신 선택으로 문구만 갱신한다. 차·다구·시간·음소거를 초기값으로 되돌리지 않는다.

<a id="navigation-policy"></a>

### 2.1 진행 중 상태와 페이지 이동

현재 도움말·설정은 별도 HTML 문서이므로 **현재 문서를 떠나는 앱 내부 이동을 안전한 idle 상태까지 유예**한다. 같은 문서에서 열리는 언어 선택과 전역 메뉴 자체, TW-05의 공지사항 읽기에는 이 제한을 적용하지 않는다. 공지는 [상태 보존·복귀 정책](design-navigation.md#announcements)을 따른다. 설정 전체를 메인으로 옮기는 대규모 재구성은 하지 않는다.

- 안전한 상태는 `phase === idle`, 완료 포 없음, 내용 있는 초안 없음, 다구 이미지 전환·제목 편집·IME 조합 중 아님을 모두 충족할 때다.
- 그 외에는 기존 `사용법` 링크, TW-05 이후 메뉴의 `이용 안내`·`설정`으로 현재 문서를 떠나지 않는다. `우림과 느낌을 유지하고 있습니다. 필요한 느낌을 내보내고 [우림 끝]을 누른 뒤 이동할 수 있습니다.`라는 비차단 상태 안내를 제공한다. 자동 종료·자동 삭제나 뒤로 가기 복원에 의존하지 않는다.
- 이동은 자동 예약하지 않는다. 안전한 상태가 된 뒤 사용자가 다시 링크를 눌러야 한다. 완료 후 다음 포 대기 중에도 완료 기록이 있으므로 같은 보호를 적용한다.
- 이 보호는 TW-03에서 초안/세션 경계와 함께 반영했다. TW-05에서 언어 전환을 연동한다. 진행 중 도움말 열기가 제한되는 비용을 받아들이며, 우림 중 도움말이 필요하다는 실사용 피드백이 있으면 같은 문서에서 읽는 방식을 후속 검토한다.
- 새로고침·브라우저 종료·OS 종료에 대한 복구 보장은 이번 범위가 아니다. 브라우저의 새 탭 열기 등 메인 문서를 유지하는 동작까지 임의로 세션 종료로 취급하지 않는다.

## 3. 표시 문자열과 데이터

- 차·다구 ID, 권장 시간·온도·색·자산 경로·동작 속성은 언어와 분리한다. 메인과 설정이 같은 차 ID 집합을 사용하고 TW-01 별칭 호환을 유지한다.
- 정적 HTML, 상태별 버튼, 토스트, 시간·포 수, 도움말·설정 설명, 공지 제목·상태·본문, 접근성 라벨, 텍스트 복사, 카드 DOM/Canvas, Web Share 제목을 번역 키로 관리한다. `t(key, vars)` 수준의 작은 공용 조회 계층을 사용하고 언어별 문자열 조합을 타이머 로직에 흩어 두지 않는다.
- 누락 키는 한국어로 폴백하며 타이머를 막지 않는다. 정상 배포에서는 두 카탈로그의 키와 치환 변수가 일치해야 한다. 폴백이 있다는 이유로 미번역을 완료로 처리하지 않는다.
- 차종 이모지는 번역 이름의 정규식이 아니라 기존 차 ID로 정한다. 사용자 편집 제목은 표시만 바꾸며 차종이나 권장값을 바꾸지 않는다. 제목 원문에 이미 포함된 이모지를 언어 전환으로 제거·중복 추가하지 않는다.
- 사용자 차 이름·태그·메모는 번역·일괄 정규화하지 않는다. 언어 선택으로 입력값, 선택 태그의 정체성, 초안, 포 기록이 바뀌어서는 안 된다.

<a id="tag-compatibility"></a>

### 3.1 기본 태그와 기존 문자열 호환

이 절은 TW-05에서 도입한 저장·호환 계약이다. TW-06의 기본 목록 선택과 builtin 원문 표시는 [§7.4의 언어별 독립 기본 목록](#locale-default-vocabulary)을 따른다. 기존 목록·ID·원문 보호는 유지하며, 공통 builtin의 표시 번역은 더 이상 사용하지 않는다.

기본 태그는 안정된 ID로, 사용자 입력은 literal 원문으로 구분한다. 아래 `tagItems`는 TW-05에서 도입한 preferences v1의 선택 필드다. TW-01에서는 생성하지 않고 알 수 없는 필드로 보존할 수 있어야 한다.

```js
tagItems: [
  { kind: "builtin", id: "taste.sweet" },
  { kind: "custom", text: "빙탕 같은 단맛" }
]
```

- 태그 필드가 없으면 [확정한 기본 15종](sensory-vocabulary.md#default-vocabulary)을 ID 목록으로 화면에 제공한다. 일반 설정 저장 때문에 기본 태그 표시 문자열을 `customTags`에 기록하지 않는다. 저장된 기존 목록은 자동 교체하지 않으며 이전 14개 ID도 계속 지원한다. 전체 ID/번역 키 표는 아래 §6에 둔다.
- 기존 `customTags: string[]`만 있으면 **모든 항목을 custom 원문**으로 읽는다. 기본 목록과 같은 문자열도 출처를 추정하지 않는다. `[]`는 빈 목록이고 없는 필드와 다르다.
- 유효한 `tagItems`가 있으면 그것이 편집 목록의 기준이다. 없으면 기존 `customTags`, 그것도 없으면 기본 ID 목록 순서로 읽는다. 태그를 명시적으로 편집할 때만 현재 항목 목록을 `tagItems`로 쓴다. 기존 `customTags`는 호환 원본으로 남기며 자동으로 번역하거나 동기화해 덮어쓰지 않는다.
- 추가한 단어는 custom, 기본 태그 선택은 builtin으로 유지한다. 사용자가 기본 태그와 같은 문구를 입력해도 ID 항목으로 바꾸거나 기존 항목과 자동 병합하지 않는다. 세션 선택도 화면 문자열만으로 비교하지 않는다.
- 선택 식별자는 builtin의 경우 `(kind, id)`, custom의 경우 `(kind, 원문 text)`의 쌍이다. 새 custom 입력 중 원문이 정확히 같은 중복은 거부하지만 builtin과 같은 표시 문구는 허용하고 `내 단어` 보조 표기로 구분한다. legacy에 동일 custom 원문이 반복되면 원본 배열은 자동 정리하지 않고 같은 논리 단어로 표시·선택한다. 그 단어의 명시적 삭제는 반복 항목 전체에 적용한다.
- `기본 단어로 복원`은 현재 목록을 기본 ID 15종으로 대체하는 명시적 동작이다. 개인 단어가 목록에서 제거됨을 알리고 취소 가능한 확인 후 적용한다. 취소하면 저장값과 화면 모두 그대로다. 전체 초기화 시에는 `tagItems`와 `customTags`를 함께 지운다.
- 지원하지 않는/손상된 `tagItems`는 자동 덮어쓰기하지 않는다. 읽을 수 있는 legacy 목록 또는 기본 목록을 임시로 표시하고 복원 안내를 제공하며, 태그 편집은 명시적 기본 복원 전까지 유예한다. 다른 설정은 공통 저장 계약에 따라 계속 쓸 수 있다.
- 호환 fixture에는 한국어에서 같은 문구로 보이는 builtin/custom의 독립 선택·삭제, legacy custom 중복, `tagItems: []`, 손상된 `tagItems`를 둔 채 음소거/시간 저장 후 raw 보존을 포함한다.
- **의도한 예외:** 기존 사용자의 한국어 기본 문자열도 번체 화면에서 원문으로 남을 수 있다. 이것은 미번역 UI가 아니라 사용자 자산 보존이다. 현재 화면 언어의 독립 기본 목록을 원하면 명시적 복원 경로를 사용한다.
- 업데이트 전 구버전 앱과 새 태그 목록의 양방향 동시 편집은 보장하지 않는다. SW 업데이트·열린 페이지 재진입을 TW-08에서 확인하며, 새 번역 지원을 구버전 앱의 데이터 보호까지 소급 보장하는 것으로 설명하지 않는다.

## 4. 제품명·공유·글꼴

- 제품명 `차 한 잔의 시간 · Time for Tea`와 설치 단축명 `차 한 잔`을 유지한다. 이번에 중국어 제품명을 새로 만들지 않는다. manifest의 이름·한국어 설명·`lang: ko`는 고정 메타데이터로 두고, 언어 선택으로 설치명을 동적으로 교체하지 않는다.
- 페이지 제목은 현지화한 화면명과 기존 제품명을 함께 사용한다. 텍스트/PNG의 기록 제목·일반 설명·Web Share 제목은 선택 언어로 표시하되 제품명은 고정한다. 파일명은 언어에 무관한 `tea-feeling-<날짜>.png`를 유지한다.
- 제품명·고유명·사용자 원문·단위·의도한 `泡` 보조 표기는 혼용 검사에서 구분한다. 그 밖의 미번역 앱 문구는 누락으로 처리한다.
- 한국어의 기존 서체 방향을 유지하면서 번체를 표시할 수 있는 시스템 CJK 폴백을 CSS와 Canvas에 함께 지정한다. 특정 기기의 폰트 설치나 외부 폰트 다운로드 성공을 가정하지 않는다. 구체적 폰트 스택은 TW-05 사전 렌더와 TW-07 기기 확인으로 선택한다.
- PNG export는 사용할 글꼴의 준비를 확인하고 로딩 실패/지연 시 정해진 폴백으로 그린다. 폰트 대기가 타이머를 정지시키거나 export를 무기한 막아서는 안 된다. 혼합 입력·긴 입력의 글자 누락, 줄바꿈, 생략 정책을 원본 PNG로 확인한다.

## 5. 캐시·검증·배포 경계

- 공용 JS·번역 카탈로그 등 로컬 런타임 자산은 도입 단계부터 SW 사전 캐시와 오프라인 로딩에 포함한다. 문서 변경만으로 캐시를 올리지 않는다. 현재 캐시 버전은 `sw.js`를 기준으로 확인한다.
- TW-05에서 한국어 기반을 먼저 적용·검증하고 TW-06에서 번체 문구를 완성한다. TW-02·03의 새 문구와 입력/삭제 안내도 번역 범위다. [보류한 TW-04](DESIGN.md#early-pour-policy)의 조기 출탕 문구는 제외하며 TW-05 착수의 선행 조건으로 두지 않는다. TW-07은 실제 문구가 합쳐진 버전으로 다시 확인한다.
- 배포 버전의 HTML·공용 JS·카탈로그가 서로 다른 버전으로 섞여 깨지지 않는지 기존 SW에서의 업데이트와 오프라인 재실행으로 확인한다. 단순 캐시 번호 증가만으로 검증을 대신하지 않는다. 업데이트를 이유로 진행 중 페이지를 강제 reload하지 않는다.
- **필수 검증:** 두 언어의 키·치환 변수 일치, 누락 키 폴백, 선택 기억, 설정 보존, 사용자 원문 불변, 레거시/신규/빈 태그, 메인에서 우림 중 명시적 언어 전환, IME·공유 중 적용 유예, 메뉴와 언어의 포커스 복귀, 진행 중 문서 이동 차단, 다른 탭의 언어 변경 유예, 정상 완료→출탕→다음 포→기록·공유 흐름. 정상 완료·출탕·다음 포·세션 종료의 중복 처리 방지는 유지하고 조기 출탕은 검증 범위에서 제외한다.
- **화면·실기기:** 375×660 화면, 680×900 PNG, 번체·한국어·이모지 혼합 입력, 폰트 네트워크 차단, 모바일 브라우저·설치형 PWA의 오디오 복귀·오프라인 셸·캐시 갱신을 확인한다. 실제 대만 표현 검토와 실기기 결과는 아직 수행하지 않았다.

TW-06에서 승인된 번체 초안과 독립 기본 단어 목록을 실제 화면·공유 경로에 적용했다. 로컬 검증 결과는 변경 이력에 기록하며, 긴 입력의 A안 조판은 TW-07에서 구현·로컬 검증했다([기록](CHANGELOG.md#tw-07-balanced-card)). 실제 모바일 글꼴·공유 검증은 남겨 둔다.

### 5.1 이번 번역 적용과 현지인 검수 시점 — 사용자 확정

**2026-08-31 사용자 결정:** 이번 구현에는 작성한 번체 초안을 그대로 사용하고, 버전 배포 후 현지인에게 실제 내용을 검수받는다. 사용자가 수정한 `茶壺` 등의 표현은 반영한다. 현지인 검수는 TW-06 구현·통합이나 이번 버전 배포의 선행 조건으로 두지 않는다. 개별 초안에 대해 현지인 검수 전이라는 이유만으로 반복 승인을 요청하지 않는다.

배포 전에는 번역 키·치환 변수·문구 누락·의도치 않은 혼용·동작 의미의 일관성과 로컬 화면·기능·데이터 검증을 수행한다. 이후 사용자 결정으로 HTTPS 실기기 검증은 [GitHub Pages 배포 후](#pages-device-validation)에 수행한다. 검증 시점을 옮긴 것이 필수 검증의 면제를 뜻하지 않는다. 배포 기록에는 현지인 검수 전과 실기기 미검증 범위를 구분하고, 검수 후 표현 수정은 후속 업데이트에서 반영한다. 실제 구현·검증·배포 완료 표시는 각각 수행 결과를 확인한 뒤 갱신한다.

## 6. TW-05 당시 구현 경계와 검토 순서 — 과거 기록

2026-08-31 사용자와 한국어 실제 화면을 먼저 검토한 뒤 TW-06 번체 화면·핵심 문구를 검토하기로 합의했다. TW-05 기능 브랜치는 `codex/tw-05-localization-foundation`이다. 이 단계에서는 공통 번역 조회와 한국어 카탈로그를 메인·설정·사용법·공지·공유에 적용한다. `zh-TW` 선택·저장·상태 보존 경로는 준비하되 미완성 번체 문구는 한국어 폴백을 사용하고 언어 선택 영역에 다음 단계 적용 안내를 표시한다. 한국어 검토는 마쳤으며 통합 상태는 마감 기록을 따른다. 번체 지원 완료나 배포 준비 완료를 뜻하지 않는다.

- 한국어 카탈로그는 공통·메인과 설정·사용법으로 나누고 `t(key, vars)`로 조회한다. HTML은 명시적 번역 속성을 가진 텍스트·접근성 속성만 갱신하며 입력값·노드 전체를 언어 전환으로 재생성하지 않는다.
- 새 언어 선택은 `locale` 필드만 저장한다. 직접 선택의 IME/공유 작업 대기와 다른 탭 변경의 안전 idle 대기를 구분하며, 세션 종료 후 최신 대기 언어를 적용한다.
- 첫 공지는 우선 `예정된 업데이트` 초안으로 제공한다. 한국어 검토 단계의 기능을 이미 배포한 업데이트로 적지 않으며 실제 배포 공지는 TW-08에서 버전과 내용이 일치하는지 다시 확인한다.
- 글꼴 후보는 `Gowun Batang`, `Noto Serif TC`, `Songti TC`, `PMingLiU`, `AppleMyungjo`, `serif` 순으로 화면과 Canvas에 사용한다. 기존 외부 글꼴 외에 새 원격 글꼴 의존성을 추가하지 않는다. 이 스택으로 혼합 문장의 일반/외부 글꼴 차단 PNG 사전 렌더를 확인했다. 실제 모바일 글꼴과 긴 내용 조판은 최종 TW-07에서 다시 검증한다.
- 한국어 실제 화면 검토에서 공지 계층·자동 이력 분류, 설정 순서·언어 라디오·기본 15개, 공통 UI 기준, 이용 안내·여운 명칭을 반영했고 사용자가 TW-05 마감을 확인했다. TW-06 전체 번체 적용은 별도 착수하며 후속 장기 기록 기능은 포함하지 않는다.

### 7.1 핵심 행동·말투 — 이번 구현 적용안·현지인 검수는 배포 후

**2026-08-31 사용자 확정:** 말투는 **차를 처음 마시는 친구에게 건네는 짧고 차분한 안내**다. 버튼에는 짧고 행동이 보이는 생활어를 쓰고, 도움말은 편안한 설명체로 쓴다. `請`·`您`·감탄사·문장 끝 조사 등을 일괄 추가하지 않는다. 삭제·저장 실패·초안 수명은 부드러운 분위기보다 동작 결과를 분명히 전달한다.

**한국어 요청 표현:** 사이트 안내의 `-십시오`는 자연스러운 `-주세요` 형태로 쓴다. 금지 안내는 `적지 말아 주세요`처럼 바꾸며, 설명·상태 문장의 `-습니다`는 유지한다. 사용자 입력 원문과 번체 문구는 이 한국어 말투 변경의 대상이 아니다.

사용자는 아래 번역 초안을 이번 구현에 그대로 사용하고 실제 번체 내용은 버전 배포 후 현지인에게 검수받기로 했다. 현지인 검수 완료를 뜻하지 않으며, 이후 검수에서 표현을 다듬어도 한 포의 완료·세션 종료·임시저장의 동작 의미는 유지한다.

| 한국어/역할 | 번체 검토 초안 | 의미 경계 |
|---|---|---|
| 우리기 시작 | 開始泡茶 | 우림 시작 행동 |
| 우리는 중 | 浸泡中… | 찻잎을 물에 우리는 진행 상태 |
| 곧 따라낼 준비 | 準備倒茶 | 완료 임박 안내. 아직 출탕 완료가 아님 |
| 차 따라내기 | 倒出茶湯 | 일반 다구의 출탕 행동. 표일배·머그 등 도구별 안내는 별도로 검토 |
| 다음 포 우리기 | 泡下一泡 | 같은 차의 다음 회차 시작 |
| 첫 우림 / n번째 우림 | 第1泡 / 第{n}泡 | 회차 표시, 세션과 구분 |
| 권장 우림 시간 | 建議浸泡時間 | 권장값이지 측정한 실제 시간이 아님 |
| 한 포 타이머 완료 안내 | 時間到了 | 시간 도달 알림. 세션 종료나 실제 출탕 완료를 뜻하지 않음 |
| 우림 끝 | 結束泡茶 | 이번 차 세션 전체 종료. 한 포 완료와 구분 |
| 차 느낌 / 이번 차의 느낌 | 喝茶心得 / 這次喝茶的感受 | 향·맛뿐 아니라 분위기와 개인 경험도 담는 선택적 기록 |
| 임시저장 | 暫存 | 현재 페이지의 이번 세션에서만 유지. 영구 저장·다음 실행 복원으로 표현하지 않음 |

안내 문장 예시도 같은 방침으로 이번 구현에 사용하는 초안이다.

- 일반 출탕 다구의 완료 안내: `時間到了，可以倒茶了。` — 시간이 되었으니 차를 따라도 된다는 뜻. 모든 다구에 같은 문장을 강제하지 않는다.
- 입력 안내: `記下喝茶時的感受，也可以寫下當時的心情或身邊的風景。` — 느낌·기분·풍경을 자유롭게 기록하도록 권한다.
- 초안 수명 안내: `暫存的內容只會保留到這次泡茶結束；重新整理頁面或關閉 App 後就會消失。` — 한 포(`這一泡`)가 아닌 이번 세션(`這次泡茶`)임을 구분한다.

용례 참고: [대만 科技大觀園의 泡茶冷熱兩相宜](https://scitechvista.nat.gov.tw/Article/C000008/detail?ID=f417ee80-e75b-44eb-8627-c9e59802c8bf)에서 `泡茶`·`沖泡`·`浸泡`·`第1泡`·`倒出的茶湯` 사용을 확인했다. 차 용어의 사용 예만 참고하며 해당 글의 건강·우림 권장값을 제품에 채택하지 않는다. 위 앱 문장은 자체 작성한 구현용 초안이며, 대만 화자 검수를 마친 번역은 아니다.

### 7.3 감각 태그 — 독립 목록 결정 전의 원어 대응 검토 기록

### 7.4 언어별 독립 기본 단어 목록 — TW-06 구현 계약

2026-08-31 사용자는 기본 단어를 언어별로 따로 제공하고 대만판에는 풍미륜 원어를 사용하며, 선정 기준은 나중에 도입할 참고용 단어장 페이지에서 설명하는 방향을 확정했다. 사용자가 추가하는 단어는 각자의 원문으로 두고 언어 사이의 일대일 번역 대응을 요구하지 않는다. §7.3은 공통 태그를 번역하는 이전 검토안이며 새 기본 목록의 언어 간 대응표로 사용하지 않는다.

전환 동작은 다음 기준으로 구현했다. §3.1의 기존 저장·호환 보호를 유지하며 기본 목록과 원문 표시는 아래 계약을 따른다.

- 기본 제공 목록은 언어별로 독립 구성한다. 한국어는 확정한 생활어 15개를 유지하고, 번체는 풍미륜 원어로 구성한다. 같은 순번에 있다는 이유로 같은 개념·ID로 취급하지 않으며 `텁텁함 ↔ 粗糙` 같은 억지 대응을 만들지 않는다. 번체 목록의 실제 원전 항목 선택은 한국어 단어의 역번역과 구분한다.
- 언어별 기본 단어는 제공한 언어의 원어를 유지한다. 버튼·설명 등 앱 UI의 번역과 사용자가 골라 기록하는 단어를 구분한다. 언어 간 자동 기록 번역은 제공하지 않는다.
- 개인 단어장은 언어별로 별도 저장소를 만들 필요 없이 하나로 유지하고, 한국어·번체·혼합 원문을 모두 허용한다. 사용자 단어의 언어를 추정해 분류·치환하지 않는다.
- 편집한 저장 목록이 없는 초기 상태에서는 선택한 UI 언어의 기본 목록을 제공한다. 이미 편집한 목록·기존 저장값은 언어 전환으로 자동 교체하지 않는다. 해당 언어의 기본 목록으로 명시적으로 복원할 때만 기존 확인 절차를 거쳐 대체한다. 빈 목록도 편집한 목록으로 존중한다.
- 진행 중 선택한 태그·제목·메모는 언어를 바꿔도 원문과 선택 상태를 유지한다. 선택된 단어가 새 기본 목록에 없더라도 시트에서 확인·해제할 수 있게 하며 카드·텍스트에서도 사라지지 않게 한다.
- `TeaTags.label()`은 UI locale과 무관하게 레지스트리에 고정한 원문을 읽는다. 기존 한국어 ID와 신규 번체 ID를 분리하며 기존 ID를 다른 의미로 재사용하거나 기존 사용자 목록을 초기화하지 않는다.

선정 기준·출처를 사용자에게 알리는 위치는 후속 [참고용 단어장 페이지](sensory-vocabulary.md#locale-selection-guidance)로 둔다. 이번 타이머·태그 화면에 언어별 차이 설명이나 대응표를 추가하지 않으며, 단어장 페이지의 구현을 TW-06·07의 선행 조건으로 삼지 않는다. 원전 그림이나 전체 어휘집 탑재도 이번 범위가 아니다. 아래 저장 계약을 먼저 기록한 뒤 구현했으며, 실제 전환과 원문 보존을 전용 회귀 검사로 확인한다.

#### 저장·표시 상세 — 2026-08-31 구현 전에 확정

- 저장 형식은 preferences v1의 기존 `{kind: "builtin", id}`를 유지한다. 기존 25개 한국어 builtin ID는 한국어 원문에 고정하며 번체 UI에서도 자동 번역하지 않는다. 새 번체 기본 단어에는 `tw.` 접두사의 별도 ID를 사용한다. ID에 해당하는 원문은 단어 레지스트리에서 읽고 UI 번역 카탈로그로 치환하지 않는다. 사용자 custom 원문과 기존 `customTags`도 그대로 보존하며 자동 저장 이관은 하지 않는다.
- 번체 첫 기본 목록은 15개로 구성한다. 향은 `青香·花香·甜香·果香·焙香`, 맛은 `鮮·甜·鹹·酸·苦`, 입안 감각은 `清爽·細膩·粗澀·濃稠·餘韻感`이다. [원전 조사 §3](research-taiwan-tea-flavor-wheel.md#3-풍미륜의-단어들은-어떻게-구성되어-있는가)의 표현을 선정한 구현안이다. 마지막 다섯 개는 실제 감각 표현 네 개와 여운 축 이름으로 구성하며 원전 전체 어휘나 공식 추천 15종이 아니다. 한국어 항목과 의미·순번을 대응시키지 않으며, 특히 `細膩`를 `텁텁함`의 번역으로 취급하지 않는다.
- 번체 ID는 순서대로 `tw.aroma.vegetal/floral/sweet/fruity/roasted`, `tw.taste.umami/sweet/salty/sour/bitter`, `tw.mouthfeel.fresh/fine/astringent/full/aftertaste`로 둔다(슬래시 뒤 항목에도 같은 접두사 적용). `tw.` ID의 원문은 한국어 UI에서도 번체로 남는다.
- 명시적인 태그 목록이 없을 때의 읽기·첫 단어 추가·기본 복원은 현재 화면에 적용된 locale을 기준으로 한다. 다른 탭이 저장한 locale의 적용이 유예된 동안에도 눈앞에 보이는 기본 목록에 추가하며, 최신 저장된 개인 목록이 있으면 그것을 우선한다. 언어 저장 실패 시에도 현재 화면의 단어 목록과 추가 동작은 일치해야 한다.
- 언어 전환만으로 기본 목록을 저장하지 않는다. 첫 명시적 편집 때 그 화면의 기본 목록과 사용자 편집 결과를 저장한다. 유효한 저장 목록·빈 목록·손상 목록 보호는 §3.1의 우선순위를 유지한다. 설정의 복원은 해당 화면 언어의 15개로 교체한다고 확인 문구에서 알린다.
- 진행 중 선택한 단어는 현재 기본 목록과 합쳐 시트에서 계속 확인·해제할 수 있게 한다. 제목 편집값·메모·선택 단어 원문·완료 기록을 언어 변경으로 초기화하지 않는다. 실제 번체 적용·키/치환 변수 검증·저장 경계·텍스트/680×900 PNG 결과는 [TW-06 검증 기록](CHANGELOG.md#tw-06-traditional-chinese)을 따른다. A안 카드 조판은 [TW-07 구현·로컬 검증 기록](CHANGELOG.md#tw-07-balanced-card)을 따른다.

### 7.5 검증 환경 — 맥 브라우저·iPhone 13 mini

**2026-08-31 사용자 확인:** 맥에서 카드 배치·미리보기를 확인한 뒤 iPhone 13 mini에서도 잘 표시된다고 보고했다. 이는 카드 화면의 사용자 육안 확인이다. 사용한 브라우저/iOS 버전, 두 언어 전체 조합, 실제 PNG 저장·OS 공유·PWA·오프라인 검증까지 완료한 것으로 확대하지 않는다.

**2026-08-31 검증 전 기기 선택 기록:** 데스크톱은 맥의 브라우저로 확인하고, 로컬 서버를 준비하면 같은 Wi-Fi에 연결한 **iPhone 13 mini**로 접속해 확인한다. 이는 사용할 기기의 결정이며 접속 성공·실기기 검증 완료를 뜻하지 않는다.

- 맥의 브라우저 종류·버전과 macOS/iOS 버전은 실제 검증 시 기록한다. 아이폰은 Safari를 우선 검증 경로로 준비하되 브라우저까지 사용자 확정한 것으로 기록하지 않는다. Android·다른 아이폰의 결과로 확대 해석하지 않는다.
- 검증용 서버는 맥의 LAN 주소에서 접근할 수 있도록 준비하고, 아이폰에는 `http://<맥의 Wi-Fi IP>:<포트>/` 주소를 제공한다. 아이폰의 `localhost`는 맥을 가리키지 않는다. 같은 Wi-Fi여도 방화벽·공유기의 기기 간 통신 차단 여부에 따라 접속을 확인해야 한다. 외부 공개나 방화벽 변경을 전제하지 않는다.
- **LAN HTTP에서 먼저 확인:** 한국어·번체 글꼴, 실제 화면 크기와 키보드가 열린 상태, 터치 조작, 우림 흐름, 단어 추가·설정 보존, 카드 미리보기와 PNG 생성·다운로드 경로. 375×660 기준 화면 검증과 680×900 원본 PNG 확인은 별도로 유지한다.
- **HTTPS에서 별도 확인:** 아이폰에서 맥의 LAN IP로 접속한 HTTP는 맥 자신의 `localhost`와 달리 보안 컨텍스트 예외가 아니다. 서비스워커 기반 오프라인·캐시 갱신, Wake Lock, Web Share는 신뢰할 수 있는 HTTPS 주소에서 검증한다. 설치형 PWA의 TW-08 검증도 이 환경에서 수행하며, HTTP 화면 확인만으로 완료 처리하지 않는다. [보안 컨텍스트](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts), [서비스워커](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API), [Wake Lock](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API), [Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API) 조건을 기준으로 한다.
- 초기 기기 선택은 공개 배포·터널 개설·기기 인증서 설치의 승인을 포함하지 않았다. 이후 임시 HTTPS 환경을 준비했으나 아래 사용자 결정으로 사용하지 않는다. 미확인 PWA·오디오·공유·오프라인 조합은 미검증으로 남기며, 현지인 문구 검수는 기존 결정대로 버전 배포 후 진행한다.

#### 현재 검증 시점 — GitHub Pages 배포 후 HTTPS 실기기 확인

**2026-08-31 사용자 결정:** 구현·로컬 검증·배포 준비를 마친 뒤 GitHub Pages에 배포하고, 공개 HTTPS 주소에서 iPhone 13 mini Safari·설치형 PWA를 검증한다. 기기에 임시 인증서를 설치하거나 신뢰 설정을 바꾸지 않는다. GitHub Pages의 `github.io` 주소는 HTTPS를 제공하므로 별도 사용자 인증서 설치가 필요 없다([GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)).

- **배포 전:** 두 언어의 기존 자동 회귀, 실제 타이머 흐름, 작은 화면·PNG·원문/설정 보존, 캐시 자산·경로, 공지 내용과 배포 버전을 확인한다. 배포할 커밋과 직전 배포 기준을 기록하고 장애 시 수정 배포/복구 절차를 준비한다. 기존 공개 사이트/PWA의 업데이트 검증을 위해 배포 전에 테스트 설정과 구버전 설치 상태를 보존한다.
- **배포 후:** 실제 HTTPS 주소 `https://winterrainlee.github.io/tea-timer/`에서 아래 기기 검증을 수행한다. 기존 설치 업데이트·오프라인 재실행·실제 공유/저장·오디오 복귀·Wake Lock·글꼴과 접근성을 확인한다. LAN HTTP에서 할 수 있는 사전 확인은 계속하되, HTTPS 기능의 성공 근거로 대체하지 않는다.
- **완료 판정:** 배포 성공과 TW-07/08 검증 완료를 구분한다. 실기기 검증을 배포 조건에서 배포 후 필수 확인으로 옮기며, 미검증 조합은 그대로 기록한다. 공개 버전에서 결함이 발견될 수 있으므로 배포 직후 핵심 흐름부터 확인하고, 중대한 문제는 수정 배포 또는 직전 버전 복구로 대응한다. 복구 시에도 사용자 저장 데이터를 삭제하지 않는다.
- 이번 결정은 배포 방식과 검증 순서에 대한 합의다. 현재 즉시 `main` 반영·원격 푸시·배포한 것으로 기록하지 않으며, 배포 전 준비를 먼저 완료한다. 현지인 번역 검수도 기존 결정대로 배포 후 진행한다.

#### 중단한 임시 HTTPS 준비 이력 — 2026-08-31

아래는 준비 당시 기록이다. GitHub Pages 방식을 선택한 뒤 HTTPS 8838·인증서 다운로드 8139 서버를 중단하고 서버 개인 키를 제거했다. 기기 인증서 설치·신뢰는 수행하지 않았으며 더 이상 승인 대기 항목이 아니다. 공개 인증서·설정·검증 로그만 근거로 보존하고, 기존 HTTP 8138 미리보기는 유지한다.

사용자가 다음 단계 진행을 요청해 **같은 Wi-Fi의 임시 HTTPS 환경**을 준비했다. 앱의 동작·저장 계약은 바꾸지 않는다. 기존 HTTP 8138은 유지하고, `https://192.168.0.12:8838/`에서 현재 통합 런타임(SW v68)을 제공한다. 서버는 해당 LAN 주소에만 바인딩하며 앱 허용 목록만 제공한다. 외부 공개·터널·방화벽 변경·시스템 인증서 신뢰 변경은 하지 않는다. 맥의 IP 변경·서버 종료·인증서 만료 시 재준비가 필요하다.

- Git 외부 작업 폴더 `…/01a05671-a428-7392-940b-09ee1a7816ad/tw08-https/`에 서버·공개 인증서·검증 로그를 보관한다. 인증서 이름은 `Tea Timer Local Test 2026-08-31`, 유효기간은 2026-08-31 18:54–2026-09-07 18:54 KST다. 서버 인증서에는 현재 LAN IP·localhost만 포함했다. 발급용 CA 개인 키는 이 서버 인증서 발급 뒤 제거했고, 서버 개인 키는 접근 권한 600·상위 디렉터리 700으로 따로 둔다. 개인 키는 HTTP/HTTPS 제공 목록에 포함하지 않는다.
- `http://192.168.0.12:8139/tea-timer-test-ca.cer`는 공개 인증서 한 파일만 제공하는 설치 준비 경로다. HTTP로 받은 인증서는 신뢰하기 전에 작업 폴더의 `certificate-info.json`에 기록된 SHA-256 지문과 대조한다. 인증서 이름만으로 동일성을 판단하지 않는다.
- **기기 설치·신뢰는 아직 수행하지 않았다.** iOS는 수동 설치만으로 SSL/TLS를 신뢰하지 않는다. 기기 전체의 인증서 신뢰에 영향을 주므로 사용자가 이 단계를 승인한 뒤 설치·신뢰 설정을 안내한다. 테스트 종료 후 이 인증서 프로파일만 제거하고 기존 인증서·기존 앱 데이터는 건드리지 않는다. [Apple의 수동 인증서 신뢰 안내](https://support.apple.com/ko-kr/102390), [프로파일 설치·제거 안내](https://support.apple.com/guide/iphone/iph6c493b19/ios)를 따른다. 브라우저 경고 무시나 검증 비활성화를 통과 근거로 삼지 않는다.
- HTTPS는 기존 HTTP 8138 및 공개 배포 사이트와 **다른 origin**이다. 기존 설정·단어가 새 주소에 안 보이는 것은 삭제가 아니다. 자동 이관·사이트 데이터 초기화는 하지 않는다. 테스트용 기록을 사용하고, 새로고침·오프라인 재실행·업데이트 전에 필요한 초안은 텍스트/PNG로 내보낸다. 초안의 재실행 복원은 기존 비목표다.
- 준비 확인은 TLS 체인/IP 검증, 앱 30개 경로의 원본 일치, 주요 MIME, 비공개 경로 차단과 키 권한 검사다. **Safari의 보안 컨텍스트·서비스워커·실제 저장/공유 성공과는 구분**한다. macOS 26.6.2(25G83)를 확인했으며 iOS/Safari 버전은 사용자 기기에서 기록해야 한다.

#### 실기기 확인 순서 — 준비됨, 결과 대기

각 항목은 **한국어·번체 × Safari·설치형 PWA** 결과를 구분한다. 자동화의 375×660·680×900 PNG·합성 입력/공유 대역 결과를 실제 iOS 결과로 대신하지 않는다. 기기 버전·주소·언어·모드와 관찰 결과를 함께 남긴다.

1. GitHub Pages 배포 후 공개 HTTPS 주소에 인증서 설치 없이 접속한다. iOS/Safari 버전·배포 커밋·SW 버전과 화면을 기록하고 서비스워커 준비를 확인한다. 기존 공개 사이트의 설치·캐시를 지우지 않는다.
2. 두 언어에서 차 선택·메뉴·설정·느낌 입력을 확인한다. 한국어/번체 키보드 조합 중 닫기, 긴 제목·메모·추가 단어, 혼합 문자·emoji, 키보드가 열린 작은 화면을 확인한다. 기본 단어는 언어별로 독립적이고, 이미 저장한 개인 목록·사용자 원문은 언어 전환으로 번역되지 않아야 한다.
3. 차 선택→정상 완료→출탕→다음 포→느낌 작성·내보내기→세션 종료 순서로 확인한다. 일반 다구와 표일배를 포함해 완료·출탕·다음 포가 중복되지 않아야 한다. 종료 취소는 초안을 유지하고 명시적 종료는 기존 계약대로 비운다. 설정 페이지 이동은 안전한 idle 상태에서 확인한다.
4. 짧은·긴·혼합 카드의 글꼴과 확정한 ③ 여백, 표시 한도 2/2/3/5, 실제 680×900 PNG와 전체 텍스트 원문을 확인한다. OS 공유 시트에서 사용자 자신의 사진/파일로 저장한다. 공유 취소는 다운로드 없이 초안을 유지해야 한다. 공유 미지원·실패의 다운로드 폴백은 별도 경로이며, 취소와 혼동하지 않는다.
5. 앱 전환·화면 잠금·오디오 인터럽션 후 복귀 시 타이머 정합성, 다음 포의 완료음, 중복 완료 방지와 Wake Lock 재획득을 확인한다. VoiceOver의 언어·버튼·상태 안내·모달 닫기·포커스 복귀도 확인한다. 백그라운드 완료음 보장은 비목표다.
6. 같은 HTTPS 주소를 홈 화면에 설치하고 두 언어에서 핵심 흐름을 반복한다. 온라인으로 메인·설정·이용 안내·공지를 연 뒤 네트워크를 끊고 앱을 재실행한다. 오프라인 화면·언어 전환·타이머·카드·글꼴 폴백과 저장 설정을 확인한다. 예상 가능한 시스템 폰트 대체는 허용하되 글자 누락·잘림은 실패다.
7. **기존 버전 업데이트는 배포 전후를 이어 확인한다.** 배포 전에 기존 공개 주소의 구버전 설치·테스트 설정을 보존하고, 새 버전 배포 뒤 강제 새로고침 없이 열린 우림/초안이 유지되는지와 다음 실행의 새 자산·설정 보존·오프라인을 확인한다. OS 종료·명시적 새로고침 후 초안 복원은 요구하지 않는다. 신규 설치만으로 기존 설치 업데이트 통과라고 기록하지 않으며, 구버전 기준을 확보하지 못했다면 그 항목을 미검증으로 남긴다. 테스트를 위해 공개 사이트에 구버전을 다시 배포하지 않는다.

첫 공지의 실제 배포 내용·예정 항목 구분·두 언어는 배포 전에 대조하고, 실제 PWA의 오프라인 표시는 배포 후 확인한다. 계획 변경만으로 TW-07/08 실기기 검증이나 배포를 완료 처리하지 않는다.
